# 场景表达轨道实施检查点 · 2026-09-14

本批把全书编排原有的章级示意曲线收口为五条通用场景表达轨道：场景节奏、句段节拍、细节展开、镜头距离和语言修饰度。点位绑定稳定场景 ID，只保存 L1—L5 与可选写法备注。

矩阵保持原章节列宽。每章只占一列，多个场景小圆圈排在章内，不再各占一格；L1 空心、L3 半填充、L5 全填充，未设置使用淡色虚线圆。五个维度名称在左侧竖排窄列中，不遮挡章节点位。悬停点位显示章号、S 序号和场景标题，左键选择、上下拖动改档、右键进入宽侧栏。关闭详情只移除最上层，底下的表达轨道面板和主页面滚动位置保留。

服务端新增 PostgreSQL 与 SQLite 同义迁移、数据库档位约束、点位所有权校验、串行化整组事务保存、版本冲突保护和幂等路由。书级“用于后续写作”开关默认关闭；关闭时 `GenerationContextAssembler` 不查询点位表、不注入新片段。明确启用后才读取当前章节真实场景的点位，并只装配固定写法字典与故事冻结边界，不增加模型调用。原有章节表达参数入口继续保留。

开发作品《净宅人翻旧账》以补缺方式新增 305 个表达点并明确启用书级开关。执行前生成 24,055,808 字节 SQLite 备份并通过完整性检查；新增开关前又生成独立完整备份。执行后章节哈希保持不变，正文、章节标题、场景任务和已有事实未被脚本改写。

验证结果：

- 共享合同构建通过。
- 客户端全书编排状态与交互测试 47/47 通过，其中场景分组、章内点位、五档吸附、未设置断线和详情分层聚焦测试 9/9 通过。
- 客户端和服务端 TypeScript 类型检查通过。
- 服务端全书编排回归 34/34、场景表达提示词与正常生成链路 3/3 通过。
- 客户端全量测试 271 项中 265 项通过；6 项既有失败位于自动导演与移动导航／设置路由合同，场景表达相关用例全部通过，未修改无关断言。
