# 叙事控制内核

叙事控制内核是现有小说底座下一阶段的目标架构。它不替换开书、全书编排、章节、场景、候选比较和采纳界面，而是把这些入口统一连接到卡片解析、提示词编译、生成校验和状态提交链路。

完整决策与迁移方案见 [叙事控制内核与 PostgreSQL + Apache AGE 目标架构](../../superpowers/specs/2026-09-15-narrative-control-kernel-postgresql-age-design.md)。当前代码已经有表达轨道、人工调整、候选版本和配置核对，但 PostgreSQL 单库切换、六卡统一模型及 AGE 投影仍属于后续实施，不得在产品说明中写成已经上线。

## 核心边界

- PostgreSQL 是唯一正式数据库和唯一事实源。
- Apache AGE 是同一 PostgreSQL 中的可重建图投影，只负责关系遍历与一致性辅助检查。
- 六类卡片各自负责事实、计划、状态、表达、执行和校验，不能跨职责覆盖。
- 每个场景解析一份唯一有效配置，正文模型只接收系统编译的执行卡。
- AI 输出均为候选；只有校验并明确采纳后，正文、事实和状态才在同一事务中提交。
- 作品数据严格隔离；卡片 schema、规则、Prompt、Skill 和模板允许全局复用。

> 🏠 **白话比喻**：这套内核像剧组的场记系统。档案室保存已经确认的剧情，导演计划下一场，场记记录演员和道具当前状态，摄影指导只决定怎么拍，最终给现场的是一张当天通告单，拍完还要对片。对应到系统里，这六种职责不能再混成一个提示词。
>
> 🧠 **速记方法**：事实不能编，计划还没发生，状态看当前，表达只管写法，执行一次一场，校验不直接改真相。

## 与现有模块的关系

| 现有模块 | 内核中的职责 |
|---|---|
| 全书编排 | 编辑计划卡与表达卡，显示冲突和有效值 |
| 场景卡 | 提供当前场景进入状态、阻力、动作、结果和边界 |
| 人工调整 | 生成有范围、有版本的覆盖卡，不直接覆盖原资料 |
| Prompt Registry | 保存版本化模板和方法卡，编译场景执行卡 |
| 候选/核对/采纳 | 承载生成候选、校验卡、人工决定和事务提交 |
| 事实账本/关系阶段 | 迁移为事实卡与状态卡，并投影到 AGE |

## 实施纪律

1. 先定义合同和五题材基线，再新增表和运行链路。
2. 新安装直接使用 PostgreSQL；既有 SQLite 数据只通过一次性迁移进入 PostgreSQL，不长期双写。
3. AGE 先只读、可关闭、可重建；图故障时必须能退回关系查询。
4. 每个阶段先验证旧链路无回归，再通过开关启用新链路。
5. 不把新职责继续堆入大型 Service，应拆成解析器、编译器、生成器、校验器和提交协调器。

## 验收口径

- 同一个控制键在同一场景只有一个有效值，并能说明覆盖原因。
- 表达变化不改变事件、行动、知情、关系、线索、因果和结果。
- 失败候选不进入正式正文、事实、状态和图投影。
- 图投影删除后能从 PostgreSQL 完整重建。
- 五题材中至少四类不劣于旧链路，且硬约束错误不增加，才允许默认启用。
