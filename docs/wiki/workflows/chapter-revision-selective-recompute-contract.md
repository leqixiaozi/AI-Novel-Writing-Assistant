# 旧章换稿与选择性重算合同

## 背景

章节一旦形成稳定检查点，后续正文、事实、人物状态、角色所知、关系图和语义索引都可能引用它。此时换稿不能等同于普通候选采用，否则系统会在作者看不到的地方改写小说历史，或让旧来源继续伪装成当前真相。

> 🏠 **白话比喻**：稳定章节像列车时刻表中的已开行站点。修改早期站点时，应从前一站重新核对线路，并通知后续站点人工确认，不能让调度系统偷偷改写已经发出的车票。对应到系统：前一稳定检查点是恢复起点，派生数据可重建，后续正文只能挂复核标记。

> 🧠 **速记方法**：**历史不删、来源要撤、派生可算、正文人审、稳定再放行。**

## 决策

旧章换稿采用“冻结预览 → 逐项计划 → 二次确认 → 选择性重算 → F4 重新结算 → 稳定放行”合同。预览必须持久化并带来源 generation；执行不能重新临时计算影响后直接采用。作者选择和原因必须进入版本化账本。

## 当前规则

1. 旧正文、旧结算和旧检查点均保留，只把旧检查点／结算标为不再作为当前稳定结果。
2. 正式事实按证据来源撤销；还有其他有效来源时不得使事实失效。
3. 人工修正和人工锁定必须显式保护，自动重算不能覆盖。
4. 后续正文不可由后台任务重写，只建立带来源原因的复核标记。
5. 通用派生计算复用统一依赖图和 030 作业，不建立 F5 专用执行器。
6. 新正文仍走 F4 变化确认；换稿执行只有在新稳定检查点存在且复核标记清零后才稳定。
7. F6／F7 只读取新的稳定检查点；未完成执行是显式阻塞信号，不是可忽略提示。

## 失败模式

- **临时预览**：页面刷新后作者无法证明执行时看过什么。必须持久化 snapshot hash 和 generation。
- **删除历史**：会破坏审计、对比和恢复。只允许状态迁移，不物理删除。
- **整书重算**：成本高且容易覆盖人工内容。必须从前一稳定检查点沿依赖链选择性重算。
- **后文自动改写**：作者失去控制，正文来源不可追溯。只允许复核提示和作者明确处置。
- **旧稳定结果继续可读**：F6／F7 会使用错误真相。换稿执行时必须把旧检查点转为 `superseded`。
- **预览过期仍执行**：并发修改会让处置计划对应错误对象。文档修订或依赖 generation 不一致时必须失败关闭。
