# 全书编排与统一章节轴

全书编排以用户的「拾章」原型为设计依据：用同一条章节轴对齐章节目的、卷段、事件、场景、人物区段和表达参数，右侧编辑所选对象。独立菜单 `/book-arrangement` 先选作品，也可由原工作台携 `novelId` 进入。原八步流程继续保留，不把编排变成开书或生成前的必经步骤。

> 🏠 白话比喻：像排课表，列是上课时间，行是老师、教室和课程；所有行看同一列，才能判断同一时刻安排了什么。对应实现：所有轨道共享排序后的章节 ID 窗口，不按各行数据分别计算列位置。
> 🧠 速记：一条章轴，多种轨道；定位用 ID，显示用章序。

## 原型转为实际产品的边界

原型的示例曲线、自动生成章节名和固定 AI 建议只说明布局。产品读取当前作品已有章节、人物、卷规划、场景和事件；没有配置的数值显示“未设置”，折线留空，不能默认为 0 或 50。0 是合法参数最低值。参数曲线表达作者的目标，不声称是 AI 对正文效果的测量。

概览显示全书尺度；对齐模式显示同一章节窗口。窗口在末尾回退以保持列数，短书不补造虚拟章节。人物使用稳定 ID，同名人物不会合并。事件的故事发生时间与章节阅读顺序分别保留。

> 🏠 白话比喻：温控器设为 20 度是目标，温度计显示 20 度才是测量；没测量不能填成零度。对应实现：编排目标与正文实际资料分开显示。
> 🧠 速记：目标不是实测，空值不是零。

## 章节窗口与颜色

全书编排使用独立的浅色工作台外壳；样式限定在 `.ba-app-shell` 和 `.book-arrangement-page`，不影响其他页面。桌面端使用左侧作品导航、中间章轴和右侧检查器；窄屏保留矩阵横向滚动，检查器排在矩阵之后。

顶部默认八章窗口。拖柄连续跟随指针，经过一章宽度时统一更新所有轨道的章 ID；点击轨道定位窗口，方向键逐章移动，Home／End 到达首尾。章节不足八章时只显示真实章节。

> 🏠 白话比喻：在长地图上移动一个取景框，框内道路、商店和公交站一起换位置。对应实现：导航只改变共享窗口，不能让各轨道自行翻页。
> 🧠 速记：一个窗口、一条章轴；拖动看范围，点击选章节。

人物颜色由稳定人物 ID 决定，同名人物仍独立。卷段蓝橙交替；人物保留多色填充，计划区段使用虚线，历史记录使用实线。颜色之外同时保留文字和线型，不能仅靠颜色表达资料性质。人物、关系和线索默认最多三行，可展开剩余区段；非连续章节必须拆段，不能把中间缺失章节涂成参与。

## 资料投影与依据

GET 工作区在原人物、章节、事件和场景之外，投影 `CharacterRelationStage`、`TimelineHook`、最新快照的 `ForeshadowState`、每章每类最新审校报告的问题及未结冲突。资料保留原对象 ID、可定位章节、来源标签和计划／记录／设定／未知性质。历史审校缺少正文版本时返回空版本，不能宣称验证了当前正文。预期回收章序不补造实际回收章节 ID；草稿抽取关系不当成确认事实。封面和题材来自原作品资产。

> 🏠 白话比喻：展览标签引用馆藏编号，旁边的预约到货日期不等于物品已经入库。对应实现：原实体是依据，未来计划与已记录事实分别标注。
> 🧠 速记：有来源才定位，有记录才称历史。

## 草稿、后续要求与大纲

编排分三种动作，不能靠一个“保存”按钮同时改变全部内容：

1. 保存编排草稿：记录章节备注、五维控制、人物参与区段、固定轨道和编排锁定，支持刷新恢复，不改变正式正文或大纲。
2. 预览并应用后续要求：按选中且未锁的章节生成持久候选，展示有效要求前后差异及范围，明确应用后才进入可选写作合同。
3. AI 重编排大纲：把授权章范围、编排备注、参数对象、人物区段和保留事项交给原规划候选服务，先比较候选，再采纳所选章纲。历史正文始终由独立的正文版本流程修改。

“锁定”只让本轮编排／重排排除该章，不等于暂停自动导演或建立人工接管。实际接管仍由原人工调整交接接口执行。

应用要求后，在章节“人工调整”中解析本次要求、生成候选时沿用编排配置。未启用新合同的原生成请求不会因保存了编排而增加提示片段或改变行为，已开始运行的任务仍使用其冻结输入。

> 🏠 白话比喻：便笺保存、下次出行要求和正式修改行程是三件事。对应实现：草稿持久化、表达要求应用和原大纲采纳分别调用独立接口。
> 🧠 速记：存草稿、看影响、选范围、再生效。

## 继承与持久化

复用 `WritingSetting` 保存 `book-arrangement:draft` 与 `arrangement:chapter:<id>`，不增加平行事实库。要求覆盖顺序为书级默认 → 编排 → 章级覆盖 → 本次要求。章级或本次已明确覆盖的控制，编排不会悄悄抢占优先级；预览展示合并后的实际效果。

候选共用 `ChapterEditVersion`，来源依赖接入 `DirectorArtifact`。请求沿用 `Idempotency-Key`、版本 CAS 与操作租约；应用在事务内校验故事依赖、草稿版本、配置版本、章归属、交接状态及待同步任务。已冻结的运行输入不被后续配置修改重写，原无调整请求仍不加载这些设置。

## 接口与模块

作品基路径：`/api/novels/:id`。

| 接口 | 职责 |
|---|---|
| GET `/book-arrangement` | 只读轨道资料、草稿、已应用要求及可恢复候选 |
| PUT `/book-arrangement/draft` | 带 `expectedRevision` 保存编排草稿 |
| POST `/book-arrangement/preview` | 按 `draftRevision` 与章 ID 范围冻结应用候选 |
| POST `/book-arrangement/:candidateId/apply` | 按选中范围原子应用后续要求 |

共享合同为 `shared/types/bookArrangement.ts`。服务位于 `modules/novel/adjustments`，前端位于 `pages/bookArrangement`；AI 大纲调整复用原 [可选人工调整](../workflows/optional-writing-adjustments.md) 的规划服务和注册提示词。

维护时重点验证：同轴对齐、0 与缺省区别、跨作品隔离、锁章排除、同名人物 ID、草稿／预览无正文副作用、过期候选拒绝、部分范围应用、刷新恢复及断网重试。可控接口的浏览器测试与真实模型文学效果分别记录。
