# 全书编排与统一章节轴

全书编排以用户的「拾章」原型为设计依据：用同一条章节轴对齐章节目的、卷段、事件、场景、人物区段和表达参数，右侧编辑所选对象。独立菜单 `/book-arrangement` 先选作品，也可由原工作台携 `novelId` 进入。原八步流程继续保留，不把编排变成开书或生成前的必经步骤。

> 🏠 白话比喻：像排课表，列是上课时间，行是老师、教室和课程；所有行看同一列，才能判断同一时刻安排了什么。对应实现：所有轨道共享排序后的章节 ID 窗口，不按各行数据分别计算列位置。
> 🧠 速记：一条章轴，多种轨道；定位用 ID，显示用章序。

## 原型转为实际产品的边界

原型的示例曲线、自动生成章节名和固定 AI 建议只说明布局。产品读取当前作品已有章节、人物、卷规划、场景和事件；没有配置的数值显示“未设置”，折线留空，不能默认为 0 或 50。0 是合法参数最低值。参数曲线表达作者的目标，不声称是 AI 对正文效果的测量。

概览显示全书尺度；对齐模式显示同一章节窗口。窗口在末尾回退以保持列数，短书不补造虚拟章节。人物使用稳定 ID，同名人物不会合并。事件的故事发生时间与章节阅读顺序分别保留。

> 🏠 白话比喻：温控器设为 20 度是目标，温度计显示 20 度才是测量；没测量不能填成零度。对应实现：编排目标与正文实际资料分开显示。
> 🧠 速记：目标不是实测，空值不是零。

## 章节窗口与颜色

全书编排沿用底座 `AppLayout`、`Navbar`、`Sidebar` 和移动导航；不再单独覆盖主题或维护另一套品牌外壳。局部布局样式限定在 `.book-arrangement-page` 和右侧编排面板，背景、文字、边界从原语义变量继承。矩阵保留横向滚动，编辑与预览在右侧独立滚动，不将窄屏表单排到矩阵下方。

顶部默认八章窗口。拖柄连续跟随指针，经过一章宽度时统一更新所有轨道的章 ID；点击轨道定位窗口，方向键逐章移动，Home／End 到达首尾。章节不足八章时只显示真实章节。

窗口本体负责平移，左右边缘直接改变可见范围，最少 4 章、最多 16 章；短书按真实章数显示。全书卷段缩略位于窗口上方，沿完整章节轴显示蓝橙卷块，点击卷块跳到该卷开头。范围变化属于浏览状态，不写入编排草稿，也不新增提示词参数。

> 🏠 白话比喻：像拉伸地图上的取景框，两边拉宽就多看几条街，拖中间则换到另一片区域；上方色带像城区分区图。对应实现：边缘改变窗口章数，中部改变起点，卷段缩略只负责定位。
> 🧠 速记：中间移动、两边缩放、色带跳卷；只改视野，不改故事。

> 🏠 白话比喻：在长地图上移动一个取景框，框内道路、商店和公交站一起换位置。对应实现：导航只改变共享窗口，不能让各轨道自行翻页。
> 🧠 速记：一个窗口、一条章轴；拖动看范围，点击选章节。

人物颜色由稳定人物 ID 决定，同名人物仍独立。卷段蓝橙交替；人物保留多色填充，计划区段使用虚线，历史记录使用实线。颜色之外同时保留文字和线型，不能仅靠颜色表达资料性质。人物、关系和线索默认最多三行，可展开剩余区段；非连续章节必须拆段，不能把中间缺失章节涂成参与。

顶部操作只放整书资料和人物关系两个全书入口。人物关系面板分为“初始关系”和“当前章节”：初始关系读取底座角色准备中的静态关系，可进入原角色关系页配置；当前章节按所选章节筛选关系阶段，点击具体关系进入右侧对象配置。卷段从矩阵卷段轨道进入，章节从章节名称进入，避免顶部范围按钮和对象编辑入口重复。新增对象、AI 重排、后续要求、卷段预览和刷新归入“更多”，避免把低频按钮平铺在主操作区。世界观仍以底座原模块为唯一编辑源，打开新窗口时保留当前编排草稿和位置。

事件单元格只显示圆点和单行截断标题；场景单元格显示 `S1 · 场景名`，同样采用单行截断。悬停或键盘聚焦时再显示状态／字数和两行摘要，点击继续沿原右侧对象编辑流程。浏览器原生标题作为窄屏或浮层被裁切时的后备信息。

单章超过 3 个事件或场景时，末尾显示与该类对象同色同形的“+N 更多”。点击只在当前章节格内展开全部标题，不跳到章级总面板；展开后点击具体标题，才打开对应事件或场景的右侧配置。“收起”恢复三项摘要。章节名称继续负责打开章级配置，两种入口职责不能混用。

## 资料投影与依据

GET 工作区在原人物、章节、事件和场景之外，投影 `CharacterRelationStage`、`TimelineHook`、最新快照的 `ForeshadowState`、每章每类最新审校报告的问题及未结冲突。资料保留原对象 ID、可定位章节、来源标签和计划／记录／设定／未知性质。历史审校缺少正文版本时返回空版本，不能宣称验证了当前正文。预期回收章序不补造实际回收章节 ID；草稿抽取关系不当成确认事实。封面和题材来自原作品资产。

> 🏠 白话比喻：展览标签引用馆藏编号，旁边的预约到货日期不等于物品已经入库。对应实现：原实体是依据，未来计划与已记录事实分别标注。
> 🧠 速记：有来源才定位，有记录才称历史。

## 草稿、后续要求与大纲

编排分三种动作，不能靠一个“保存”按钮同时改变全部内容：

1. 保存编排草稿：记录章节备注、五维控制、人物参与区段、固定轨道和编排锁定，支持刷新恢复，不改变正式正文或大纲。
2. 预览并应用后续要求：按选中且未锁的章节生成持久候选，展示有效要求前后差异及范围，明确应用后才进入可选写作合同。
3. AI 重编排大纲：把授权章范围、编排备注、参数对象、人物区段和保留事项交给原规划候选服务，先比较候选，再采纳所选章纲。历史正文始终由独立的正文版本流程修改。

“锁定”只让本轮编排／重排排除该章，不等于暂停自动导演或建立人工接管。实际接管仍由原人工调整交接接口执行。

应用要求后，在章节“人工调整”中解析本次要求、生成候选时沿用编排配置。未启用新合同的原生成请求不会因保存了编排而增加提示片段或改变行为，已开始运行的任务仍使用其冻结输入。

> 🏠 白话比喻：便笺保存、下次出行要求和正式修改行程是三件事。对应实现：草稿持久化、表达要求应用和原大纲采纳分别调用独立接口。
> 🧠 速记：存草稿、看影响、选范围、再生效。

## 卷段调整与原卷规划

卷段代表原 `VolumePlan` 的章节归属，不等同于可重叠的主题／Arc 故事线。点击彩色卷段选择卷；左端和右端改变起止，中部移动整个范围，按全书排序的稳定章节 ID 吸附。拖动过程只是本地预览，松手更新编排草稿，Escape 取消；右侧起止选择器与键盘方向键提供同等范围调整。章节表头使用数字加名称，保留生成状态。

> 🏠 白话比喻：像把书签移动到另一个页码，先标出新的分卷位置，核对后才改目录；书页内容没有被重写。对应实现：卷草稿与正式卷规划分离，章节正文和实际阅读顺序不随拖动改变。
> 🧠 速记：选卷、调范围、存草稿、看影响、再应用。

`volumeEdits` 是草稿中的可选字段，旧请求无需添加它。预览选取全部待调整卷，一并核对相邻卷的章节归属；不自动把章节从未授权卷抢走。锁定章节、重复归属、非连续范围或资料版本变化会阻止应用。作者可先调整相邻卷，再重新预览。原卷的名称、摘要、目标、主角变化、高潮与下卷衔接在详情面板编辑，打开面板不产生草稿。

卷预览返回调整前后、移入移出章节、已写章节、相邻卷、关联资料和未检查范围。它是结构与依赖检查，不代表 AI 已核实剧情合理性。预览共用编辑候选持久记录；应用复用原卷规划文档、版本和事务持久化能力，单独保留回执，重复请求不重复产生卷版本。原卷规划接口和未启用人工调整的生成路径保持原行为。

> 🏠 白话比喻：换课表先核对教室是否重复占用，但不能因此声称课程内容质量已经检查。对应实现：确定性范围校验与文学、因果分析分开标明。
> 🧠 速记：范围通过不等于剧情通过；重叠先调整，旧稿不覆盖。

## 对象编辑与正文核对

事件、场景、关系、线索以原对象 ID 打开右侧详情，字段合同分别对应 `StoryTimelineEvent`、`ChapterPlanScene`、`CharacterRelationStage`、`TimelineHook`。对象候选与正式资料分开，预览记录修改前后、版本、引用、受影响章节和未检查范围。应用时重验版本、章写入许可、锁定、导演执行与同步状态，成功回执和原表变更在同一事务提交。

> 🏠 白话比喻：修改通讯录前先看原联系人和关联群组，确认后只改这张名片。对应实现：原对象 ID、依赖版本、范围保护与事务回执；不另建一套人物或事件事实库。
> 🧠 速记：先看来源，再看影响；预览留档，应用改原表。

事件取消、线索放弃和关系停用保留原 ID 及引用；场景移除只整理相关章规划的场景顺序，候选保留修改前内容。故事快照和章节抽取的关系只读；作者可另建计划，不能用计划编辑直接制造“已经发生”“已经回收”的事实。事件的故事日与所在章节分别编辑，预计回收章只是目标。

场景行与原 `Chapter.sceneCards` 同步，保留能够按 ID／原位置对应的预算及独立约束，再以实际场景卡计算原规划复用合同。不能把旧场景卡和新场景同时送入写作。卡片与场景无法可靠对应时预览提示冲突；删除／移走最后一个场景需要先补替代，避免原规划器自动重新生成而掩盖作者的意图。

章节内场景采用“上方篇幅条、中部场景卡、右侧编辑区”的同页交互。点击矩阵中的场景或“编排所选章节场景”进入章内编辑；彩色篇幅条按各场景目标字数分配宽度，拖动相邻边界时只重算两侧未锁定场景，最低保留 5%。场景卡支持稳定 ID 下的排序、拆分、合并、新增和删除，右侧按故事安排、节奏表达、人物边界编辑原场景字段。锁定只保护本次编辑，不写成新的故事事实。

预览会冻结整章场景顺序、字段、章节版本和依赖版本，并保存为 `arrangement_scene` 候选；此时不修改场景、场景卡或正文。应用在一个事务内同时更新 `ChapterPlanScene` 与 `Chapter.sceneCards`，重验锁章、人工接管、导演租约、同步任务及并发版本，返回可重复读取的采纳回执。整章至少保留 3 个、最多 8 个场景，预算总字数必须在合法范围。应用只调整后续写作依据，已有 `Chapter.content` 保持原样。

> 🏠 白话比喻：像在一张披萨上移动切线，某一块变大时相邻那块会变小，整张披萨没有凭空增加；确认菜单前也不会端走桌上的旧菜。对应实现：边界拖动只改相邻预算，预览与正式应用分离，正文不随场景规划重写。
> 🧠 速记：拖边界、编卡片、先预览、整章落库、正文不动。

关系目标使用 `arrangement_plan` 来源；`isCurrent` 只表示此计划启用，不是事实确认。动态人物概览的 `plannedRelations` 与原 `relations` 分开，按稳定章节 ID 或纯卷范围读取，事实库和当前人物关系查询排除它。规划和写作只在有匹配目标时附加明确的“尚未发生”目标片段；未设置时保持原上下文输出。新线索使用 `planned`，不得放入既有未回收钩子或人物已知事实。

`TimelineHookPlanService` 按本章铺设和本章预计回收读取计划，通过可选 `plannedHookGuidance` 接入原规划与写作的四种模式。发生过的钩子仍由原 `listOpenHooks` 路径处理。两种来源不能混用，预计回收缺少原文铺垫依据时仍需核对，不能补造历史。

> 🏠 白话比喻：待办清单上的“明天签合同”不能记进今天的成交账本。对应实现：关系／线索计划通过独立目标通道进入提示词，事实查询只保留已确认资料。
> 🧠 速记：计划按范围，事实不预支；没有计划，不加片段。

候选历史携带已采纳回执。网络断开导致结果不明确时，本地记录待确认状态并锁住重复新增入口，重试同一个候选获取回执；即使故事版本已变化，也可恢复已经提交的结果。已删除场景的回执详情读取候选中的修改前记录，不要求原场景仍然存在。

核对入口支持已有问题和没有历史问题的章节。原问题展示其证据与建议；旧报告没有绑定正文版本时明确说明，不把“最新报告”当成“当前稿已审核”。作者可以调用原核对接口，再针对实际问题生成修复候选，复用原章节调整组件比较、手改、核对、采纳和重试资料同步。生成候选及打开面板均不自动采纳正文。

> 🏠 白话比喻：旧体检报告可以帮助定位复查项目，但不能证明今天的检查通过。对应实现：历史问题、实际修复稿及其审核绑定分别保存，采纳使用实际版本。
> 🧠 速记：旧报告作参考，新稿要复核。

## 编排设置继承

复用 `WritingSetting` 保存 `book-arrangement:draft` 与 `arrangement:chapter:<id>`，不增加平行事实库。要求覆盖顺序为书级默认 → 编排 → 章级覆盖 → 本次要求。章级或本次已明确覆盖的控制，编排不会悄悄抢占优先级；预览展示合并后的实际效果。

候选共用 `ChapterEditVersion`，来源依赖接入 `DirectorArtifact`。请求沿用 `Idempotency-Key`、版本 CAS 与操作租约；应用在事务内校验故事依赖、草稿版本、配置版本、章归属、交接状态及待同步任务。已冻结的运行输入不被后续配置修改重写，原无调整请求仍不加载这些设置。

## 接口与模块

作品基路径：`/api/novels/:id`。

| 接口 | 职责 |
|---|---|
| GET `/book-arrangement` | 只读轨道资料、草稿、已应用要求及可恢复候选 |
| PUT `/book-arrangement/draft` | 带 `expectedRevision` 保存编排草稿 |
| POST `/book-arrangement/preview` | 按 `draftRevision` 与章 ID 范围冻结应用候选 |
| POST `/book-arrangement/:candidateId/apply` | 按选中范围原子应用后续要求 |
| POST `/book-arrangement/volumes/preview` | 按 `draftRevision`、`volumeIds` 冻结卷调整与影响候选 |
| POST `/book-arrangement/volumes/:candidateId/apply` | 校验版本、范围与交接状态后应用卷规划；正文与章序保持不变 |
| POST `/book-arrangement/scenes/preview` | 冻结一章完整场景顺序、预算和约束，保存整章候选但不改正式资料 |
| POST `/book-arrangement/scenes/:candidateId/apply` | 原子同步场景行与场景卡，返回幂等回执且不改章节正文 |
| GET `/book-arrangement/objects/:kind/:objectId` | 原对象详情、来源版本和字段定义；`objectId=new` 只读新建模板，可带 `chapterId` |
| POST `/book-arrangement/objects/preview` | 按 `kind`、`action`、`objectId`、`expectedRevision`、`patch` 保存原对象修改候选 |
| POST `/book-arrangement/objects/:candidateId/apply` | 在版本及范围保护内提交原表变更，返回可幂等恢复的回执 |

共享合同为 `shared/types/bookArrangement.ts`。服务位于 `modules/novel/adjustments`，前端位于 `pages/bookArrangement`；AI 大纲调整复用原 [可选人工调整](../workflows/optional-writing-adjustments.md) 的规划服务和注册提示词。

维护时重点验证：同轴对齐、0 与缺省区别、跨作品隔离、锁章排除、同名人物 ID、草稿／预览无正文副作用、过期候选拒绝、部分范围应用、刷新恢复及断网重试。可控接口的浏览器测试与真实模型文学效果分别记录。

## 后续交互约束

用户要求继续基于底座增量修改，并统一沿用项目组件和交互风格。编辑、依据查看、影响预览及采纳在右侧工作区完成，主章轴保留位置；右侧可以独立滚动，不能要求用户滚到主页面底部找表单。

demo 使用用户授权的开发作品《净宅人翻旧账》，稳定作品 ID 必须由执行参数提供。虚拟数据只补缺并标明来源，不补造历史事实或审校结论。`server/scripts/seed-book-arrangement-demo.cjs` 默认只读计划，显式 `--apply` 才备份、校验并以单个事务补缺，支持幂等重跑；自身未改动的早期演示场景可以对齐原章节场景卡，演示关系可以升级为专属计划来源，不批改用户规划。备份保存在代码仓库外，回执记录新增、调整前值与原草稿。具体步骤和分批验收见 [底座增量交互实施计划](../../superpowers/plans/2026-09-13-book-arrangement-interactions.md)。
