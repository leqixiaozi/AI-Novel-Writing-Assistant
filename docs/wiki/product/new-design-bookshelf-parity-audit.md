# 旧版书架功能对应审计（2026-09-17）

旧版对照基线：`codex/new-design-card-kernel`，`f9102574`；本表跟随书架补齐阶段维护。逐项检查实际挂载页面、条件渲染分支、处理函数及新版能力合同。结论：弹层、只读正文与下载、原导演命令已有接入，但分类、完整封面准备链与部分旧生产流程仍存在差异，不能称为旧版完整复刻。页面跳转不等同于弹层管理、直接下载或执行命令。

证据以源码与模拟专项测试为主；按用户“看一下封面”明确要求，只读查看了新旧书架及空封面弹层。未进行真实模型调用、测试写入用户数据库、归档作品或真实下载。前后端 noEmit 与专项测试不代替 UI 验收；HTTP 可读和空正文导出拒绝也不证明非空流程完整完成。

## 实际挂载及判断口径

- 旧 `/novels` → `NovelList`，由 `NovelListHeader`、`NovelListFilterBar`、`NovelShelfCard`、`NovelContinueCard`、`NovelProjectCard`、`NovelListPagination` 构成；页面实际挂载 `NovelCoverDialog` 和 `AICockpit` 弹层。
- 旧 `/novels/create`、`/novels/auto-director`、`/create`、`/novels/:id/simple`、`/novels/:id/preview`、`/novels/:id/story` 均在路由注册；短篇按钮受 `creationStudioEnabled` 控制，代码默认开启，实际只读旧页面也显示短篇入口。
- 书架筛选分支提前 return，实际只有搜索、长短篇形式和排序；草稿/已发布及原创/续写按钮实际出现在工作台。其余未渲染的 `isShelf` 分支不算可见功能。
- 实际列表组件没有“更多”下拉菜单，操作是直接按钮和两个弹层；不能把其他页面或未挂载文件的菜单算入本页。
- “完整对应”指该项交互与结果在新版已有对应实现，仍需 UI 验收；“部分对应”表示保留部分能力但入口、步骤、信息或语义有差异；“缺失”表示没有对应实现；“底层不适用”表示旧字段或协议不能直接照搬，仍须与用户确认等价业务方案，不能据此删除需求。

## 建议补齐范围及需确认事项

1. **先补现有能力的漏接**：视图偏好记忆、受控的只读运行态刷新、等待审批作品突出、加载分页行为；工作台补已有角色/世界/规划/质量事实以及精确原任务/导演入口。这些不需要数据库迁移或调用模型，但不能将新指标伪装成旧评分或旧进度。
2. **按旧操作体验接入现有来源能力**：从书架管理精确本书封面及图库，明确展示对应候选/当前正式封面；把导出与任务信息做成对应可操作入口和反馈。弹层不是泛链接，同一操作结果才算完整对应。现有管理和命令已接入本书弹层，未实现的单步主图及自动替补必须继续按正式合同补齐。
3. **创建和作品分类需确认**：恢复 AI、参考、手动快捷入口的具体预选流程；短篇及其作品流程范围；已发布、长短篇、原创/续写和平台的正式来源及历史作品归类。统一开书中的参考、续写已有输入能力，并非完全从零开发，但不能省略书架入口和正式分类。
4. **正文与导出范围需确认**：是否完全读取旧当前保存稿/审校稿，或维持仅明确采用正文；是否提供书架一键全书 TXT，和审阅稿标识/正式稳定稿之间如何对应。不能悄悄将旧 full 改为 formal，也不能绕过冻结版本和稳定检查点。
5. **AI 执行入口需确认**：旧书架直接继续、批次自动执行与单/全部任务恢复，是否恢复同页执行，还是用户明确接受新版在原来源页审阅后执行。新增直接执行须复用正式任务合同、完整凭证与防重复机制；本次不启动 AI。
6. **封面合同需确认**：资料自动形成草稿、AI 中英优化、风格/负向分项、旧尺寸、多张生成、无主图自动采用/删除主图自动补图。这些不能用现有单张请求或改变绑定语义假装完成。
7. **阅读与创作体验需确认**：复制/本章下载、目录抽屉是具体遗漏；完整 simple 模式包括稿件范围、恢复、重规划、导出及体验切换，不能把只读阅读页当作已复刻，须另定实现范围。本批相关创建、阅读、封面、导演及导出入口可调整；不泛化全站改造。

用户已确认的回收站替换继续有效。其余旧版功能未因“底层不同”获得删减授权，必须依 AGENTS.md 与用户确认差异或执行用户给出的修改方式。
