# 新设计语义索引与检索边界

## 结论

新设计只在 PostgreSQL 内使用 pgvector 维护可重建语义索引。事实表保存内容正本，Apache AGE 提供关系遍历，pgvector 提供相似度召回；三者不能互相代替或反向写入。

> 🏠 **白话比喻**：事实表像档案原件，AGE 像人物关系通讯录，pgvector 像按意思找书的主题目录。对应到系统：问“发生了什么”查事实，问“谁和谁有关”查图，问“哪段内容相近”查向量。

> 🧠 **速记方法**：**事实、关系、相似度，三账分开；索引能重建，原件不回写**。

## 长期规则

- 每个来源必须先冻结一本书内的稳定对象、精确版本、修订和内容哈希；全局资源需经书内采用或引用后才能进入索引。
- 分块记录锚点、分块器版本和内容哈希；嵌入记录 profile version、维度、距离算法、请求、尝试和回执。旧执行结果若与当前哈希不同，只能留作迟到记录。
- 多模型和多维向量可以共表保存，但每个 HNSW 索引只能属于一个书籍 generation 和一个不可变 profile version。新 generation 覆盖完整并核验校验和后才能激活。
- 查询只能走服务端固定合同：书籍、当前 generation、来源白名单、结构化过滤、`top_k`、候选数、阈值、超时和固定混合权重。客户端不能提交 SQL、索引名、维度或距离运算符。
- 原始查询文本默认不入检索轨迹；轨迹保留查询哈希、可选脱敏摘要／上游引用、过滤快照、耗时、命中来源版本、分数和入选原因。
- 来源归档只改变是否进入当前索引，不删除历史快照、分块、向量回执或旧检索轨迹。

## 依赖失效

统一依赖链为：`来源 → 快照 → 分块 → 嵌入结果 → 索引世代`。任何上游换版都通过 026 账本传播，029 只负责把受影响派生物标记为陈旧。这样既能解释为什么要重建，也能确保旧 worker 不会把新数据覆盖回旧版本。

## 当前未完成边界

当前只有数据库、类型契约、服务 API 和客户端调用层，不包含真实 Embedding provider、Outbox worker、RAG 页面、中文最终分词策略或打包验证。部署前必须验证 pgvector 扩展随 PostgreSQL 一起交付，并完成跨书、多维、切代、失效、超时、恢复与规模测试。

实现细节和跨机器备份口径见 [`new-design/docs/semantic-retrieval.md`](../../../new-design/docs/semantic-retrieval.md)。
