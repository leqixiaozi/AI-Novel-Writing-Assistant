# 全书编排底座增量交互实施计划

> **For agentic workers:** 按任务逐项执行，可使用 subagent-driven-development 或 executing-plans；用户当前要求是功能评估、修改计划和指定 demo 数据准备，不等于批准下列全部功能立即实施。

**Goal:** 在现有全书编排和原小说工作台上补齐对象操作，所有编辑、预览和采纳在右侧完成，无需滚动主页面寻找表单。

**Architecture:** 保留原章轴、数据库实体、生成与保存流程。复用项目自有 UI、现有候选和人工调整接口；右侧承载内容，业务操作仍归原模块所有。

**Tech Stack:** React、项目自有 Button／Dialog／AppDialogContent、TypeScript、Express、Prisma、现有 SQLite／PostgreSQL 合同。

**Spec:** [全书编排与统一章节轴](../../wiki/product/book-arrangement.md)。本计划记录用户最新交互要求；其中“窄屏检查器排在矩阵之后”是待替换的现状，不是目标。

## 约束与范围

- 以底座增量接入，保持原菜单、八步流程、模型默认行为与保存授权。
- 功能优先。沿用现有字体、间距、按钮、表单、弹窗及状态词，不另造设计系统；保留已有彩色轨道和计划／历史区分。
- 右侧编辑、预览和采纳共用一个工作区，不能再把表单排到矩阵下方；允许右侧内容独立滚动。
- demo 使用用户已有作品。当前只读查询仅发现《净宅人翻旧账》，ID `cmtvm8yxq005578y2lcp4fhs6`，是否为用户所指 demo 待确认。
- 截至本计划生成，仅查询数据库与接口，没有填充虚拟数据，没有覆盖正文或规划。
- UI 验收由用户进行；默认使用状态测试、接口／数据库测试、类型检查，不自动运行浏览器。

## 统一右侧交互

> 🏠 **白话比喻**：像查看地图时打开右侧地点详情，地图留在原位置，详情里完成修改并返回。对应实现：主章轴不跳转，选中对象 ID 驱动右侧工作区。
> 🧠 **速记方法**：点谁编谁，预览不换页，关闭回原位。

复用 `components/ui/dialog.tsx` 的 Dialog／AppDialogContent：浮层从右侧展示，继承底座表单和按钮。若宽屏持续保留右栏，则与浮层共用同一内容组件；拖动卷段期间不自动弹出遮罩抢走指针，松手后提供详情操作。窄屏从右侧展开到可用宽度，不降级成页面底部表单。

建议状态：`selectedObject = { kind, id, chapterId? }`，`panelView = edit | evidence | impact | history`。对象类型明确到事件／场景／关系／线索／问题 ID，不能一律退化为章节 ID。

- 标题区：对象名称、章节或卷范围、关闭／返回。
- 内容区：编辑、依据、影响预览、历史版本，按任务切换；复杂比较可加宽右侧面板。
- 底部固定操作：保存草稿、预览、应用；失败时保留输入，可重试。
- 打开只读取；保存草稿不等于应用。涉及历史正文仍调用原候选、核对、采纳流程。
- 切对象、关闭、Esc 均保留本地草稿；重新打开恢复输入。请求进行中避免关闭／恢复另一份草稿造成响应覆盖。
- 返回矩阵保留章节窗口、选中对象、勾选范围和横向滚动位置；键盘焦点返回触发控件。

## 验收场景

1. 在 demo 点击第 N 章或卷段，右侧直接编辑；保存与预览全过程主页面位置不变。
2. 调整相邻两卷，右侧列出冲突和受影响章；只应用选定草稿，正文与章序保持。
3. 同名或多个角色出场，按人物 ID 调整某一个区段；切换对象后输入不丢失。
4. 参数依次体验 0、未设置、停用、恢复继承，预览展示实际生效值。
5. 点击一个事件、一个场景、一个关系／伏笔，展示对应对象而非整章杂项。
6. 保存失败、过期候选、重复点击、刷新、关闭重开均可恢复；后台操作不得覆盖刚恢复的输入。
7. 关闭人工调整后原生成与保存流程可继续；demo 资料和真实审校结果的来源可区分。
