# 新设计开发入口

本文件仅适用于 `new-design/`。先遵守仓库根目录 `AGENTS.md`，通过根目录 `AGENTS.local.md` 的映射读取 `personal-dev-workflow` Skill；同一会话已读且未变可复用。再按需读取专项 Skill。同目录 `AGENTS.local.md` 记录新版的本机环境入口，不放宽授权；缺失时按根目录规则处理。

## 对标与系统边界

- 范围从 `src/client/navigation.ts` 和实际路由确定，覆盖新版菜单、子页面、书内入口及可见操作。旧版页面和业务流程是参考，旧版 `client/`、`server/`、`shared/` 业务代码只读。
- 新版前端通过 `src/client/api.ts` 调用 `src/server/http/` 下的 `/api/new-design` 接口；业务、模型、数据库和运行记录只使用新版来源。共用页面壳仅承担展示与导航，不能调用旧版业务或复用旧版状态充当新版结果。
- 新版以卡片及版本、来源、候选采用、结算记录实现业务；不要按旧版表结构复制底层。数据库结构以 `migrations/` 和 `src/server/database/migrations.ts` 为准，业务含义按需读 `docs/data-model.md`。

## 新版提示词与模型门禁

- 新版产品提示词只在 `src/server/ai/prompts/` 定义为 `PromptAsset`，在其 `index.ts` 注册任务及资产版本，由 `preparePrompt` 构造系统消息、输出规格并验证结果。根目录旧版 `server/src/prompting/` 规则只管旧版；新版不得借用旧版提示词或从业务路由拼接系统提示词。
- 新增 AI 可见操作时，先核对 `src/server/ai/gateway.ts`、`src/server/ai/index.ts`、模型任务路由与对应业务回执；配置缺失、输入或输出不符时不能冒充成功。请求键在调用前领取，结果未知只读按原键恢复，不换键重发；模型结果只保存为候选，作者明确采用后才进入正式来源。
- 完成条件：注册表唯一且覆盖任务、冻结来源和结果边界有测试、原键与未知回执有测试；真实模型调用、作者库迁移与页面验收分别说明，测试替身不能充当在线生效证据。

## 修改与验证

- 先确认目标操作的用户可见结果，再追踪页面、API、业务记录和恢复回执；区分代码接线、隔离验证、作者环境生效与页面验收。未知请求不得换键重发模型，候选不得自动冒充正式采用。
- 仅在对应节点使用项目原生命令：服务端 `npm run build:server`，客户端 `npm run typecheck:client` 或 `npm run build:client`，跨系统边界 `npm run check:boundary`，功能测试选受影响用例。已有等价证据可复用；不自动全量测试或 Review。
- `npm run dev:server` 会连接新版数据库、检查默认迁移并启动后台处理器；`npm run dev:compare` 只启动对照前端，不启动两套 API。启动、迁移、模型调用和作者数据写入分别按任务授权与备份条件执行，不以页面返回 200 当成功能验收。
- 编辑只改新版及已明确需要的共用展示入口。提交前核差异和旧版目录状态；不得夹带用户的其他修改、缓存、凭据或运行数据。

## 本地调试与安装门禁

- 用户未明确要求“安装”“部署”“发布”“打包”时，交付目标固定为当前源码 checkout 的本地开发服务：修改代码、编译，并按需启动或重启 `127.0.0.1:5273`／`127.0.0.1:5301` 做调试。数据库目标统一按下方开发库约定；不得自行进入安装器、运行包、跨机器或发布流程。
- 新增迁移 SQL、运行包迁移清单或数据库代码只表示代码已准备，不授权应用到作者开发库。实际执行须匹配用户授权并核对准确目标；变更方式与保护措施遵守下方数据库增量门禁。
- 不因存在待安装迁移、功能需要新表、服务需要重启、用户要求“补全／启用／对标 main”或此前已完成过数据库操作，就推定新目标仍授权作者库迁移、数据修复、批量写入、备份或恢复演练；同一未完成数据库任务的明确续做仍按原授权执行。
- “启动／重启服务”仅授权本地源码服务生命周期操作；不连带授权数据库迁移、真实模型调用、安装打包、推送或部署。
- 用户明确要求安装但未说明目标时，先区分本机作者开发库、桌面运行包、其他机器或发布环境；未确认的目标保持不变，独立的本地代码调试可继续。

## 数据库增量门禁

- 本地开发、联调和数据库验证统一使用当前开发库（历史文档中的“作者库”），准确连接入口见 `AGENTS.local.md`。不自动新建、切换或恢复测试库；历史隔离测试授权不继续沿用。运行测试前核数据库副作用，要求独立空库、清表或故障注入的用例不得直接指向开发库；无法安全运行时说明缺口，不换库绕过。
- 日常迭代默认追加增量迁移，保留已有数据及迁移账本；不重跑已登记迁移，不以全库备份、还原或重建作为每次调试／新增功能的固定步骤。普通服务启动不自动执行结构变更。
- 新功能涉及新增或调整表、字段、索引、约束、初始化数据时，执行前告知用途、具体变更、数据影响及是否需停写；未涉及数据库也如实说明。功能实现授权不替代实际数据库写入授权。
- 删表／合表、删除或改变字段类型、破坏兼容性的约束变更、大批量转换／回填、加密方式变更、清库／重建属于重大变更：先告知必要性、受影响数据、停写风险和回退方案，取得用户明确确认后执行；不沿用已完成任务的旧授权。
- 普通增量按风险选择事务、幂等、隔离验证及必要的定向保护，不默认整库备份与恢复演练。仅用户明确要求、故障恢复或已确认的重大变更确需保护时安排完整备份／恢复；先说明保护范围，不因“安全”自行扩展操作。
- 失败优先事务回滚并保留现场；提交结果未知先只读核对，不重复迁移、不自动还原或清库。恢复、重建及切换目标库分别核授权。
- 新版与旧版数据库边界不变。完成报告区分源码、历史隔离验证、当前开发库实际应用和页面验收；既有测试库不自动删除。
