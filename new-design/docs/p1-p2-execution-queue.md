## 实施边界

- 仅修改 `new-design/` 及其文档；旧目录只允许阅读参考，禁止直接／间接 import、运行调用、旧网关注入或旧 SQLite 数据链依赖。已有旧壳挂载是过渡耦合，不算独立运行验收。
- 根 PromptAsset／registry／网关写入例外申请撤回，用户明确否决。受控 PromptAsset、注册、结构化输出、模型适配和独立启动／构建入口均归属 `new-design/`；提示词治理保留，不在业务服务散落内联提示词或原始模型调用。
- 每项必要补缺先记录：无法闭环的用户动作 → 必要缺口 → 旧系统参考行为 → 新设计最小实现 → 验收点。只补已授权 P1／P2，不照搬旧模块、不扩张 P3／P4／P5。
- PostgreSQL 是正本，AGE 与 pgvector 是同一底座上的投影。已有卡片、表单、关系、状态、规划、正文、任务、研究和资产不得再复制成第二套事实。
- 人工、模板与 AI 使用同一合同；AI 提供候选，用户明确采用。人工未保存草稿必须保留。
- 普通用户只操作中文和类型化组件，技术键、UUID、哈希和 JSON 仅限明确折叠的系统信息。
- 失败必须标识具体阶段／可识别资料与字段、已保存内容及明确恢复入口。动作位于对应来源页，运行记录只负责查看并跳回；幂等回执不确定不重复创建，人工接管拒绝迟到覆盖。这条要求接入后续所有专业流程，不只开书页。
- 修订防覆盖、来源审计、历史引用和作用域校验属于各阶段的安全要求。
- 本轮不做 P3 全书画布、开书后长期批量生产导演、智能世界／人物工作台与视觉生成，不做 P4 版本专项、P5 权限体系。自动导演的开书准备部分已提前进入 P1-B。

> 白话理解：现有业务数据是一本账，界面和索引只是不同的查账方式，不能每换一个页面就抄出另一本账。

## 提示词分类树追加范围

2026-09-16 由讨论任务追加派发，随后用户锁定为最高优先；未勾选仍表示尚未完成，不以文档代替编码。

- 独立“提示词管理”入口，不要求普通用户从通用内容类型目录查找提示词。左侧选择分类／提示词，右侧编辑、预览；分类内可直接新建。
- 分类树与字典、标签在业务上独立；复用已有树形组件和提示词资源空间的资料分组引用，不另存提示词正文或建立事实孤岛。
- 中文初始分类：角色与职责、任务指令、写作要求、约束与质量、示例、上下文组织、用户自定义。支持子分类、原地新增、重命名、移动、同级排序和分类／提示词搜索。
- 每个组件默认一个主分类，标签支持额外多维归类。兼容已有多组成员时不丢引用，明确主分类与额外分组；移动只改组织引用，不改正文、配方或运行历史。
- 使用既有 `prompt_component` 资源，通过中文表单维护名称、内容、说明、适用任务与启停。分类不是执行顺序，也不会自动加入所有 AI 任务。
- 同一组件可被多个配方引用，禁止复制正文。分类用于查找维护，配方列表决定组合／排序；独立管理页与后续调试台互通。
- 资源管理、配方选择器、AI 组件选择处共用分类树查找／选择；普通用户不输入英文键、UUID 或 JSON。
- 作者组件与系统 PromptAsset 注册是不同层，均归属新设计。系统任务合同、schema、路由和凭据不改成普通组件卡；根模块写入例外明确被否决，需在新设计实现自有受控基础。
- 仅改 `new-design/`，不提前 P4 版本专项／P5 权限；完成编码后补充类型检查、分类移动／归档／引用稳定性测试及文档。真实界面未验收时明确说明，不能勾选完成。

> 白话比喻：分类树像图书馆书架，标签像检索贴纸，配方像某次阅读清单。对应到系统：移动书架位置只改变分类引用，同一提示词正文能被不同配方引用；分类顺序不等于运行顺序。

> 速记方法：分类管找，标签管筛，配方管组合；移分类不改正文，不改旧运行。
