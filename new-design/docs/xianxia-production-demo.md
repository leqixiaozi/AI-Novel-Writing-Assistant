# 《照骨山河》仙侠生产样例

本样例用于验证新设计卡片是否真的能支撑小说生产，而不只是展示空表单。卡片内容位于 `../migrations/004_xianxia_production_demo.sql`，书籍安装位于 `../migrations/006_template_books.sql`：新机器拉取代码并启动后，会得到同一套 55 张原创卡片、19 类书内类型副本和事件规划表单。

## 参考来源与转化边界

结构参考选取还珠楼主《蜀山剑侠传》第一回。维基文库的作品页标注该作品在中国大陆、台湾等作者逝世满五十年的地区属于公有领域，同时提示它在美国仍受保护至 2044 年；因此本项目不复制原文、专名、人物关系或具体情节，只做结构分析。

提取的抽象方法只有五项：

1. 先用山川、迁徙和日常职业建立可触摸的凡俗入口。
2. 让奇观由人物当前欲望触发，而不是先堆设定说明。
3. 导师在展示能力时同时说明门槛、恒心和代价。
4. 用一次真实旅程同时推进空间、人物关系与修行升级。
5. 在开篇末尾给出离开旧生活的不可逆行动。

《照骨山河》的角色、地名、组织、法器、修炼规则、事件因果、章节任务和场景内容均为原创。后续正文生产只应读取本样例卡片，不应把参考原文作为续写上下文。

> 🏠 **白话比喻**：这里像研究一栋老建筑的采光和动线，再在另一块地上画一套新房图纸；不会拆走旧建筑的门窗。对应到数据里：保留的是“凡俗入口 → 奇观递进 → 拜师门槛 → 启程”的抽象组织方法，写入数据库的是完全不同的原创故事事实。

> 🧠 **速记方法**：**借结构，不借砖瓦**。结构是叙事推进方式，砖瓦是原文表达、专名和具体情节。

## 可生产范围

样例书名为《照骨山河》，第一卷为《无灯照夜》。当前 55 张卡片覆盖全部 19 种核心类型：

|---|---:|---|

| 地点 | 5 | 日常起点、探索区、训练据点、交易节点和高潮地点 |
| 道具 | 4 | 核心法器、证据、战斗工具和通行凭证 |

## 第一章生产入口

正文可以从“第1章：逆水殓舟”开始。五个场景已按顺序给出视角、地点、目标、阻碍、转折和离场状态：殓舟靠岸 → 第七口棺 → 巡检封船 → 白焰照伤 → 旧名与封镇。

生产时建议至少装配这些卡片：沈照微、孟青萝、陆归尘、白水驿、照骨灯、殓舟第七具空棺、忘记的父亲声音、白焰认主。这样一章的行动、世界规则、证据、伏笔和人物代价能互相校验。

界面入口为“新设计 → 我的书籍 → 照骨山河”。“创作表单”可把事件主卡与人物、地点、道具、剧情线装配在一起；人物的本事件目标、立场和结果保存在挂载局部字段中。“本书资料库”展示全部 19 类卡片，标题不再重复显示《照骨山河》前缀。

## 跨机器同步

- `004_xianxia_production_demo.sql` 与 `006_template_books.sql` 使用稳定 UUID 和幂等迁移，属于可随 Git 同步的确定性基础数据。
- 本文记录来源、原创边界、卡片清单和生产入口，也应随 Git 同步。
- 作者之后在界面里修改或新建的正式业务数据仍位于 PostgreSQL，必须通过逻辑备份与恢复跨机器迁移；不要复制正在运行的数据目录。
