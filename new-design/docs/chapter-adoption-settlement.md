# 正文采用确认与章节稳定结算

## 目标与边界

章节正文从“候选”进入“可被下一章读取的稳定结果”必须经过同一条确认链。正文采用、变化提案、人工决定、正式事实／状态、稳定检查点和派生刷新都有明确账本；计划中的预期变化、未采用候选和未确认提案不能进入下一章上下文。

> 🏠 **白话比喻**：候选正文像餐厅后厨写好的菜单，采用是确认今晚按这份菜单出餐，变化清单是逐项核对库存和过敏信息，稳定检查点才是签字生效的出餐单。对应到系统：`chapter_body_versions` 保存菜单草稿，`chapter_adoption_sessions` 编排确认，事实／状态表保存正式结果，`chapter_stable_checkpoints` 是下一章可读取的签字单。

> 🧠 **速记方法**：**先选正文，再核变化，全部处理，最后稳定。** “稳定”不是按钮文案，而是同一事务完成采用引用、审核决定、正式变化、检查点和派生请求。

## 四步用户流程

1. 确认正文：展示整章候选、计划来源和版本来源。首次采用可继续；旧正文或稳定章节换稿只产生影响预览合同。
2. 整理变化：AI 按冻结合同、上下文、路由和尝试来源提交候选；作者也可手工补充。两种来源都必须保存正文精确字符范围与摘录。
3. 人工核对：按事实、角色所知、人物、关系、道具、事件和伏笔筛选，展开证据并选择纳入、不纳入或稍后处理。重要／核心变化始终需要人工决定。
4. 稳定结果：不存在待确认或稍后处理项时，单事务提交正式事实、知识变化、状态变化、里程碑和稳定检查点，并登记图投影与语义分块请求。

## 数据合同

- `settlement_policy_versions` / `book_settlement_policies`：书级、带版本的低风险自动确认策略。默认关闭；只有 AI 来源、低风险、类别在白名单且置信度达标时才允许策略确认。
- `chapter_adoption_sessions`：冻结准备记录、正文版本、计划版本、上下文、策略版本和依赖哈希。状态机区分审核、部分决定、结算、稳定、失败和影响预览。
- `chapter_settlement_items` / `chapter_settlement_item_versions`：把各领域提案汇总成统一确认清单，同时保留各领域正本 ID、风险、计划对齐、证据、来源和决定历史。
- `chapter_proposal_extraction_requests`：冻结 AI 变化提取的合同、配方、上下文和模型路由；AI 结果只能新增 `proposed` 状态内容。
- `chapter_stable_checkpoints`：连接采用正文、章节结算、上一检查点、章节顺序、确认摘要和依赖哈希。下一章只读取 `status='stable'`。
- `chapter_settlement_events`：只追加的过程审计与幂等回执。

事实继续写入 `canonical_facts`，角色所知继续写入 `knowledge_state_*`，人物／关系／道具／事件／伏笔变化继续写入 `state_change_*`。040 没有创建第二套小说真相表。

## 原子结算

`settleChapterAdoptionSession` 会锁定会话、章节档案和清单项，拒绝待确认／稍后处理项，随后在同一个 PostgreSQL 事务中：

1. 创建 `chapter_settlements`；
2. 确认或拒绝各领域提案并写审核历史；
3. 写正式状态／知识变化并更新当前投影；
4. 对开放事实冲突失败关闭；
5. 登记统一依赖资源，触发 AGE 图投影请求；
6. 针对启用的嵌入配置创建来源快照与分块请求，由 Outbox 接管后台执行；
7. 写状态里程碑和 `chapter_stable_checkpoints`；
8. 把会话推进到 `stable` 并写幂等事件。

事务失败时不会留下半套正式结果；会话写入可诊断的 `failed` 状态，作者修正提案后可重试。

## F5 换稿边界

只要章节存在稳定检查点，或目标正文与当前采用正文不同，本阶段不切换正文，也不失效旧事实。`GET /chapter-adoption-sessions/:id/impact-contract` 只返回旧／新正文、旧结算、旧检查点和下游依赖，且固定 `executionAllowed: false`。F5 在这个合同上实现影响预览、选择性重算和确认执行。

## 跨机器同步

迁移 `040_chapter_adoption_settlement.sql`、接口代码、运行包规格和本文随 Git 同步。作者的采用会话、提案决定、正式变化与稳定检查点属于 PostgreSQL 业务数据，必须通过项目逻辑备份／恢复合同同步；仅拉取代码不会带走写作进度，也不能复制运行中的数据目录代替一致性备份。
