## 事实与模块边界

继续复用正文采用准备、确认会话、结算清单、领域提案、章节结算、正式事实／知识／状态、当前投影、稳定检查点与状态快照。不得建立另一套状态账本，不能让界面确认清单成为新的正式事实。

> 白话比喻：结算清单像送货时的待签收单，签收结果记入原有账本，而不是再开一本账。对应到系统：清单引用已有领域提案，明确结算后才写入现有正式事实与投影。

> 速记方法：提案先审，结算入账，快照查源。分别对应待确认清单、正式事实和稳定结果来源。

## 合同先行的实现边界

公共编辑合同放入独立职责模块，不继续扩大既有大型 `common/contracts.ts`。目录应返回服务端限定的中文对象、正式字段定义、关系维度、版本／能力修订、字典节点、基线值及其来源、不可编辑原因。清单展示引用冻结规格，不能用最新字典重新解释历史值。

类型化输入复用现有 `DynamicForm` 控件及 `TreeSelector`。现有动态字典控件读取最新字典且允许按规则新增节点，不可直接当作冻结结算字典；结算输入禁止暗中修改字典。关系维度若无正式值类型来源，应明确不可编辑原因，不能恢复自由英文键或裸 JSON 输入。

保存／修改／审阅请求携带会话与提案期望修订、原请求标识及冻结规格。错误按 [失败恢复门禁](wiki/failure-recovery-gate.md) 提供中文阶段、对象／字段、保留结果与来源页动作。运行记录仍只读。

## 需讨论任务确认的语义

需求讨论任务已确认：本轮保持现有状态语义，“事件结果”仅为对象／资料状态变更，“关系变化”仅为资料关系状态变更。故事时间、事件因果与并发等 `storyTimeline` 提案的编辑、确认及联动安排后续多维／P3 工作台，复用原合同与正本，不纳入本轮状态确认、不以状态 JSON 伪装或复制事实。若有相关待办，本轮仅只读提示或跳实际来源；若结算确实依赖已有前置条件，明确展示条件与来源恢复，不默默绕过或自动改变。P4／P5 重算专项仍不进入本轮。
