# 模型设置、执行和失败恢复

## 操作范围

从“高级设置 → 模型设置”进入，左侧选择默认创作模型或中文任务，右侧编辑首选模型、备用顺序、技术失败类别和用量策略。点击“保存并启用”将设置与生效版本一起提交。任务没有独立路线时继承默认；“此任务恢复默认”只停用任务覆盖，保留历史版本。

连接检查只检查服务与显式选择的模型，不自动选择列表第一项。配置可读取不等于连接成功。普通界面使用中文；专用环境变量名和版本凭证放在折叠区。凭据只保存引用，不保存密钥正文，不读取旧网关或旧配置。

| 接口协议 | 示例地址 | 请求与认证 | 检查范围 |
| --- | --- | --- | --- |
| 本机 Ollama | `http://127.0.0.1:11434` | `/api/chat`，本机直连 | `/api/tags` 返回名称；生成仍需单独验证 |
| OpenAI 兼容 | OpenAI `/v1`、OpenRouter `https://openrouter.ai/api/v1`、MiniMax 中国区 `https://api.minimax.cn/v1` | `/chat/completions`、Bearer；OpenRouter 结构化请求限定支持参数的端点 | `/models` 返回名称；同一网关不同模型的结构化能力可能不同 |
| Anthropic Messages 兼容 | Claude `https://api.anthropic.com/v1`；MiniMax Anthropic 路径以服务方文档为准 | `/messages`、顶层 `system`；Claude/MiniMax 用 `x-api-key`，OpenRouter Messages 用 Bearer | `/models` 由服务方提供；Claude 官方目录分页时核对所填模型 |

传输前形成统一任务请求，协议适配器只转换 HTTP 格式；收到回复后统一成内容、输入用量、输出用量与可用性，再做 JSON 和原任务合同校验。Claude 官方结构化输出的 Schema 子集不替代原合同；不能安全表达或超过语法上限时只使用提示词中的原合同，并继续严格核验回复。当前 MiniMax-M3 使用已配置的 OpenAI 兼容路线；其中国区凭据和地址与国际区不混用。

> 🏠 **白话比喻**：默认模型像常用快递公司，任务覆盖像某类包裹指定专门承运人，备用像约好的候补承运人。对应到系统：每次调用读取已生效配置，并先保存确切版本快照；修改设置只影响后续调用。

> 🧠 **速记方法**：先保存生效，再冻结版本，最后发请求；检查连接不是生成成功。

## 预算和技术备用

输出上限与总预算独立：每次尝试按输入与结构规格的 UTF-8 字节数加 256，以及输出上限预留预算。所有重试和备用共用本次预算；丢失回复也保留预留额，不重置预算。此方法是保守调度估计，不是模型分词计量或收费保证。上游未报告用量、失败尝试的实际用量未知时，快照明确标注不完整；不声称已知全部用量。

> 🏠 **白话比喻**：总预算像一次出门带的钱，每次换乘先留出车费；前一趟是否扣款不确定，也不能假装钱包重新装满。对应到系统：重试前检查剩余预留额度，不足时停止发送；成功输出仍保留，不因后续计量异常丢掉。

> 🧠 **速记方法**：一次钱包，多次共用；预留不是账单，未知不能算零。

只有配置明确允许的技术失败才切换备用。超时、频率限制、服务不可用和连接失败可按次数重试；授权失败不盲目重试。内容不符合任务结构时直接说明失败，不自动换模型，不用模板或关键词生成假结果。

## 失败恢复入口

|失败阶段|保留的内容|具体操作|
|---|---|---|
|连接或模型检查|当前设置草稿|在连接区域修改地址、凭据或模型，点击连接检查|
|字段校验|当前设置草稿|按中文字段提示修正，点击“保存并启用”|
|提交回执不确定或修订冲突|人工编辑、已确认版本|点击“核对服务器结果”，再明确选择服务器设置或保留自己的设置按最新修订继续|
|保存已成功，目录刷新失败|成功版本及保存凭证|重新读取目录，不重新保存|
|凭据引用创建结果不确定|当前路线与已创建引用|读取并核对凭据目录，明确确认后继续，不自动重复创建|
|任务模型路由、凭据或预算不可用|已有创作资料和人工内容|点击“打开模型设置”，修正并生效，返回来源页核对候选后重试|
|配置快照未能保存|已有创作资料，模型请求未发送|检查运行维护，恢复后从来源页重新发起|

运行记录用于查看状态和打开来源页；恢复和重试在有创作上下文的来源页操作。全流程恢复覆盖仍按执行队列逐项完成，本功能不代表所有工作台均已覆盖。
