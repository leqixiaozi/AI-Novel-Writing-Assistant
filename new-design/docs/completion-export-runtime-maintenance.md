# 完本、导出与运行维护

F8 把创作流程收口为可检查、可完本、可安全导出、可维护。实现以 `044_completion_export_release_gate.sql` 为数据合同，不复制章节、质量、任务或备份正本。

## 完本检查

完本检查读取采用正文、稳定检查点、客观质量问题、待确认事实/状态/知情提案、伏笔、旧章返修、失败任务、依赖失效、备份和扩展状态。结果写入不可变快照；来源发生变化时，旧快照保留但不再是当前快照。完本状态使用只追加事件：`completion_checked`、`completed`、`reopened`。

> 🏠 **白话比喻**：它像交房验收单。房间、管线和门窗仍是原物，验收单只记录检查当时看到的结果。对应到系统：正文和事实仍在各自正式表中，快照只保存规则、来源哈希和问题清单。

> 🧠 **速记方法**：**先检查、再清阻断、后登记完本。** 提醒项可由作者判断，阻断项必须处理。

## 导出合同

支持 Markdown、UTF-8 纯文本、DOCX；支持全书、指定卷和指定章节。正式稿必须绑定当前完本检查快照，且章节处于从第一章开始的连续稳定范围。审阅稿允许使用尚未形成稳定检查点的采用正文，并在文件中标记稿件性质。

流程分两步：先生成不可变 manifest，冻结章节顺序、正文版本/哈希、稳定点、范围和格式；提交前再次校验采用正文与稳定点，一致才通过既有 Outbox/后台作业生成文件。

> 🏠 **白话比喻**：manifest 像印厂开机前的逐页蓝纸清单。原稿换过就停下重做清单。对应到系统：409 表示来源漂移，不会拿旧预览悄悄导出新正文。

> 🧠 **速记方法**：**预览冻结，提交复核，后台生成，只写新文件。** 导出器拒绝覆盖，并把文件限制在应用私有 `exports/` 目录。

## 运行维护与跨机同步

`/new-design/structure/maintenance` 聚合私有运行时诊断、后台作业、AI 恢复来源、031 传输操作和 Release Gate。后台作业可安全重试、取消或重新派发；AI 任务仍回到来源页面处理。整库恢复不会暴露为普通按钮，必须经过停写排空、dry-run、兼容性检查、独立备份、受控切换和失败回滚。

Git 同步代码、001—044 迁移 SQL、内置定义和数据文档。作者正文、资料、版本、完本记录、导出记录和任务账本属于 PostgreSQL 数据，必须通过整库备份或书籍数据包同步；受管附件随 manifest 迁移。不能复制运行中的数据库目录充当备份。

下载接口只接受数据库登记的受管 locator，并验证目录边界、符号链接和文件类型；API 不返回物理路径或凭据。
