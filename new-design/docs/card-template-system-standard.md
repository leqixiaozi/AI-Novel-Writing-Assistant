# 卡片与书籍模板体系标准

## 文档状态与范围

本文是新版小说创作流程的**目标设计基线**，用于讨论和实现“元卡片 → 卡片模板 → 书籍模板 → 本书资料”。它不表示新菜单、图形编辑器或计算规则已经上线。现有数据结构与可运行能力仍以 `src/`、`migrations/` 和[数据字典](data-model.md)为准；原型 HTML 只作交互参考，不作业务正本或运行依赖。

本体系只使用 `new-design/` 的客户端、`/api/new-design` 接口、卡片内核和新版数据库。元卡片、卡片模板、书籍模板将有**独立菜单与页面**；已有“内容类型”“创作表单”“开书模板”等页面和数据不能通过换名伪装为新功能，接入时应复用其正式能力并补齐差异。

## 对象及身份

| 层次 | 含义 | 当前可复用的正本 | 必须保持的边界 |
| --- | --- | --- | --- |
| 元卡片 | 可复用的字段块和展示语义，不是某本书里已填写的人物或世界 | 新的元卡片定义及版本；发布时投影到 `card_types`／`card_type_versions` | 定义与内容类型不是同一对象；稳定 key 与字段 key 不因改显示名而变化 |
| 卡片模板 | 将多个独立元卡片放入有名称、槽位和必选规则的模块蓝图，如“人物模板” | 新的卡片模板定义及版本；书内分组可复用 `material_group` | 每创建一个人物实例才产生一组槽位；组内元卡片填充后各自成为资料卡，不合并成一张 |
| 书籍模板 | 以“书籍基础信息”元卡片为根，引用卡片模板和可独立使用的元卡片，规定开书时可用结构 | `template_groups`、不可变的 `template_group_versions` | 同一人物模板只引用一次，可指定初始实例数量；发布时冻结根卡字段、来源版本和装配规则 |
| 本书 | 从某个书籍模板版本开出的具体作品 | `books`、书内 `card_spaces`、唯一书籍根卡与独立模板快照 | 书籍 ID 与书籍根卡 ID 不同；修改本书不回写模板 |
| 本书模块实例 | 本书中的顾玄、叶知秋等具体人物组 | 书内模块实例记录与 `material_group` | 同一人物模板引用可创建多个独立实例；组 ID 不等于人物卡 ID |
| 本书资料卡 | 某个人物实例中的基础身份卡、战力卡等已确认内容 | `cards`／`card_versions` 与正式资料关系 | 每个元卡片槽位独立填成一张卡；组内关系需明确确认，不凭同组推断 |

书籍基础信息**是一张真正的卡片，也是图上的唯一根节点**。开书时填写书名等信息，立即在本书空间创建根卡和首个卡片版本；书籍模板中的其他元卡片仍先成为待填槽位。现有 `books` 保留书籍聚合身份、空间、模板绑定和列表查询；根卡保存可版本化的书籍资料，`books.name/description` 与根卡对应字段须由同一事务维护，不能各自改出不同内容。根卡后续编辑走书籍根卡专用命令；普通卡片更新、归档和复制不能绕过它。比如把根卡《守影者》改名为《夜行录》，根卡版本与书籍列表须一次提交并同时变为《夜行录》。一书只能绑定一张根卡；模板节点 ID、根卡 ID、书籍 ID、槽位 ID 和卡片版本 ID 均分开，不能用中文名称或画布坐标推断对应。

书籍模板对同一卡片模板只保留一次模块引用，也可以在根节点下单独放置元卡片。模块引用是可重复使用的蓝图，不是顾玄等具体人物；它配置开书时要预建多少实例（可为零），本书需要更多人物时再从该引用创建。每个本书模块实例有独立分组、成员槽位和内部关系线，首次确认填写才形成正式资料卡；独立元卡片则直接成为本书待填槽位。只有选为“拥有／归属”等包含类型的连线才改变结构归属。战力等元卡片填成独立资料卡，必须以明确的“归属人物”关系连接所属人物卡，同组本身不能代替这种关系。

> 比喻：元卡片是积木的规格，人物卡片模板是制造一个人物模块的模具，书籍模板是整套搭建图，本书是依图搭出的作品。顾玄与叶知秋是同一模具在本书中造出的两个模块实例，各有自己的卡片和关系。

## 装配图与真实关系

整个产品需区分三种连线，本批模板编辑器处理装配线以及预设的资料关系线：

1. **装配线**：选择“拥有／归属”等类型，表示书籍模板包含某卡片模板，或卡片模板包含某元卡片；它定义结构与槽位。
2. **资料关系线**：模板内可预设“战力归属人物”等有向关系，并明确必需／可选；开书先复制为待绑定关系，两端资料卡确认后，再按已发布关系类型版本和作者确认建立真实 `card_relations`。“人物拥有战力”可反向展示，不创建第二条事实。人物与战力卡均已填写但必需归属线尚未确认时，模块仍待核对，人物战力计算不能采用该战力卡；可选关系未确认不阻断完成。其他书内人物关系也沿用已发布关系类型及作者确认流程。
3. **计算依赖线**：某项计算读取哪些状态或关系维度，属于规则输入，不因拖动画布而变化。

节点位置、尺寸、组框、折叠、缩放、线条颜色和视图标签是编辑布局；它们与结构、关系和计算语义分开保存。删除一条装配线、结束一条业务关系、移除一条计算依赖，必须展示各自不同的影响。空白画布不代替模板目录、必填检查和作者下一步引导。

## 发布、复制与创作流程

1. **系统定义**：维护元卡片字段，编排卡片模板，再组合书籍模板。草稿可改；发布形成可追溯版本，保存节点、槽位、关系、约束及所引用定义的确切版本。另存为新版本不影响旧版。修改当前共享版本须列出所有引用版本和已开书籍的差异，逐本确认同步；未确认者仍使用原快照，历史修订不被抹除。
2. **基本信息与开书复制**：作者先填写书名、说明、篇幅与目标字数，并可补题材基底、文风关键词、目标读者等根卡字段，再选择已发布书籍模板版本。新版开书流程把模板版本绑定到本书，创建已填写的书籍根卡，复制独立结构、字段和关系快照，按模块引用配置的初始数量创建具体模块实例，只为这些实例和独立元卡片生成待填槽位及独立关系身份，并保留来源映射；本书可改，原模板不受影响。
3. **资料填充**：人工或 AI 准备世界、人物等资料。AI 结果是候选；作者核对后才成为正式卡片内容。每个待填槽位可解释“缺少什么、由谁建议、是否确认”。
4. **故事规划**：采用故事、卷、章、场景规划，引用确切的本书卡片版本。上游版本变化后，下游需要待复核标记，而不是悄悄换用新值。
5. **生成前预测**：计算只读取当时有效且冻结的资料、关系、状态和规则版本；预测用于引导章节任务，不提前改变正式状态。
6. **正文与结算**：生成候选、人工编辑、明确采用正文；基于采用正文提出变化，再由作者确认结算。确认后的状态投影供下一章读取。

以上是**完整目标流程**，不是本批三个定义页面均已实现的承诺。新版已有模板版本、开书审阅、规划版本、AI 上下文、正文采用与章节结算基础；本批的图形装配与书内节点映射方案见[功能设计](card-template-feature-design.md)和[数据库设计](card-template-database-design.md)，通用计算规则另行设计。不得用浏览器 `localStorage`、原型截图或只有前端连线的页面冒充正式保存。

## 数据与操作的最低要求

- **版本与来源**：发布版本记录稳定对象 ID、精确版本 ID、内容哈希和引用来源；开书记录书籍模板模块引用到每个本书模块实例、局部槽位到本书槽位的映射。
- **校验**：发布前检查必选槽位、数量、重复键、循环包含和不存在或未发布的来源；开书前检查所选模板版本可用。
- **本书字段规则**：书籍模板对元卡片字段的局部覆盖在开书时冻结到槽位；第一次填槽和此后从任何入口编辑绑定卡片，都按该槽位的有效规格校验。比如本书把“速度”改为必填，后续也不能清空，不因共享元卡片原本可选而放行。
- **变更边界**：本书内容与模板隔离；模板升级先预览影响，旧版仍可读，不静默覆盖作者修改。
- **AI 权限**：AI 可建议字段、结构或关系，但不自动发布模板、采用书内资料、采用正文或确认结算。
- **读取与恢复**：编辑器刷新后从新版服务端读取草稿和版本；写入使用修订号与原请求键处理并发和未知回执。
- **初心者入口**：默认展示模板列表、缺项与下一步；自由画布作为同一数据的高级编排视图，不另建正本。

## 待讨论的功能与模式

以下后续模式尚未定案，**不能作为本批实现合同**：

- 平行世界、不同时间线和章节局部资料如何设适用范围、继承与冲突处理？
- 战力及关系维度的公式语言、单位、缺值处理、循环依赖、版本与重算边界如何定义？预测与正式结算的差异如何呈现？
- 超出本批两级包含结构的多层嵌套和跨书籍模板引用，如何控制实例数量及循环？

讨论定案后，先更新本文的对应规则，再将它们落到新版数据合同、API 和页面。不得把开放问题直接写入现有表的非结构化字段并视作正式能力。
