# U5 资料管理静态审查

## 审查结论

- 数据边界：迁移 036 只新增组织引用、不可变定义版本、操作事件和归档影响证据，不复制资料正文或智能视图结果。
- 隔离边界：书籍与公共资源空间必须二选一；标签、分组父子、成员和视图都按同一 `space_id` 校验，分组额外锁定 `book_id`。
- 树边界：禁止自指、循环、跨空间／跨书父项和归档父项；归档明确选择提升子项或归档子树。
- 查询边界：筛选 AST 使用字段／运算符矩阵、参数化值、深度／条件／排序／分页上限，不接受任意 SQL、JSONPath、Cypher 或函数。
- 历史边界：标签、成员、分组、智能视图和归档事件使用只追加版本；并发写要求 `expectedRevision`，重试要求 `idempotencyKey`。
- 删除边界：标签、分组、视图和资料均为软归档；组织项归档不会删除资料。
- 依赖边界：标签／分组成员和智能视图定义接入 026 资源登记；资料归档／恢复通过既有失效函数产生待重算请求，由 030 Outbox 接管，不直写 AGE。
- 兼容边界：六个 `book_view_configs` 在迁移时生成对应智能视图；旧视图配置保存会追加统一视图版本。
- UI 边界：本书资料和公共创作资源复用同一管理组件，具备真实加载、空、错误、冲突和无权限文案；危险归档使用影响对话框。

## 已做静态检查

- 服务端 TypeScript：`tsc -p tsconfig.server.json --noEmit`。
- 客户端 TypeScript：`tsc -p tsconfig.client.json --noEmit`。
- 迁移编号、运行时清单、接口与客户端方法逐项对照。
- 文案检查：用户界面使用“资料、内容类型、创作表单、分组目录、智能视图”，没有要求作者理解底层卡片结构。
- 样式检查：普通区域使用浅底、留白和选中态，没有新增第三方 UI 组件或持续阴影。

## 未执行与发布验证债务

遵照开发优先策略，本批没有运行单元测试、集成测试、构建、服务、浏览器、截图、真实 PostgreSQL、迁移执行、AGE、pgvector、安装包、备份或恢复。

发布前必须验证：

1. 在真实 PostgreSQL 顺序执行 001—036，验证不可变触发器、分组环路防护、资源回源和旧六视图回填。
2. 覆盖标签批量增删、资料多分组、分组提升／归档子树、视图复制／修订／归档及全部并发 409。
3. 覆盖筛选 AST 的白名单、4 层／40 条限制、100 条分页上限和恶意 SQL／JSONPath／Cypher 输入拒绝。
4. 覆盖归档预览过期、令牌错误、哈希错误、修订变化、引用变化、阻塞项、风险确认、恢复和幂等重试。
5. 验证归档产生的 026 重算请求进入 030 队列，AGE／pgvector 只由既有投影和索引流程重建。
6. 用 031 完成数据库、附件和 manifest 的跨机器恢复，确认标签、分组、视图与归档历史一致。
