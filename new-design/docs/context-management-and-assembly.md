# 上下文绑定、装配预览与运行快照

## 目标

迁移 `037_context_binding_assembly_snapshots.sql` 把“哪些资料可以进入某个创作任务”从各页面的临时拼接提升为版本化规则。作者在“高级设置／上下文管理”使用表单维护规则，在正式运行前查看装配预览；受控运行时在同一事务中冻结运行快照。

> 🏠 **白话比喻**：规则像选菜标准，manifest 像这次真正装进餐盘的逐项小票。对应到系统：规则决定候选范围，运行快照记录某次任务最终选入的确切资料版本、未选原因和预算结果，而不是复制资料正文。

> 🧠 **速记方法**：**先定范围，再筛候选；必须事实不裁，参考资料按预算；预览可失效，快照不改写。**

## 数据边界

- `context_bindings` 保存稳定规则身份、作用范围和当前／采用指针；`context_binding_versions` 与选择器只追加版本。
- 作用范围包括系统、公共资源、任务组、任务节点、书、卷、章、场景和本次调整。解析顺序固定为系统／公共默认 → 任务组 → 任务节点 → 本书 → 卷／章／场景 → 本次调整；同名规则按继承、覆盖或排除处理。
- 激活条件只接受白名单字段、白名单运算符以及最多 4 层、40 条条件的 AND／OR 结构。接口和数据库都拒绝 SQL、JSONPath、Cypher、JavaScript、脚本或提示词表达式。
- 来源选择器支持明确资料版本、内容类型、标签、智能视图、资料关系、故事范围、研究资料包、提示词组件和既有语义检索轨迹。智能视图和检索只提供候选，不直接成为正式运行依据。
- `context_previews` 冻结书籍、任务合同、提示词配方、规则版本、候选决定、Token 估算与来源集合哈希。预览不调用模型，也不是正式运行记录。
- `context_manifests` 在内部 finalize 事务中冻结任务合同、提示词配方、模型路由、规则版本、确切来源版本、检索轨迹和选入／排除理由。正式快照及其槽位、条目和排除项禁止更新或删除。
- manifest 只保存引用、决定、小型摘要、哈希和数量，不复制正文、卡片字段值、向量、提示词正文或凭据。

## 预算与失败关闭

每条规则声明装配位置、优先级、资料角色、局部预算、裁剪方式和去重方式。必须事实不会被自动裁剪；只要必须事实总量超过总预算，或明确要求的确切来源不可用，预览状态就是 `invalid`，内部 finalize 会拒绝形成运行快照。参考资料可按优先级和大小移出，并保留逐项原因。

## 并发、审计与失效

规则修改、采用和归档都要求 expected revision 与幂等键。发生 `409` 时，界面保留本地表单并显示服务器修订供对照。规则只允许归档，不做物理删除。

上下文规则版本、装配预览、任务合同、提示词配方、模型路由、正式来源和语义检索轨迹均进入 026 依赖账本。来源变化不会修改历史运行快照；尚未运行的预览会标记为需重新预览，后续预览重新读取当前候选。

## 接口

- `/context-bindings`：规则列表、创建、版本、采用、归档、规则校验和解析。
- `/context-previews`：按书籍与任务生成、读取和列出装配预览。
- `/books/:id/context-snapshots`：按书籍查看运行快照、详情和来源链接。
- `/books/:id/context-impacts`：查看规则或预览在依赖账本中的状态与失效原因。
- `/internal/context-manifests/finalize`：仅供受控运行时调用，事务化冻结正式运行快照。

所有普通读取都带书籍边界；普通作者界面使用“上下文、参考资料、必须事实、激活条件、装配预览、运行快照”等业务词。版本号和哈希只在高级模式展示。

## 跨机器同步

迁移 SQL、运行包清单和本文随 Git 同步，可保证不同开发机器得到同一结构。作者实际创建的规则版本、预览和运行快照属于 PostgreSQL 业务数据，必须使用项目的逻辑备份／恢复与受管附件流程迁移；只拉代码不会同步这些运行数据。
