# 元卡片、卡片模板与书籍模板功能设计

## 状态、依据与交付边界

本文是**产品与交互目标合同**，不是上线说明。目标只落在 `new-design/`：新增三个独立菜单和页面，以新版 API、卡片内核及开书流程为正本。参考原型为 Obsidian 项目中的《卡片体系配置台》《系统卡片可视化编排台》《书籍模板配置台》和《开书与书籍配置台》；原型的浏览器本地存储和示例书籍不进入正式数据。界面采用原型的三栏布局、卡片信息密度与图形操作，在新版 Shell 中使用现有主题、按钮、输入框和状态样式，不逐像素复制原型深色皮肤。

本期范围是三层定义页面，以及开书选择已发布书籍模板并复制其结构。对应新版源码与增量 SQL 已开始实现；是否安装到作者数据库、是否完成页面验收，以各自检查记录为准。AI 自动填充、通用战力公式、人物关系计算及章节结算不在本期；它们可在书内资料卡建立后按已有合同接入。

当前实现批次先交付三层定义、书籍模板直接开书、根卡与待填槽位、模块实例及书内关系确认。下面所述的书籍模板局部字段覆盖、已开书籍逐本结构同步和 AI 候选填槽仍是目标合同，尚未进入本批已验证能力；不能把影响预览当作同步完成。数据库迁移未应用前，页面与接口也不视为作者环境可用。

## 对象边界与一个贯通例子

| 对象 | 作者看到的含义 | 编辑结果 | 开书后的对应物 |
| --- | --- | --- | --- |
| 元卡片 | 可复用的字段块，如“基础身份”“战力维度” | 字段、选项来源、必填规则及发布版本 | 一个待填槽位；填写确认后成为**一张独立资料卡** |
| 卡片模板 | 放入一个框中的元卡片集合，如“人物模板”；是创建一位人物所用的模块蓝图 | 成员槽位、必选性、顺序、内部关系线及布局版本 | 每创建一个本书模块实例，产生一个分组及组内独立待填槽位；不是一张合并卡 |
| 书籍模板 | 以“书籍基础信息”元卡片为根，引用卡片模板模块和独立元卡片 | 根卡字段、模块引用、初始实例数量、独立节点、关系线、局部字段设置和精确来源版本 | 可修改的本书结构快照；同一模块只引用一次 |
| 本书 | 从一个书籍模板版本开出的具体作品 | 书籍 ID、已填写的唯一根卡和独立结构快照 | 修改本书不回写书籍模板；根卡就是本书的书籍信息卡 |
| 本书模块实例 | 某本书中的“顾玄”“叶知秋”等具体人物组 | 模块实例 ID、组 ID、各自的待填槽位和内部待绑定关系 | 新增人物是新增实例，不回写或重复放置人物模板 |
| 本书资料卡 | 顾玄的基础身份卡、顾玄的战力卡等具体填写内容 | 卡片 ID、字段值和卡片版本 | 每个元卡片槽位分别填成一张资料卡；同一组内的卡片也须靠明确关系关联 |

例如“人物模板”框内有“基础身份”和“战力维度”，并预设“战力维度 --归属--> 基础身份”。书籍模板只引用一次人物模板，并指定开书时预建几个空白人物实例；开书后还可以点“新增人物”。每个实例各自复制两个待填槽位和一条待绑定关系。顾玄的“基础身份”填成顾玄人物卡，战力槽位填成独立战力卡，两张卡均确认后，才建立战力卡指向顾玄的正式资料关系；再创建叶知秋时获得另一组槽位与关系，不会共用顾玄的战力或关系。“顾玄拥有战力”可作为同一关系的反向展示，不能重复造两条事实。直接连到书籍根节点的“序章目标”元卡片没有模板组，填写后也独立成卡。“顾玄与叶知秋是师徒”属于两个实例之间的资料关系，须单独建立。

原型中有把组内字段合成一张人物卡的示例文案；正式设计按已确认的“每个元卡片独立成卡”执行。这是**数据语义上的明确调整**，不是遗漏原型功能。原型预置的人物、世界和书籍内容仅用于交互对照，不自动导入作者的真实书籍。

稳定身份采用书籍 ID、定义对象 ID、版本 ID、书籍模板模块引用 ID、本书模块实例 ID、实例节点 ID、槽位 ID 和本书卡片 ID；书籍根卡 ID 与书籍 ID 一对一绑定但不混用。中文名称、画布位置、X6 cell ID 的显示形式均不能代替业务身份。同一书籍模板对同一卡片模板保留一个模块引用；创建多个人物是在本书基于该引用生成多个模块实例，每个实例有自己的组、槽位、内部边和最终资料卡。一个元卡片可以在不同模板中复用。包含关系为“书籍根卡 → 本书模块实例 → 元卡片槽位”和“书籍根卡 → 独立元卡片”；书籍模板中的模块引用是创建实例的蓝图，不是一个已填写的人物。连线须选择已定义的关系类型及方向：“拥有／归属”等包含线决定组或卡的装配归属；元卡片间的资料关系线还须标记必需／可选，开书后等待两端卡片与作者确认，不以坐标或同组代替。删除归属线应预览节点移出后的影响，不能仅删视觉线条。

## 操作流程

1. **定义元卡片**：从目录新建或选择元卡片，编辑名称、稳定 key、说明、分类以及字段。字段支持现有新版字段类型、默认值、必填、选项／字典来源、说明和排序；草稿可保存，发布前检查重复 key、字典有效性和字段规则。发布冻结元卡片版本。改名不改变 key，已有发布版本不被编辑。
2. **编排卡片模板**：从已发布元卡片目录点击加入或拖入画布，用组框组织成员，设置槽位必选／可选和显示顺序。列表视图与 X6 图形视图读写同一草稿；组内是具体元卡片节点，不用一张抽象卡片代替。保存草稿、预览、发布和复制模板均有明确操作及回执。发布冻结成员所引用的精确元卡片版本。
3. **编排书籍模板**：选择或新建书籍模板，根节点固定为可填写字段的“书籍基础信息”元卡片，拖入已发布卡片模板作为模块引用，也可直接拖入已发布元卡片。同一卡片模板只引用一次，并配置开书时预建的模块实例数量。根卡在开书时立即成为本书正式卡片；独立元卡片及已预建模块实例的成员先是待填槽位。编辑节点、关系类型与方向、版本引用、必选性与布局；选中元卡片还可仅在这份书籍模板中覆盖字段显示名、默认值和必填性，字段 key 与来源元卡片不变。资料关系线可标记必需／可选；“战力归属人物”是必需关系。发布冻结整张装配图、局部字段设置和所引用的精确版本。“另存为新版本”产生独立版本，不修改其他版本或已开书籍。若选择“修改当前共享版本”，先列出引用链上所有模板版本和已开书籍及字段、节点、关系的差异；历史发布快照不原位改写，逐本明确确认同步后才为该书生成更新后的独立副本，未确认的书保持原快照。这是影响范围覆盖所有引用方、实际更新逐本确认的共享变更。
4. **开书**：先填写书籍根卡的通用基本信息，再选择已发布的书籍模板版本。所有书籍模板根卡须保留相同稳定 key 的通用字段：书名、作品说明、篇幅形式和目标字数；题材基底、文风关键词、目标读者等定位字段也由根卡承载。模板专有的额外字段在选定模板后继续补填。书名在正式确认时必填，其他字段的必填性按根卡字段规格校验。模板列表展示版本、组成模块、初始实例数量及待填数量。作者确认开书时，在同一事务内建立 `books` 和书内空间，安装根卡所需类型，创建已填写的书籍根卡及首个版本，把根卡 ID 与书籍、所选模板版本绑定，并复制独立的结构、关系和字段快照；仅为配置的初始模块实例建立书内分组、各自的待填槽位与内部待绑定关系，独立元卡片另建槽位。书籍根卡是画布唯一根节点；`books.name/description` 与根卡对应字段同步维护。本书副本可改，不回写原模板。

   书籍模板开书与原有“创作准备 → 统一审阅 → 开书”流程分开：新流程先开书，再在本书填充槽位并核对关系。后续 AI 候选只有明确绑定目标槽位且经作者采用，才算完成填写；不得仅凭同类型或同名自动匹配。
5. **填充与核对**：开书后从书籍列表进入本书资料，左侧先显示已填写的书籍根卡，再显示具体模块实例、待填槽位和其他已填卡片；右侧填写或查看选中项。点选待填槽位时展示本书冻结的有效字段规格、必填缺项和来源版本。人工输入或后续 AI 候选经作者确认后，首次生成本书资料卡并绑定槽位；再次编辑仍走正式卡片版本机制，但每次保存都按该槽位的有效字段规格校验，不能退回共享元卡片的较宽松规则。例如本书把“速度”设为必填，后续从普通资料入口清空速度也必须拒绝。编辑根卡的书名或说明走本书根卡专用写入命令，在同一事务内生成卡片版本并同步 `books` 的列表字段；其他普通卡片写入入口不能绕过该命令修改或归档根卡。关系两端尚有待填槽位时只显示“待绑定”，不能创建正式资料关系；两端确认后校验关系类型，提示作者确认建立关系。已填卡片与已绑定关系分开显示：例如人物和战力都填完、但“战力归属人物”尚未确认时，模块仍提示必需关系待确认，不能把这张战力卡计入该人物的关联属性或相关计算；可选关系未确认不阻断模块完成。未填写槽位不进入正式资料检索、关系或计算。模板修改不会静默覆盖本书结构和内容。

发布书籍模板时必须有且只有一个可实例化的“书籍基础信息”根卡；其他元卡片槽位按模板选择，**不强制存在“世界”组**。缺失必选成员、未发布来源、失效字典、重复业务 key、无效关系端点或包含循环时拒绝发布，并定位问题节点。战力槽位若声明归属人物必需，则其人物端点与关系类型也必须有效。删除已发布来源定义不影响旧版快照；归档后不得被新草稿新增引用。

书籍模板中一个卡片模板对应一个模块引用，引用配置开书时预建的实例数量（可以为零）。本书需要第二个人物时，通过“新增人物”从同一引用创建第二个模块实例；只有已创建的实例产生待填槽位和内部待绑定关系。上文“组”在书籍模板编辑时指模块引用的预览，在本书填写时指具体模块实例。

## 页面与 X6 交互合同

三个入口放在新版“运行与设置”的结构配置区，名称分别为“元卡片”“卡片模板”“书籍模板”。保留现有“内容类型”“创作表单”“开书模板”入口及其既有行为；新入口不是改名页。左栏是可搜索、按分类展开的目录，中央是列表或画布，右栏是选中节点、连线或版本的填写与来源面板。左右栏可拖动调整宽度并收起；窄屏按目录、工作区、详情顺序堆叠，画布自身保留可平移空间。

| 操作 | 可见结果与数据边界 |
| --- | --- |
| 添加／拖入节点 | 书籍模板中同一卡片模板只产生一个模块引用，重复拖入定位已有引用；本书中从引用“新增人物”时生成新的实例、节点和槽位 ID；右栏显示对应字段。 |
| 组框与框选成组 | 组内卡片保留相对位置；移动组时成员整体跟随，缩放组框不能遮住成员；把节点放入框内更新成员归属。 |
| 收起／展开 | 收起只隐藏子节点和相关视觉细节，展开恢复原位置、大小和连接；不删除成员。 |
| 四向端口连线 | 连接有效节点时选择关系类型和方向；选中线后可查看两端、修改关系类型／标签或删除。拥有／归属线维护装配归属；元卡片间关系线冻结为待绑定关系，两端成为正式卡片后才创建经校验的书内资料关系。 |
| 选择、复制、删除 | 右键菜单及工具栏提供复制节点、复制节点及子节点、删除线／节点；复制书内模块实例时重建组、节点、槽位及内部边 ID，引用来源版本保持不变；书籍模板中的模块引用不能通过复制产生同源第二份。删除含成员的组先显示影响；根节点不可删。 |
| 布局与视图 | 自动布局只在点击时执行；拖动和调尺寸显示对齐线；手动尺寸有内容最小值。提供撤销／重做、选择／框选、手型平移、45%—200% 缩放、100% 与适应可见内容。工具栏可收起。 |
| 保存与恢复 | 画布变更进入同一服务端草稿；刷新恢复节点、线、标签、组归属和手动布局。撤销／重做是当前编辑会话操作，发布版本由服务端保存。 |

X6 只负责编辑和渲染装配图；React 页面状态及新版服务端合同保存语义数据，不把 `graph.toJSON()` 的任意图元属性当数据库正本。编辑器适配以原型使用的 X6 2.x 为基线，引入与之兼容的 Selection、Transform、Snapline 等能力，并核对本地打包与许可。端口线、组框折叠和复制子树的业务语义由本项目实现和校验，不假设插件会自动处理。历史发布版本只读；当前版本修改先写草稿、记录新修订并进行影响预览，不直接覆盖旧快照。

## 接口与状态

以下为 `/api/new-design` 下的目标接口；页面不能绕过它们直接调用原型本地存储。画布与列表调用同一草稿修订命令。

| 对象 | 读取与写入接口 | 返回的关键身份 |
| --- | --- | --- |
| 元卡片 | `GET/POST /meta-cards`、`GET/PATCH /meta-cards/:id`、`POST /meta-cards/:id/publish`、`GET /meta-cards/:id/versions`、`POST /meta-cards/:id/copies` | `id`、`revision`、`currentVersionId`、版本列表 |
| 卡片模板 | `GET/POST /card-templates`、`GET/PATCH /card-templates/:id`、`POST /card-templates/:id/publish`、`GET /card-templates/:id/versions`、`POST /card-templates/:id/copies` | `id`、`revision`、`currentVersionId`、冻结成员来源 |
| 书籍模板 | 扩展现有 `GET/POST /templates`、`PATCH /templates/:id`、`POST /templates/:id/publish` 和 `GET /templates/:id/versions`，增加完整装配图读取与复制命令 | 原有 `templateVersionId` 加 `assembly` 快照 |
| 书籍根卡 | 开书回执及书籍读取返回 `rootCardId`；读取可复用正式卡片接口，后续编辑使用 `PATCH /books/:bookId/root-card`，同时提交书籍与根卡修订号，原子更新根卡版本及 `books.name/description`；普通卡片更新／归档根卡返回冲突 | `bookId`、`rootCardId`、根卡版本、书籍修订号、所选模板根节点 ID |
| 本书模块实例与槽位 | `POST /books/:bookId/module-instances` 依据书籍模板中的模块引用新增人物等实例；`GET /books/:bookId/template-slots`、`POST /books/:bookId/template-slots/:slotId/fill`；书内增删节点另用带影响预览的命令；绑定后所有卡片编辑仍通过同一有效规格校验 | `moduleRefNodeId`、`moduleInstanceId`、实例 `nodeId`、`slotId`、`cardId?`、`revision`、有效规格版本与哈希 |
| 本书待绑定关系 | `GET /books/:bookId/template-relations` 查看两端及必需／可选状态；两端已填后由作者调用 `POST /books/:bookId/template-relations/:pendingRelationId/confirm` 建立正式关系 | 书内 `edgeId`、来源 `sourceEdgeId`、`moduleInstanceId?`、`required`、`status`、`relationId?`；模块完成状态依据必需关系是否已绑定计算 |
| 模板共享修改 | 当前版本保存前读取引用链影响预览；同步命令按书籍分别确认并携带预览版本及请求键 | 受影响模板版本、书籍、字段／节点／关系差异及每本书的同步结果 |

每次写入带 `expectedRevision` 和请求键，服务器返回新 revision、版本 ID 或明确的冲突／恢复回执。填槽命令提交冻结字段规格所需的值，返回既有卡片结果和槽位绑定结果。开书继续使用现有 `templateVersionId` 入口，不另设第二套创建书籍 API；其审阅卡片若要填充槽位必须显式携带 `nodeId`。公共类型分别表达元卡片、卡片模板、书籍模板装配图和本书待填槽位；旧 `TemplatePayload` 无装配图的历史版本仍按原流程安装。

列表与画布均展示加载、空态、未保存、校验失败、并发冲突和发布成功。保存失败保留用户输入；未知写入结果按原请求键只读核对，不换键重复提交。切换模板或离开页面前提示未保存草稿。新增 AI 可见操作不在本期，因此不触发模型或候选采用。

## 验收场景

- 定义并发布“基础身份”“战力维度”，编排人物模板；刷新后布局、标签、必选性和版本引用不变。移动人物组时两张元卡片相对位置不变，收起后展开恢复。
- 在书籍模板中引用一次人物模板，再放置一张独立元卡片；开书时预建顾玄实例，之后从同一引用新增叶知秋实例。两个人物组各有独立的实例 ID、槽位与内部待绑定关系；删除顾玄实例的一条关系线时，预览并只应用它的影响，不改叶知秋实例或模板定义。
- 先填写书名、篇幅、题材和文风等根卡字段，再选择确切书籍模板版本开书；书籍列表出现新书，书内立即有且仅有一张已填写的书籍根卡，其余元卡片仍是待填槽位。填写人物与战力两张卡后，按预设的“战力归属人物”连线确认正式关系。
- 本书把战力卡的“速度”从可选改为必填：首次填槽和后续普通资料编辑均拒绝空速度；有效规则随书内槽位版本可追溯，不改变共享元卡片版本。
- 将根卡书名从《守影者》改为《夜行录》后，书籍列表与根卡版本同时显示《夜行录》；用普通卡片接口改名或归档根卡时拒绝，旧卡片版本仍可查。
- 人物与战力两张卡已填、必需的“战力归属人物”尚未确认时，页面显示关系待确认，人物模块不算完成，人物战力计算不能采用这张未归属的卡；确认后才解除阻断。
- 另存为版本时其他版本与书籍不变；修改当前共享版本时显示所有引用方的影响清单，只有逐本确认同步的书籍获得更新副本，其余继续读取旧快照；历史开书模板仍能创建书籍。
- 画布在桌面与窄屏中可操作；右栏选中元卡片、组、连线时显示对应资料，键盘焦点、按钮禁用态和删除影响提示可见。
