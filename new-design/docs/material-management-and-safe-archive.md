# 资料管理、智能视图与安全归档

## 用户工作流

“本书资料”提供内容类型、标签、分组目录和智能视图四种查看方式；“创作资源”对公共资源空间复用同一管理器。两者使用相同操作，但服务端必须精确校验 `bookId` 或 `spaceId`，禁止跨书、跨公共空间建立组织引用。

- 标签有稳定 `tag_key`，显示名称、别名、颜色和元数据按不可变版本追加。改名不改变身份。
- 分组是一棵固定目录树，每个分组最多一个父项；资料可以同时加入多个分组。归档分组时，可把子分组提升一级或归档整棵子树。
- 智能视图只保存筛选、排序、分组、列和布局，不保存查询结果。每次打开都从 PostgreSQL 读取当前资料。
- 归档标签、分组或智能视图只改变组织方式，不删除资料；资料归档也只追加版本和事件，不执行物理删除或级联删除。

> 🏠 **白话比喻**：标签像档案袋上的彩色贴纸，分组像文件柜目录，同一份原稿可以同时出现在“人物”和“第一卷重点”两个目录里，但原稿只有一份。对应到系统：标签与分组只保存引用，正文和资料值仍由 `cards/card_versions` 唯一持有。

> 🧠 **速记方法**：**贴签不复印，入组不搬家，视图不存结果**。

## 安全查询边界

智能视图使用带类型的筛选 AST。服务端只接受白名单字段和运算符：内容类型、标签、资料状态、正典／候选状态、章卷、故事时间、关系／关联是否存在、来源和更新时间。组合最多 4 层、40 个条件，排序最多 3 项，单次最多返回 100 条。

AST 由服务端编译为固定 SQL 片段和参数值；不接受 SQL、JSONPath、Cypher、字段路径或客户端函数。六个基础书籍视图通过 `book_view_configs.smart_view_id` 连接统一智能视图，旧保存入口会同步产生新的智能视图版本。

> 🏠 **白话比喻**：筛选器像图书馆检索台，只能选择馆方提供的“作者、分类、年份”等按钮，不能把一张自写指令塞给管理员执行。对应到系统：客户端只交结构化条件，SQL 列名和运算方式全部由服务端白名单决定。

> 🧠 **速记方法**：**字段白名单、值参数化、层数有上限、结果不落库**。

## 归档影响预览

资料归档必须先调用影响预览。服务端冻结以下证据并生成 SHA-256：026 依赖下游、035 表单挂载和独立关系，以及创作表单主项、正式事实、故事时间、章节位置、正文锚点、状态、认知、规划、研究采用、素材、标签和分组引用。

预览返回 15 分钟有效的确认令牌；数据库只保存令牌哈希。确认时再次锁定资料，校验预期修订、令牌、预览哈希并重新计算全部引用。任何变化都会返回 409，不能拿旧预览归档新状态。创作表单主项和有效卷章规划属于阻塞项；其他引用需要明确接受风险或进入待重算。

归档／恢复会新增 `card_versions`，登记 `card_archive_events`，并把旧、新资料版本交给 026 失效传播。依赖重算继续走 030 Outbox；资料管理模块不直接写 AGE 或 pgvector。

> 🏠 **白话比喻**：归档像把档案移入库房。管理员先打印一张“谁还借着这份档案”的清单并盖时效章；真正入库前再核对一次，清单变了就必须重打。对应到系统：预览哈希、短期令牌和修订号共同防止陈旧确认。

> 🧠 **速记方法**：**先盘点、再锁版、复算一致、只软归档**。

## 跨机器同步

`036_material_management_smart_views.sql`、类型合同、API、UI 和本文档随 Git 同步。作者建立的标签、分组成员、智能视图版本、归档预览／事件及资料内容属于 PostgreSQL 业务数据；换机器必须使用 031 的逻辑备份／恢复，并同时搬运受管附件和 manifest。只拉代码只能得到空结构，不能得到另一台机器上的组织结果。

完整恢复后，标签／分组成员和智能视图定义可由 026 资源登记回源；智能视图结果、AGE 投影和 pgvector 索引均为可重建数据，不进入迁移包的业务正本。

## API 摘要

- `GET /api/new-design/material-management/workspace`：读取标签、分组、智能视图和成员摘要。
- `POST /api/new-design/material-management/query`：按临时条件或已保存视图查询当前资料。
- `/material-management/tags`、`/groups`、`/views`：创建、修订、归档、复制和批量成员操作；写请求都带幂等键和预期修订。
- `/material-management/cards/:id/archive-preview`：冻结影响与确认凭据。
- `/material-management/cards/:id/archive`、`/restore`：软归档和恢复。

所有接口必须且只能通过查询参数指定一个 `bookId` 或 `spaceId`。当前未接入账户权限系统，记录仍保留 `created_by/updated_by/visibility`，为后续权限层提供稳定审计字段。
