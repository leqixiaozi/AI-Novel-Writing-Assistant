# 书籍概览与规划中心

## 目标与边界

书籍概览回答“这本书走向是什么、准备到哪里、下一步缺什么”；规划中心回答“故事、卷、章和场景怎样安排，以及哪一版可交给后续创作”。作者面对的是树形目录和业务表单，底层仍使用稳定资料身份、不可变版本与唯一采用指针。

本阶段只管理规划，不生成章节正文，也不确认事实或结算人物、关系、道具和伏笔状态。表单里的“预期变化”是计划，正式变化仍由正文证据与结算流程确认。

> 🏠 **白话比喻**：概览像项目大厅的进度看板，规划中心像导演桌上的分镜夹。分镜里写“角色受伤”只是拍摄安排，镜头完成并确认后才算剧情事实。对应到系统：计划版本不能替代正文、事实或状态账本。

> 🧠 **速记方法**：**先看缺口，再分层规划；候选可多份，采用只一份；计划写意图，正文才落账。**

## 页面结构

### 创作概览

`/new-design/books/:bookId/overview` 展示：

- 当前采用的故事方向；没有采用版本时提供“开始规划”。
- 卷规划、章节规划、已写章节、待确认事实、待结算变化、质量／连续性问题、待复核／重算项。
- 按本书已发布内容类型及其必填字段计算的资料准备情况，不维护第二份硬编码类型清单。
- 上下文规则与最近装配预览状态。
- 最近真实 AI 任务；没有任务时显示空状态，不制造运行记录。

每个指标带来源名称、来源页面和更新时间。数据库没有可信记录时使用 `null` 或“暂无”，不推算虚假百分比。

### 故事规划

`/new-design/books/:bookId/planning` 使用故事 → 卷 → 章节 → 场景树。事件安排、人物弧和伏笔安排是同一计划版本的筛选视图，不创建平行正本。

计划表单包含：

- 目标、故事时间、后续执行方式。
- 视角人物、地点、参与者、事件、道具和组织／势力。
- 必须发生、必须保留、禁止越界。
- 预期变化、人物弧、伏笔动作和补充说明。

卷、章、场景必须先选择已采用的上级计划，并绑定本书同类型资料。第一条主路径是建立故事总览与卷计划，再为前三章分别建立并采用章节计划。执行方式只有“人工创作、AI 辅助、自动执行意图”，不会在此页面写正文。

## 版本、采用与并发

- 每次保存追加候选版本，不覆盖采用版本。
- 人工稿与 AI 结果都先进入候选；AI 能力未配置时显示真实不可用状态。
- 作者可以比较候选、采用、标记不采用，或重新采用历史版本完成回退。
- 父级采用其他版本后，依赖旧父版的子计划与相关派生项进入待复核，历史保留。
- 修改、驳回、采用、归档和恢复都校验预期修订并使用幂等键；`409` 返回服务器修订，客户端保留本地填写。
- 规划对象只归档，不做物理删除；恢复子级前必须先恢复上级。

## 精确引用与 F3 读取合同

计划版本引用的每份人物、地点、事件、伏笔、道具和势力资料都保存稳定 `cardId` 与精确 `cardVersionId`。显示名称只是读取投影，不是关联依据。

F3 使用 `GET /books/:id/chapters/:chapterCardId/adopted-plan` 读取章节唯一采用计划。响应包含：

- `planningObjectId` 与 `planningObjectRevision`。
- `chapterCardId` 与当前章节资料版本。
- `planningVersionId`、版本号与内容哈希。
- 执行方式、结构化计划内容和精确资料引用。
- `basedOnVolumePlanVersionId`，用于证明章节计划依赖哪一版卷计划。

缺少采用计划、父级卷依据或活动章节时返回明确错误。F3 不应读取当前编辑候选，也不能按标题猜测引用。

## API

- `GET /books/:id/overview`：书籍概览聚合。
- `GET /books/:id/planning-center`：规划树、资料选择项与 AI 能力状态。
- `POST /books/:id/planning-objects`：建立规划和首个候选。
- `POST /planning-objects/:id/versions`：追加候选版本。
- `POST /planning-objects/:id/adopt`：采用或回退到指定版本。
- `POST /planning-objects/:id/reject`：标记候选不采用。
- `POST /planning-objects/:id/archive`、`/restore`：安全归档与恢复。
- `GET /books/:id/chapters/:chapterCardId/adopted-plan`：F3 稳定读取合同。

## 跨机器同步

`038_book_overview_planning_center.sql`、运行包规格和本文随 Git 同步，保证各开发机器使用同一结构和接口约定。作者建立的规划、候选版本、采用记录、精确资料引用和操作回执属于 PostgreSQL 业务数据，必须通过逻辑备份／恢复同步；只拉 Git 不会带回这些运行数据，也不能复制运行中的数据库目录代替备份。
