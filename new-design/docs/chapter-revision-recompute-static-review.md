# 旧章换稿与选择性重算静态审查

## 审查范围

本轮按开发策略只做静态审查，没有执行测试、构建、服务、浏览器、真实 PostgreSQL 迁移、AGE、pgvector、AI 或后台运行器。

> 🏠 **白话比喻**：静态审查像施工前核对图纸、材料清单和消防通道，能发现编号断档、门开错方向和流程缺口，但不能代替通水通电后的验收。对应到本轮：类型、SQL 状态机、路由、界面投影和文档可检查；真实事务、扩展和并发行为仍需发布前动态验收。

> 🧠 **速记方法**：**图纸先闭环，通电后验收。** 图纸对应类型／SQL／接口／状态投影，通电对应真实数据库、worker 和浏览器。

## 静态结论

- 041 迁移连续接在 040 后，迁移注册、运行包 manifest、期望数量和规格范围统一为 001—041。
- 冻结预览允许保留多份历史，但同一采用会话只允许一个 `ready` 预览；来源变化后可失效并重新生成。
- 预览执行前校验文档修订、当前采用正文和依赖 generation；不一致时只使预览过期，不移动采用指针。
- 正文指针切换、旧检查点／旧结算失效、统一依赖失效和 F4 会话回到变化确认在同一事务中执行。
- 事实按精确证据撤销，共享来源不会误删；人工纠正写保护标记；后续正文只写复核标记。
- 依赖重算继续使用 026 失效请求和 030 后台作业；带作业 ID 的步骤复用既有重试／取消接口。
- 章节工作台、规划中心和书籍概览均显示执行中、失败恢复和后续正文复核状态。
- F6／F7 读取合同只暴露安全稳定检查点、当前影响和未稳定执行。
- 服务端和客户端 `tsc --noEmit` 静态类型检查通过。

## 发布前动态验收债务

- 在真实 PostgreSQL 17 上顺序执行 001—041，覆盖预览重生成、并发修订冲突、事务回滚和约束／触发器状态转换。
- 验证 AGE 墓碑／重建、pgvector 失效／重建与 030 作业的领取、重试、死信、取消和恢复。
- 覆盖共享事实、多证据归零、人工保护、后续正文复核、新 F4 结算和稳定检查点闭环。
- 进行多主题、键盘、窄屏和浏览器视觉回归，验证焦点、筛选、二次确认和长正文对比。
- 完成逻辑备份／恢复与跨机器同步演练，确认 041 业务数据和附件清单一致。
