# 统一业务表单外壳

## 目标

作者在“创作概览、人物、世界设定、剧情与事件、章节、线索与伏笔、本书资料”中看到的是业务表单，不需要理解底层卡片、JSONB 或关系边。所有入口读取并修改同一份书内正式资料，不建立页面私有副本。

> 🏠 **白话比喻**：同一份户籍档案可以从姓名索引、住址索引或家庭索引打开，但工作人员最终填写的仍是同一份档案。对应到系统：书籍任务入口只是不同索引，保存目标始终是同一张 `cards` 记录及其 `card_versions` 修订。

> 🧠 **速记方法**：**入口可不同，表单只一套；资料是正本，页面不抄表。**

## 表单解析顺序

页面必须按以下顺序解析填写规格，并展示实际命中的来源与版本：

1. 本书已经安装或复制的已发布创作表单版本。
2. 当前已发布内容类型版本中的字段、分组、控件、选项和规则。
3. 系统内置的成熟业务分组顺序。
4. 保证字段仍可读写的通用安全布局。

解析结果只存在于页面内存，不能作为第二份配置持久化。每次保存会在 `card_versions` 记录实际 `type_version_id`、可选 `form_version_id` 和 `form_resolution_kind`，因此可以回答“当时用哪一版规格填写”，又不会复制渲染后的表单。

人物默认使用“基本信息、外在表现、人物内核、当前状态、关联资料、补充信息”；事件默认使用“基本信息、故事时间、参与人物、发生地点、涉及道具、前因后果、局部目标”。世界观、地点、组织／势力、道具、章节、线索与伏笔使用各自业务分组。字段值不在前端映射中硬编码，标签、说明、必填、输入类型、选项、显示条件、AI 建议能力和状态跟踪能力均来自已发布字段规格。

## 路由与作用域

| 路由 | 默认资料范围 |
| --- | --- |
| `/new-design/books/:bookId/forms` | 作品约定、故事构思、主题与创作策略 |
| `/new-design/books/:bookId/views/characters` | 人物 |
| `/new-design/books/:bookId/views/world` | 世界观、规则、地点、组织／势力、道具等 |
| `/new-design/books/:bookId/views/events` | 事件、目标、冲突、剧情线、节拍和弧线 |
| `/new-design/books/:bookId/views/chapters` | 卷、章节和场景规划 |
| `/new-design/books/:bookId/views/clues` | 线索、伏笔、悬念与秘密 |
| `/new-design/books/:bookId/cards` | 本书全部已发布内容类型 |

上述深链保持不变，只把展示层统一到 `BusinessFormWorkspace`。`/fields` 仍是本书内容规格设置，不混入普通创作填写。

## 加载、编辑和保存合同

- 首屏并行读取本书正式资料与本书已发布创作表单，再读取当前内容类型的不可变版本。
- 空白新建、模板生成和 AI 提案只提供不同初始值；进入正式资料后都由同一个组件、路由和保存接口处理。
- 列表只展示当前书籍、当前内容类型且状态为使用中的正式资料，不生成演示占位数据。
- 新建调用 `POST /api/new-design/cards`，修改调用 `PATCH /api/new-design/cards/:id`；两者都提交标题、动态字段值和实际表单解析来源。
- 保存仍由服务端按当前已发布内容规格验证，并新增不可变 `card_versions` 快照。
- 修改记录只读展示创建／修改来源、内容规格版本、创作表单版本和字段快照，不提供伪恢复按钮。
- 修订号冲突返回 `409` 后保留本地填写；作者可主动读取服务器最新修订、逐字段比较，再明确采用服务器内容。页面不得静默覆盖任何一边。
- 已有关系、故事时间、叙事位置和正文锚点只显示摘要；U2 不提供关系选择、新建、挂载或局部值编辑。

U3 在同一外壳加入“＋ 添加信息”。作者先选“本书所有同类资料”或“仅当前资料”，查看影响后确认；字段来源和范围可展开查看。类型字段与局部字段在页面连续显示，但保存仍各归其位，详细合同见 [field-scope-and-versioning.md](./field-scope-and-versioning.md)。当前关联仍为只读预留，不提前实现 U4。

## 状态口径

页面显式覆盖：加载中、栏目无内容类型、没有正式资料、没有已发布规格、字段校验失败、保存中、保存成功、修订冲突、普通 API 失败和私有 PostgreSQL 不可用。错误出现时保留尚未保存的输入；重试读取不会伪造成功状态。

## 跨机器同步

`033_business_form_provenance.sql`、`034_scoped_field_definitions.sql`、字段合同、表单解析规则和本文档随 Git 同步。作者填写的字段扩展、`cards`、`card_versions`、局部值和附件不进入 Git，仍必须使用 PostgreSQL 逻辑备份、受管附件和 manifest 一起迁移。只复制仓库相当于搬走空白表格，不能搬走已填写内容。
