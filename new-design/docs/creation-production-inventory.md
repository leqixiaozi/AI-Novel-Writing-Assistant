# 统一开书空白 AI 与正式生产结构盘点

日期：2026-09-16。接续章节结果确认切片后，按讨论任务派发实施 P1-A／P1-B 必要补缺。仅新设计；本页是前置源码盘点，不是测试或完成声明。

## 保留的正本

七种开书起点、研究来源与模板版本继续进入同一创建会话及统一审阅表单。保留已有分阶段执行器、一键／分步暂停策略、字段来源、普通资料安装与创建完成指针；不重做已交付部分、不借旧目录模型或密钥。

> 白话比喻：同一张新书设计桌，编辑可一次交齐草稿，也可每交一份停下来讨论；不另摆一张桌保存另一套稿件。对应到系统：一键与分步共用会话、阶段、候选和明确采用，只有暂停策略不同。

> 速记方法：一桌两节奏，候选先审阅，确认才建书。

## 真实规划口径

讨论任务已明确：复用迁移 022 的全书 → 卷 → 章节 → 场景四层，不新增事件规划层或改消费者。事件是独立资料，通过 `planning_version_references.reference_role='event'` 精确引用关联规划，可跨多章共享同一事件正本。事件不等于场景，不把事件文本塞入规划字段代替正式引用，不复制事件事实。AI 输出分别表达资料、规划对象、关系及引用候选；安装时映射临时审阅身份到真实本书资料和版本。

> 白话比喻：一次婚礼可在准备、仪式、宴席多段叙述中出现，但这些叙述不是多场不同婚礼。对应到系统：不同章节或场景规划精确引用同一事件资料正本，而不复制事件对象。

> 速记方法：规划四层管组织，事件引用可跨章；场景不是事件层。

## 源码确认的必要缺口

| 作者动作 | 已有模块 | 本轮必要补缺 |
| --- | --- | --- |
| 选中空白资料请 AI 填写 | `client/bookCreation/ReviewForm`、通用资料空白 AI | 单独准备必填／剩余／全部建议，冻结实际模板字段与树范围；不以必填完整作为生成门禁，勾选建议入原表单保护人工 |
| 一键或分步连续准备 | `application/creationDirector`、`database/creationDirector` | 使用自有受控资产和结构化合同，精确审阅身份，不按同名猜目标；保留各阶段输出，可从原批次恢复 |
| 关系与规划正式生效 | `bookCreationStore`、`templateStore`、正式关系与规划账本 | 草稿中文编辑及明确采用；原子确认安装真实关系版本／规划版本／事件精确引用，不把描述卡冒充正式合同 |
| 断线后恢复创建会话或保存 | 原会话查询，部分写入仅修订 | 创建起点原键查询，保存／正式审阅／确认开书回执；未知先只读核对，空查询不当未执行证明 |
| 返回、切方式或人工接管 | 既有导演控制与迟到保护 | 保存原草稿、显式控制回执、拒绝迟到覆盖；一键和逐步不分叉另一套数据 |
| 保存后读取失败 | 安装事务后再读取完整会话 | 同事务形成成功回执，成功与读取失败分别显示；保留草稿与正向成功证明，只续读不重做 |

## 实施与验证纪律

完整功能前后端、落库、界面与文档连续编码后才集中测试。真实 PostgreSQL／HTTP、模型模拟和实际模型、界面体验分别记录；独立模型配置不可用不改作者路线、不伪造生成。运行记录只读跳原来源页，恢复动作在开书表单旁明确说明失败阶段、保留结果和后续按钮。

必要最小有效规格、能力、对象选择与发布恢复入口可以补齐，但不扩新产品、全书正文生产、P4／P5。章节阶段既有证据不能替代本轮验收。SQL 和文档进入 Git，已有作者数据不删除，镜像保持可重建 Dockerfile 方式。
