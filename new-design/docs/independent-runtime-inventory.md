# 新设计独立运行依赖盘点

日期：2026-09-16。只读盘点，不修改旧目录，不将当前过渡接线视为独立运行成功。

## 用户边界与闭环缺口

用户要求新功能不修改、不依赖旧目录；旧实现只读参考。根提示词注册／网关写入例外申请撤回，不再等待该授权。

无法闭环的动作：不启动旧应用，仅用新设计启动并完成资料 AI／开书准备。必要缺口是新设计没有可独立监听的服务／前端入口，也没有自有受控提示词注册和模型执行适配。

参考旧系统的行为仅限注册资产、结构化输出、配置与脱敏；最小实现必须在新设计建立明确 id／version／taskType／contextPolicy／outputSchema 的受控资产、统一执行入口、模型配置与独立启动／构建。不能只复制提示词文件而继续注入旧网关。

> 白话比喻：新店借旧店收银，即使货架是自己的，也无法单独营业。对应到系统：独立目录不等于独立运行，启动、执行与配置也必须自有。

> 速记方法：目录自有只是起点；入口、注册、模型、合同都自有才闭环。

## 验收与推进

提示词分类树最高优先；其运行闭环所需自有基础先补齐。独立入口验收需启动／构建不加载旧业务目录，完成资料生成 → 编辑／采用草稿 → PostgreSQL 保存 → 下游读取，并验证失败定位／核对结果／重试。导演正式关系与规划另由明确提案合同及现有事务采用，不借文字描述猜测。
