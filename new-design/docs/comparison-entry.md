## 路由与隔离

- `/api/new-design` 及子路径优先转发 5301；其余 `/api` 路径转发 3000。匹配有路径边界，避免相似前缀误路由。
- `/new-design` 及子路径转发内部新版前端 5274，其 Vite base 为 `/new-design/`，模块、依赖及热更新请求均带此前缀。
- 其他页面及资源转发内部旧版前端 5275，旧版资源仍使用根路径。
- 两个 Vite 实例分别使用各自进程、工作目录和配置。PostCSS/Tailwind 会使用进程工作目录发现配置，不能在新版工作目录内用同一进程启动旧前端，否则旧版主题类可能编译失败。网关不导入旧业务模块，新版构建不包含旧源码。网关仅转发 HTTP 和 WebSocket，不读取或复制模型凭据。
- 新旧 HMR 分别使用 `/new-design/__new_hmr` 与 `/__legacy_hmr`，浏览器通过 5273 连接。两套前端独立提供 SPA 深链回退。

5273、5274、5275 必须可用；入口与前端仅监听回环地址，5174 不使用。启动失败关闭本启动器创建的前端，不停止外部 API 或数据库。退出入口会关闭自身前端及连接。

`/new-design` 请求在代理内部补尾斜线，以满足 Vite base 约束，同时保持地址栏原路径及查询参数，避免原首页导航状态改变。

## API 与数据保护

新版 API 5301 使用已有 PostgreSQL；旧版 API 3000 使用原 SQLite。API 未启动时返回明确 502，不借用另一套 API。旧版常规启动流程可能自动初始化数据和恢复后台任务，必须依据当前授权选择启动方式，不能为显示入口擅自执行迁移、seed 或任务恢复。

用户授权的安全对比启动命令：`powershell -NoProfile -File scripts/comparison/start-legacy-api.ps1`。它先检查旧 SQLite 存在及 3000 空闲，再使用原 API 开发启动器；不运行 Prisma 准备脚本。进程内设置 `AI_NOVEL_COMPARISON_STARTUP=1`，旧 `startServer` 跳过迁移、RAG 兼容导入、资源初始化、日志清理和后台恢复，也不挂载内嵌新版路由。`SQLITE_ENABLE_WAL=false` 避免启动时修改旧 SQLite 日志模式。此模式不是只读数据库或完整生产运行模式；页面中的人工操作仍使用原业务 API，依赖后台 worker 的任务不会自动执行。正常启动不设置此开关时行为不变。

对比模式与单独 `npm run dev:client` 均占用 5273，不应同时运行。切换只需停止前端入口进程，保留 API 与数据库；独立构建和发布方式不受此网关影响。
