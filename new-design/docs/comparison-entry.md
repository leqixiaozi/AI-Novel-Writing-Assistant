# 新旧版本同源对比入口

## 系统边界

共同入口仅为并排展示和导航服务。旧版与新设计分别拥有业务 API、AI 执行链和数据库，彼此不调用业务模块或读取对方的业务数据。浏览器进入 `/new-design` 后，新设计的业务请求、模型配置和运行状态应只来自新版服务；进入旧版页面时使用旧版服务。共享外壳可以复用布局组件，但不能把旧版的业务状态当成新版状态。

复刻以旧版页面和可见功能为参考，新版内部按卡片模型实现，不要求与旧版表结构一一对应。旧版源码保持只读；对标时允许在旧版界面模拟操作以收集证据。

5273 当前将旧版页面和 `/new-design` 子页面都交给旧版前端 5275 的共同外壳，顶部保留原“AI 实况”、模型选择与温度控件，侧栏同时展示旧版和新版菜单。新版业务仍由独立的 new-design 包提供，`/api/new-design` 仍转发新版 API 5301；其他 API 转发旧版 API 3000。独立新版前端 5274 仍可直接用于开发，但不承担 5273 的页面展示。旧版 API 3000 需要运行，旧顶部的 AI 控件才能读取其配置和实况。

## 路由与隔离

- `/api/new-design` 及子路径优先转发 5301；其余 `/api` 路径转发 3000。匹配有路径边界，避免相似前缀误路由。
- `/new-design` 及子路径与其他页面、资源都转发内部旧版前端 5275；旧版 React Router 的集成路由加载独立 new-design 包，旧顶部和共同侧栏保留。
- 两个 Vite 实例分别使用各自进程、工作目录和配置；5274 为可直接访问的独立新版开发前端。PostCSS/Tailwind 会使用进程工作目录发现配置，不能在新版工作目录内用同一进程启动旧前端。网关仅转发 HTTP 和 WebSocket，不读取或复制模型凭据。
- 共同页面的 HMR 浏览器直连回环地址 `127.0.0.1:5275/__legacy_hmr`；独立新版前端直连 `127.0.0.1:5274/__new_hmr`。页面与 API 仍从 5273 进入，两端各自提供 SPA 深链回退。HMR 若通过 5273 的 WebSocket 代理，空闲连接可能约每 30 秒断开，Vite 重连后触发整页刷新；排查周期性刷新时先核对浏览器 Vite 日志和 HMR 连接目标。

5273、5274、5275 必须可用；入口与前端仅监听回环地址，5174 不使用。启动失败关闭本启动器创建的前端，不停止外部 API 或数据库。退出入口会关闭自身前端及连接。

`/new-design` 与其子路径经旧版外壳集成路由读取新版业务，页面深链保持原地址和查询参数。

## API 与数据保护

新版 API 5301 使用已有 PostgreSQL；旧版 API 3000 使用原 SQLite。API 未启动时返回明确 502，不借用另一套 API。旧版常规启动流程可能自动初始化数据和恢复后台任务，必须依据当前授权选择启动方式，不能为显示入口擅自执行迁移、seed 或任务恢复。

用户授权的安全对比启动命令：`powershell -NoProfile -File scripts/comparison/start-legacy-api.ps1`。它先检查旧 SQLite 存在及 3000 空闲，再使用原 API 开发启动器；不运行 Prisma 准备脚本。进程内设置 `AI_NOVEL_COMPARISON_STARTUP=1`，旧 `startServer` 跳过迁移、RAG 兼容导入、资源初始化、日志清理和后台恢复，也不挂载内嵌新版路由。`SQLITE_ENABLE_WAL=false` 避免启动时修改旧 SQLite 日志模式。此模式不是只读数据库或完整生产运行模式；页面中的人工操作仍使用原业务 API，依赖后台 worker 的任务不会自动执行。正常启动不设置此开关时行为不变。

对比模式与单独 `npm run dev:client` 均占用 5273，不应同时运行。切换只需停止前端入口进程，保留 API 与数据库；独立构建和发布方式不受此网关影响。
