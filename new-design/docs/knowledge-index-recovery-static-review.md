# 知识索引原准备恢复：静态收口记录

更新日期：2026-09-17。仅属于原授权知识索引／失败恢复收口，不启动[下一批功能计划](next-batch-legacy-reference-plan.md)。本记录描述源码审阅，不是动态测试或数据库迁移证据。

## 根因与最小改造

初始模型准备事务实际回滚，但响应丢失时，原分块可能仍待处理、检索原凭证可能查询为空；二者都没有已领取租约可走超期结束。原界面保持未知锁是安全的，却没有显式完成原准备的入口。此外中央两个索引构建 API 把实际 `KnowledgeGenerationReceipt` 缩成一般分代类型，遗漏原 key／fullhash 回执合同。

中央构建与原构建查询已同步实际回执类型。恢复复用原 execute／semantic POST 和原数据库来源，不加新系统、服务、业务库或伪终态。源页保留原凭证、完整输入与身份，先只读核对，再经明确确认恢复；按钮说明可能首次领取并调用，不冒充只读操作。

> 白话比喻：看不到快递单不能就另寄一份；要到同一个柜台核对原单，确实从未收件才处理这张原单。对应到系统：GET 阴性不提供重发许可，服务器在同 key／fullhash／锁下判定；已有领取只返回原结果。

> 速记方法：原单不换，原输入不变；已有只读，确无才领。

## 源码核对点

- `common/knowledgeIndex`：原分块身份包含书籍、请求、分块、来源快照／原版本／hash、规格版本／hash、模型连接版本／hash及完整正文输入 hash；语义查询保留原问题、数量和原选索引分代身份，不复制正文正本。
- `database/knowledgeIndex/execution`：同锁检查身份与已有领取；原 key 相同的既有分支仅返回原结果。没有领取 key 还必须核实真实尝试行、attempt_count 与 pending 状态，不能仅据 key 为空插入“第一次尝试”。
- `database/knowledgeIndex/retrieval`：原 key 对应 run 先按完整输入 hash 核对并返回；确无记录时核对原选分代／规格／模型，不能用当前新分代替换旧输入。
- `database/knowledgeIndex/repository`：只有成功持锁并核实原准备不存在后的标记，加上未开始 COMMIT 和已确认回滚，才能证明未进入原准备；BEGIN／锁／原记录查询失败或后续局部回滚仍未知。
- `application/knowledgeIndex`：只有本次新领取者继续发送；已领取分支不进入传输。原回复、本地执行证据、原回复入库与超期操作沿原来源核对，不因恢复而重生向量。
- `client/knowledgeIndex`：只读核对、显式原准备恢复、原回复入库及超期结束分开；恢复失败不清原 key，完成／结束动作仍保留原调用输入；回执身份和 fullhash 不符不覆盖、不清凭证。
- `http/knowledgeIndex`：完整原输入严格校验并转发；GET 错误不携带未写入结论。入口前校验、初始准备可信证明与外部／多事务结果未知分别处理。
- `client/api`：构建与原构建查询返回 `KnowledgeGenerationReceipt`，其他输入输出沿公共实际合同，不另建 API 事实。

## 残余风险与真实阻塞

旧凭证缺少身份、旧冻结记录不含必要指针、损坏存储、已失效原件／正文／索引分代、已有非受控尝试但缺少领取凭证，均不能自动补成当前来源、清键、换键或虚构取消／成功。此类情形保留真实阻塞；运行维护链接只导航，不代表已经实现读取或修复浏览器原凭据。可读原请求由知识来源页的实际只读核对入口处理。

新恢复入口解决当前精确凭据下“无领取／无租约”的安全衔接，不宣称所有历史坏凭据或全站失败都可自动恢复。真实模型配置、传输回复、数据库提交与来源采用分别验证；未知用量不按零。

## 统一验证边界

本轮相关用例已编写，静态审阅不运行它们。待全部原授权编码及静态审阅完成后，进入同一批统一验证：类型／构建、单位与模拟事务负例、受控独立 PG／HTTP、实际模型／输出／用量及必要界面验收。重点验证同 key 并发只有一个新领取者、已有尝试无再调用、锁／查询失败无未写入假证明、跨书／hash冲突、原分代失效、未知响应与原回复保留。未配置真实模型不得用模拟结果冒充真实通过；不得对用户开发数据库盲跑重建型集成用例。
