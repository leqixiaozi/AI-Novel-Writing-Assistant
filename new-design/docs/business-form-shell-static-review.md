# U2 统一业务表单外壳静态审查

审查日期：2026-09-16

## 已完成的静态检查

- 客户入口检查：七个书籍业务入口均解析到统一 `BusinessFormWorkspace`，原深链未改变。
- 数据边界检查：读取限定为本书空间和使用中正式资料；保存复用 `cards` / `card_versions`，未增加页面私有内容副本。
- 表单来源检查：按本书已发布表单、已发布内容规格、系统默认、通用布局依次解析；已发布表单使用不可变版本定义判断适用类型。
- 并发检查：客户端保留 HTTP 状态，`409` 进入显式读取、比较和采用流程，保存按钮在冲突未解决时禁用。
- 历史检查：修改记录只读，不提供无法兑现的恢复操作；显示内容规格和实际创作表单版本。
- 功能边界检查：关系区只读；未实现 U3 添加信息、U4 关系编辑、U5 智能视图／数据管理和三章生产闭环。
- 可访问性检查：输入有可见标签，必填与错误有文本反馈，异步消息使用 `aria-live`，对话框和关闭按钮有可读名称，移动布局不依赖横向滚动。
- 样式检查：复用主题变量、现有按钮／控件／消息样式；内容层保持扁平，仅在表单控件、分隔、冲突和浮层使用边界。
- TypeScript 静态检查：`pnpm exec tsc -p new-design/tsconfig.server.json --noEmit` 与 `pnpm exec tsc -p new-design/tsconfig.client.json --noEmit` 通过。

## 本批明确未执行

## Release Gate

进入 `beta` 或发布前仍需人工完成：

1. 在四套主题及明暗模式检查桌面和窄屏的真实布局、焦点顺序、长文本与字段错误。
2. 在真实 PostgreSQL 执行 001—033，确认新旧 `card_versions` 的来源字段和外键兼容。
3. 依次验证空白、模板和 AI 来源资料共用同一编辑器，AI 部分成功／失败后仍可手填。
4. 双窗口制造修订冲突，核对本地保留、最新修订读取、逐字段比较和采用行为。
5. 验证本书安装表单优先于内容规格布局，并确认历史记录显示实际表单版本。
6. 完成逻辑备份、附件与 manifest 的跨机器恢复演练。
