# 作者界面中文与类型化输入边界

## 决策与维护规则

作者编辑的是小说内容，不负责输入 JSON、UUID 或内部英文键。动态业务字段沿用当前已发布内容规格与 `DynamicForm`；内部稳定标识和数据库正本不因中文显示改变。

> 白话理解：作者看的是商品名称，不需要记住收银系统里的条码。中文名称对应显示，稳定键对应内部识别，两者不能混用。

> 速记方法：显示用名称，保存用标识，编辑看已发布规格。未匹配内容保留待复核，不猜类型、不偷偷丢字段。

系统固定运行状态采用受控中文标签，只影响显示，不成为可修改的业务字典，不参与 AI 路由。任务名称优先读取已发布任务合同；未取得名称时使用“创作任务”，不把内部任务键直接展示给作者。

## 当前切片：研究提案与普通服务提示

- 参考包的书内提案编辑共用 `researchAdoption/AdoptionItemEditor`；本书发布类型优先，公共发布类型只按现有采用合同兜底。字段取精确发布指针，不读未确认草稿定义。
- 姓名、文本、数值、布尔、选项及字典树直接复用通用表单。不存在已发布类型时阻止选择采用，允许忽略并返回本书设置。
- 不属于当前表单的来源字段继续保留，提示数量并阻止界面采用；需要先调整规格，而不是擅自删除或推断新字段。
- 请求失败不重置当前填写；字段错误映射到表单。切换书籍时清除旧列表，并忽略旧请求的迟到响应。
- 普通页面的 5xx 提示引导重试与运行维护；原始错误仍留在 `ApiError.technicalDetail`，不把 Docker 构建和数据库堆栈散布在普通界面。4xx 保留具体校验／冲突指导。
- 创作概览最近任务读取正式合同名称与受控中文状态，不使用技术键作为作者标题。
- 不新增 SQL 或业务事实表。本切片不执行数据库恢复、清空或备份。
