# 新设计受控提示词与输出合同

## 边界与原因

新设计运行不得导入旧业务目录、旧提示词注册或旧模型网关。系统任务资产归属 `src/server/ai/prompts/`，由该目录 facade 编译；作者可复用提示词组件仍使用提示词管理中的组件资料。分类顺序不会改变执行顺序，组件正文不会取得系统合同权限。

> 🏠 白话比喻：系统任务合同像工厂的检验标准，作者组件像可更换的配料。换配料不等于可以绕过出厂检查。对应到本模块：注册资产控制任务和结构，作者内容与外部参考只能作为上下文输入。

> 🧠 速记方法：先注册，后编译，再生成，必校验。任务资产先固定身份和输出结构，再组装本次输入；模型输出通过校验才能进入现有候选流程。

## 资产与调用入口

`preparePrompt(taskType, input)` 返回资产标识、版本、中文名称、上下文策略、生成参数、标准 JSON Schema、system/user 消息和 `parseOutput`。`listPromptAssets()` 仅提供注册元数据，不返回实际任务输入或正文。受控任务为：

| 任务 | 结果包裹 | 输出边界 |
| --- | --- | --- |
| directions | `{directions:[]}` | 故事方向标识不可重复 |
| initial_content | `{cards:[]}` | 类型和字段来自本次规格，覆盖指定类型 |
| form_assist | `{suggestions:{}}` | 仅本次字段白名单，允许显式合成字段 |
| market_analysis | MarketAnalysisResult | 不引用未采集平台，不编造市场统计 |
| book_analysis | BookAnalysisResult | 分析维度完整，候选类型/字段/证据受计划约束 |
| planning_candidate | PlanningCandidateOutput | 层级来自既有 story/volume/chapter/scene 合同，资料引用只来自输入 |
| chapter_settlement | `{items:[],notes:[]}` | 真实本章正文、正式字段、已知前值及字典范围；仅提案，不直接确认或结算 |

本模块不执行 HTTP 模型请求、不读数据库、不读凭据、不写候选、不采用资料或规划。模型适配层消费编译结果并将输出交给 `parseOutput`；应用层继续使用唯一资料、关系、规划、正文正本及原有事务。

## 输入与校验

固定系统合同包含任务指令及输出 JSON Schema；用户请求、参考正文、当前资料和字段说明只进入 user 消息的 `taskData`。这是一条权限边界，而非声称能完全消灭模型提示词注入；模型仍可能违规，所以落库前需要确定性结构与领域校验。

字段输出按短/长文本、数值、布尔、单/多选和日期构建。选项只允许当前可选 value；字典节点必须先由现有新设计上下文装配器解析为本次允许选项。未知字段、额外顶层字段、错误类型、错误枚举均拒绝，不修剪后伪装成功。JSON Schema 描述结构，Zod 额外检查引用范围、唯一性、数量和证据位置。

空开书内容类型及空表单建议字段拒绝；诊断计划合法使用零候选、空内容类型，此时仅允许 `candidates:[]`。研究候选须满足总数、每类型上限、目标字段和证据索引。明确证据必须能在本次文本中定位，位置填 null 时仍需准确摘录；推断必须标明不确定性。

## 失败与恢复

规格缺失先在来源表单维护内容类型或字典，再刷新本次建议；输出违规标记生成失败，由来源页面保留人工草稿并明确重试入口。不得按关键词猜测意图、不得硬编码伪造结果、不得把资料描述当正式关系或把卷章资料卡当正式规划。

资料生成与单项规划候选六任务继续用于组合调试；章节变化提取有独立冻结输入与恢复合同，见 [章节提取来源](chapter-settlement-ai-provenance.md)。导演批量关系／正式规划提案仍需要独立的新设计资产和事务采用合同，不能以这些资产存在宣称该缺口完成。

## 验证边界

定向用例位于 `tests/controlled-prompts.unit.test.cjs`。本子任务只编写用例，遵守完整功能编码后集中测试；类型检查、真实模型、HTTP/PostgreSQL和独立启动证据由完整运行基础阶段统一记录。单测结构校验不等于实际模型质量或独立运行验收。
