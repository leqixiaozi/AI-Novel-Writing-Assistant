# 本章变化提取与恢复边界

## 为什么单独注册任务

章节变化提取读取本章精确正文、正式可结算字段、字典选项和已知前值，只提供审阅候选。它不能借一个名称相似的旧任务合同宣称可用，也不能把时间线、事件因果和并发关系写成状态字段。事件结果表示资料对象字段变化，关系变化表示已有资料关系维度变化。

> 🏠 白话比喻：盘点员依据送货单记录库存变化，不能顺手改配送路线。对应系统：正文证据支持对象状态提案，故事时间与因果依旧归原时间线正本。
>
> 🧠 速记方法：正文证据 → 正式字段 → 已知前值 → 候选审阅 → 明确结算；缺一环不能自动写正式状态。

独立任务 `chapter_settlement` 使用注册资产 `new_design.chapter.settlement_candidates@v1`；模型默认和专属任务覆盖复用同一模型设置版本链。提示词组合调试仍限制其原六个任务，不能把新提取任务放进没有输入编译器的组合菜单。

## 冻结与领域写权

模型调用前，同事务锁定章节会话、正式对象、规格、字典和前值，核对整个目录与作者选择一致。配方版本、任务合同、上下文清单和模型快照引用真实书籍与精确正文版本，输入、消息和输出规格均有哈希。运行使用既有任务、步骤、尝试、事件和用量账本，不另造正式事实库。

> 🏠 白话比喻：收银小票记的是付款当刻的价格和商品，事后价签改变不能偷偷改小票。对应系统：冻结输入和模型路由保留当次事实，导入旧候选时仍须检查当前领域规格及前值是否适用。
>
> 🧠 速记方法：冻结管追溯，现值管落库；历史可读不代表可以越过并发校验。

AI输出采用与人工相同的类型化草稿合同，选择对象与字段必须来自冻结目录，字典只能使用允许节点，数值增减必须与前后值一致，证据必须匹配 UTF-16 正文偏移。候选经过同一后端领域校验进入同一待审清单，人工逐项确认和明确章节结算后才进入原账本和稳定快照。模型没有确认权；作者未配置可用模型时如实不可用，人工补充继续，不借旧密钥或假模板代替。

## 分开恢复模型调用与候选保存

提取请求先领取为单次初始尝试；相同请求只读原回执，不会第二次调用模型。模型输出先保存到既有提取请求，再在领域事务内创建候选。候选保存失败保留原模型输出，来源页“导入已保存结果”只重试导入，不重新生成。规格或前值已经变化时拒绝旧结果导入，不能覆写冻结内容来假装重试成功。

> 🏠 白话比喻：货物已经送到仓库门口，但入库登记失败，只应补登记，不能再订一车同样的货。对应系统：模型结果已保存但候选未入库时，明确恢复旧结果的候选导入，不重发模型。
>
> 🧠 速记方法：已生成补保存，未知先核对；不是所有失败都点重新生成。

候选已入库但运行终止回执保存未确认时，保留确定成功的候选结果，来源页“完成运行回执”只补终止账本，不新增候选或调用模型。只读 GET 不隐式改变任务。运行记录页只展示来源导航，所有恢复动作属于本章结算工作台。

旧规格或前值变化使原结果无法导入时，来源页允许明确“保留旧结果并结束本次提取”。该动作只结束未入库提取的请求与运行记录，保留原模型结果及真实用量，不删除候选或事实。结束后旧结果不可再导入；作者可以人工补充，或明确选择新的正文规格再发起一次新请求。已入库候选、未知模型调用回执不能使用该动作，防止绕过并发保护或掩盖已经成功的候选。

服务进程中断导致原请求没有保存模型结果时，未超过整个冻结模型策略的最迟调用时限，只能读取原回执。数据库时钟确认租约已过期后，来源页允许明确“结束过期未知提取”。该动作保留原冻结和运行记录，原调用是否发送、是否完成和用量依旧未知，不能标成“未调用”或零用量。它结束旧领取，不调用模型、不写事实；旧调用即使晚到，保存结果也因尝试已经结束而拒绝覆盖。作者明确结束后，可以人工补充或手动准备新的提取请求，不会自动新建调用。

模型请求尚未发送、已发送但回执未知、模型已回复但保存未知必须分开表达。没有调用时用量为未知而非伪造零使用；供应商未报告的输入输出用量保留空值。技术重试和备用模型仍受同一已冻结路由和共享预算约束，输出不符合规格不能自动换模型掩盖语义失败。

提取准备只包含数据库写入，尚未调用模型。这一事务如果从未进入 COMMIT，且数据库确认 ROLLBACK 成功，可以确定本次没有保存领取，允许恢复后重新准备；原始数据库故障必须转为安全中文提示，不透出 SQL 或服务堆栈。已经进入 COMMIT 或回滚未获确认，则保留未知回执，只能先读取原请求。这个证明仅用于纯数据库准备，不能推广到已经有模型调用或外部结果的输出保存、候选导入及终止回执。
