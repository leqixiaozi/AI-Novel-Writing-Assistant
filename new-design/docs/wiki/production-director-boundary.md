# 全书导演、原正文与恢复边界

## 决策与原因

开书后的导演负责把已采用规划按全书顺序送入章节生成，不替作者采用候选。技术范围必须引用原请求、原规划、原正文和原 AI 账本，否则手动创作与自动范围会出现两份进度与两套事实。

> 白话比喻：配送员按装好的订单清单送件，签收单归原订单，不重新抄一本订单簿。对应到系统：导演保存范围及执行边界，采用正文／变化结算／稳定章由原创作链确认。

> 速记方法：导演送单，正文留正本；先保存候选，再明确采用与结算。

## 当前规则

1. 冻结完整正式总／卷／章／场景及精确资料引用、输入正文和真实路由来源版本；缺失、失效或读取不完整明确指出对应阶段。
2. 手动章节与全书范围使用同一受控原请求生成函数。原回复先保留，候选必须与原回复及冻结选区精确一致；明确采用与后续结算不是生成的副作用。
3. 未确认收到模型回复，停止该原请求的自动重试和模型回退，先只读核对。明确结束真实过期领取保留未知用量及原事件，旧尝试不能迟到覆盖。
4. 已保存原回复的入库／账本恢复不重复模型。档案修订冲突保护人工稿，精确原回复仍可读与复制，不能自动改原期望修订或伪造成功。
5. 已保存候选的账本和章边界确认必须恢复完成。边界确认与暂停／重规划状态原子保存，防止中断后跳过原判断。
6. 完成优先的局部质量欠账记录为章级提醒，继续后续章；质量优先明确人工暂停只由作者恢复；明确重规划要求准备新范围，不能直接沿旧范围继续。
7. 原结果未知只读核对原凭证，GET 空值不是未写入证明；开始 COMMIT 后丢失回执为 unknown，读失败不能撤销已经确认的保存。
8. 运行记录只看状态、候选进度、错误、历史和精准来源。继续、暂停、结束、重试、采用与结算均放原来源页，读取和轮询不派发任务。

## 连续性与知识实际注入

准备章节的同一数据库事务读取六类精确原来源，来源 hash 沿正式依赖解析器，完整元信息的 hash 单独保存。前章正文只取真实顺序紧邻章的稳定采用版本；缺失或过期明确说明，不跳过不稳定章改用更旧章。当前章／后章变化不得混作此前历史，人物认知不能当客观事实，初始状态不能当结算流水。来源超限明确拒绝，不用静默裁剪掩盖缺失。

手动章节与导演范围均由作者显式选择原知识资产、原件版本、解析版本和完整 UTF-8 哈希。范围冻结该选择，每章准备再次核对原来源、成功解析与有效依赖状态，完整内容进入实际 Prompt 消息和相同 manifest。知识绑定不等于已经给模型引用，关键词搜索不等于语义检索；失效原版本必须回知识来源页明确核对，不能自动换成最新解析版。

> 白话比喻：备课时把选定版教材和上一堂课的签到单放进同一个备课袋，而不是只在书架上贴标签。对应到系统：实际消息和 manifest 冻结版本内容，mount 仅是绑定，不能代替消费证明。

> 速记方法：明确选版→同事务核对→冻结消息与来源；认知不当事实，绑定不当引用。

## 原回复与人工出口

模型真实成功返回后，先把完整输出与脱敏执行快照写入受控本地原回复凭证，再保存原数据库请求输出。本地凭证只证明保存了回复，不证明数据库已提交、候选已采用或章节已稳定。只读源页面区分 `local_receipt` 与 `database`，提供精确原回复查看／复制；仅本地有凭证时不能伪造数据库入库完成。

queued 请求只有原任务／步骤 queued 且无当前或历史尝试，才允许明确结束未领取请求。已入库原回复因人工正文修订冲突无法导入时，可明确保留原回复并结束导入，原输出不删、真实用量与取消事件保留，不生成候选、不采用、不再次调用模型。已有候选必须先补原账本／章边界，不能用取消跳过质量优先的人工暂停。已结束尝试拒绝迟到结果写入。

> 白话比喻：饭菜已做好但顾客改了订单，厨房回单留存，顾客可以取走回单或结束这次出餐，不能把重做一份算成找回原菜。对应到系统：原回复保留与结束导入是明确人工出口，恢复不是再次调用模型。

> 速记方法：未领取才结束未领取；有回复先保留，已有候选补账本；未知只核对。

## 易错点

- `running` 不是原回复已保存的证据。恢复按钮依赖真实 controlled output；候选保存数也不等于采用或稳定正文数。
- 存在旧候选不能掩盖当前尝试未知；局部质量警告不能升级为全局重新规划。
- 不能以数据库字符序号代替编辑器 UTF-16 选区；拼回整章时原前后文字精确保留。
- 原请求 frozen fields 与终态不允许为了恢复而改写；另存／新重试需作者明确，旧证据保留。
- 混用 request→step 与 task→step→attempt→request 锁序会导致结束未知领取与结果保存死锁。
