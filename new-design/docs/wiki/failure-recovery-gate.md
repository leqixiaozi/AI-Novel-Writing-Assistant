# 失败恢复的开发门禁

## 为什么不只显示报错

小说系统面向初次写作的作者。失败提示的目标是帮助作者继续完成作品，不是把数据库或模型异常原文转贴到页面。错误发生后，作者需要知道具体停在哪一步、内容有没有保存、接下来点哪里，以及这次操作会影响什么。

> 白话比喻：快递停在分拣站，客服应该告诉你包裹在哪、是否保管好、怎样补地址；不能只说“系统异常”。对应到产品：错误提示同时携带失败阶段、保留结果、具体来源与恢复动作。

> 速记方法：定位、保留、入口、后果，四项齐了才算能恢复。

## 每个流程必须检查

1. **具体定位**：使用中文阶段名称；字段校验指明哪个表单、资料位置或字段，不让作者猜英文稳定键。技术详情仅供主动展开核对。
2. **结果分开**：列出已确认保存／发布／生成的部分与尚未确认部分；保存、采用、读取失败不能混为一次失败。重读失败保留已确认成功凭证与当前草稿。
3. **可点击恢复**：配置问题提供模型设置入口，底座问题提供运行维护入口，创作问题回到正确书籍与原工作页。不能只有“稍后重试”文字。
4. **安全后果**：操作前明确会重试哪一步、是否再次调用模型、是否覆盖草稿／影响下游。默认不重新生成整个流程，不让迟到结果覆盖人工接管后的编辑。
5. **未知先查**：超时、断连、无效回执和冲突先按原请求标识核对服务器。读取不到结果不证明原请求没执行；不得自动新建请求或再次模型调用。
6. **工作页恢复**：运行记录只读查看与跳回来源；重试、继续、审批、采用等修改动作必须在能看到内容与影响范围的原工作页。
7. **质量与运行区分**：可用章节的局部质量问题保留正文，登记局部修补或质量债，不无条件停止全书链路；明确质量优先人工暂停与数据安全失败仍遵循对应合同。
8. **独立验收**：编码／静态 review、单元模拟、真实 PostgreSQL／HTTP、真实模型、用户界面分别列证据。未执行不得以其他层通过替代。

## 验收判断

审阅任何失败分支时直接问：作者看到此页能否回答“哪一步失败、哪些没丢、我要点哪里、点击会发生什么”？其中一项答不出，恢复入口仍不完整。

### 按失败性质给出实际动作

| 失败性质 | 作者应看到的定位与保留说明 | 原工作页动作及安全限制 |
| --- | --- | --- |
| 表单校验未通过 | 中文对象、资料位置和字段；保留未保存输入，不能声称已入库 | “前往该字段”，展开所在分组并聚焦实际控件；修正后由作者明确保存 |
| 配置或底座不可用 | 停在准备、连接或调用阶段；分开说明已保存内容与尚未执行内容 | “打开模型设置”或“打开运行维护”，保留具体书籍／章节来源；修复配置后回原页操作 |
| 保存或结算结果不确定 | 标为“结果待核对”，不是“保存失败”；保留草稿、原请求标识与既有回执 | “核对保存结果”，只读查询原请求；未核实前锁定重复提交，不能自动生成新请求 |
| 已保存，刷新结果失败 | 明确“保存成功，读取结果失败”；保留成功回执，不能退回未保存状态 | “重新读取结果”，只读刷新；不得再次保存、采用、结算或调用模型 |
| 修订冲突或来源失效 | 指明冲突的对象、章节正文或正式字段版本；保留当前输入，不覆盖他人修改 | “查看最新版本”，只读核对；作者比较后明确重新准备提案，不盲目以新修订重发旧输入 |
| 模型生成失败 | 指明停在调用还是结果保存；列出保留的正文／候选和未生成部分 | 配置问题先去模型设置；仅在原工作页说明调用范围、次数与影响后允许明确重试，未知调用先核对 |

按钮名称必须对应真正实现的行为：只有读取接口时不能标为“恢复运行”；缺少原请求查询能力时不能声称已实现未知回执恢复。来源链接必须定位到相同书籍、章节及确认会话，并验证归属；不能仅跳到写作首页让作者再次找内容。跳回来源本身不得触发采用、重新生成或结算。

状态说明、问题定位和恢复按钮应在同一失败区域可见。字段错误通过控件关联的中文说明呈现；技术原文、标识和堆栈只供折叠查看，不替代普通作者说明。

该门禁是新设计自己的安全与产品合同；旧项目用于了解历史行为，不作为必须照搬的门禁。需要新增技术安全校验时，应解释其保护的数据或不确定性，不能把局部质量审核伪装为全局阻断。

## 当前覆盖与后续

内容类型保存／发布、统一开书表单与阶段准备、章节结果确认／结算、模型设置及提示词组合分别维护各自实现和证据。开书字段定位按具体审阅资料 ID 和字段解析；相同字段名称不能代替对象身份。关系规格失效需要提供模板／资料关联配置入口，不能只让作者反复提交原草稿。

开书实现与集中验证状态见 [统一开书验证](../creation-production-review.md)，章节证据见 [章节结果确认验证](../chapter-settlement-editing-review.md)。知识索引、全书编排与导演后续逐切片接入；本合同不是“全站都已完成恢复”的声明。唯一排期见 [执行队列](../p1-p2-execution-queue.md)，组合具体规则见 [组合执行](prompt-composition-execution.md)。
