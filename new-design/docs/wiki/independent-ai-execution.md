# 独立 AI 执行与失败恢复

## 背景与决策

新设计必须有自己的提示词注册、输出合同、模型传输和启动入口。旧系统配置与网关只读参考；标准模型 HTTP 服务不属于旧业务代码，可以按明确配置调用。

> 白话比喻：餐厅菜单和订单检查由本店负责，食材配送由指定供应商负责。对应系统：自有受控提示词定义任务，模型适配只发送请求，模型回复必须过自有表单校验才能成为候选。

> 速记方法：先配置，再编译，后传输，最后校验；连接可用不等于创作成功。

## 当前规则与范围

- `server/ai/prompts` 持有六种任务的版本化资产与动态输出合同；业务服务通过 `server/ai/index.ts` 的网关调用，不散落原始模型调用。
- 本阶段开发入口仅读取 `NEW_DESIGN_AI_*` 专用环境配置，支持 Ollama 与兼容 OpenAI 的结构化接口。不读取旧根配置，不自动选择模型，不把密钥写进 PostgreSQL、提示词、日志或 Git。
- 远程模型必须 HTTPS；地址不能嵌入用户名／密码／查询参数，传输禁止跳转。凭据只在服务进程内组装请求头，外部错误响应正文不进入错误或候选。
- 超时和输出上限有明确数值范围。失败没有自动重试或质量回退；不使用模板、关键词规则或静默取消严格输出以伪造成功。任务来源页负责明确发起下一次运行。
- 兼容接口请求使用 JSON Schema 引导并保留可选字段，不强制把所有可选资料变成必填；服务端 Zod 白名单与规格校验始终严格执行。传输侧非 strict 不表示允许未知字段或跳过本地校验，接口能力需真实模型验证。
- 提示词资产快照和模型参数随研究返回已有账本接口，不另建任务／正文事实；模型未报告用量时 `usageReported=false`、`usageStatus=unavailable`。既有数字接口的 0 仅为兼容占位，不是实测零消耗，不可用作计费证明。
- 模型页面只读配置检查与连接／模型名称探测，不生成资料、不写创作正本。完整中文持久化默认／备用／任务路由、旧凭据安全迁移、统一总预算与用量中心仍在 P2-3 后续范围，必须复用已有模型路由／快照事实，不建立第二套表。

## 失败动作

| 步骤 | 作者看到的结果 | 可点击恢复位置 |
| --- | --- | --- |
| 配置模型 | 模型名称或凭据未配置 | 模型设置 → 开发环境配置说明 → 重启服务 → 重新读取配置 |
| 检查连接／核对模型 | 无连接或指定模型不在列表中 | 模型设置 → 检查连接与模型 |
| 请求模型 | 授权、额度、服务故障或等待超时 | 模型设置检查后，回具体来源页核对状态再重试 |
| 解析／校验输出 | 返回结果不符合当前任务表单，未采用 | 模型设置核对能力；回来源页重新生成或调整输入 |

自有 HTTP 错误携带明确失败阶段、保留结果、固定模型设置入口；独立壳展示可收起错误通知，设置在新标签打开，原编辑页不跳走。运行记录仍只读，不能在记录页重试、恢复或修改候选。网络丢回执不证明服务器没有写入；API 连接失败／无效回执保留“待核对”语义。

## 验证边界

本功能完整编码后集中类型检查、边界扫描、单元、真实独立 Express／PostgreSQL及启动检查。传输测试桩仅证明合同与错误路径，不能证明真实模型质量；未配置专用模型时明确记录实际模型未执行。页面中文、点击、输入法与主题由用户验收，不宣称浏览器验证通过。
