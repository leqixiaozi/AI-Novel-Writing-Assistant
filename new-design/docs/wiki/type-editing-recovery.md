# 内容类型编辑失败与回执恢复

## 决策

失败必须说明当前内容类型、保存／发布／读取的具体步骤及可点击入口。只展示失败字符串不足以帮助作者恢复。

> 白话比喻：收银已付款但小票打印失败，不能让顾客再付一次。对应到系统：发布确认与随后版本列表读取分开处理；读取失败只重试读取，不重试发布。

> 速记方法：明确失败再修正，回执不明先核对；发布成功只重读。

## 当前规则

- 发布有未保存修改时，先保存当前编辑，再使用服务器返回修订号发布；保存失败则不执行发布。
- 网络／服务端故障视为结果待核对，禁止盲目重复写入。当前页面编辑仍保留，但未承诺刷新或跨设备后保留未保存编辑。
- “核对服务器结果”只读；新类型以固定类型键查找，已有类型按身份读取，避免网络丢回执后新建第二个类型。
- 核对保存成功时保留提交后追加的编辑，只更新服务器身份与修订元数据，不覆盖人工内容。
- 修订冲突先展示服务器名称、说明、字段及版本；作者显式选择保留当前编辑继续后，才允许以核对后的修订保存。该动作不自动写库，保存仍有乐观锁。
- 读取规格失败不伪装为空字段／空标签。已发布字段未读到时阻止字段编辑，显示原页面“重试读取规格”。
- “运行维护”在新标签打开，原编辑页保持不离开。来源页操作恢复，运行记录只负责查看与跳转。
- 表单校验返回明确路径：HTTP 参数错误按 `fields.<序号>.<属性>` 定位；类型演进与字典绑定错误按 `fieldKey.<稳定键>` 定位，避免人物“姓名”与类型“名称”同名时误指。错误列表显示中文名称和“定位到错误字段”，目标行显示校验说明、错误边界并可键盘聚焦。
- 校验位置按提交时的字段快照解析成稳定键；人工移动字段不会让错误跳到另一行。已删除或无法识别的字段错误跳到字段定义区域，不从错误文本猜测位置。
- 明确拒绝且无需核对的保存／发布错误，在提示旁提供“修改后重试保存草稿／发布版本”；回执不明或冲突只提供只读核对，不开放盲目重试。确认保存成功但发布失败，提示保留的服务器草稿，不把完整流程说成全部失败。

## 范围与验证

覆盖内容类型目录读取及编辑器保存／发布和规格读取。其他专业流程仍按相同原则逐切片接入，不能宣称全部页面已统一恢复。当前页面未做浏览器／主题／窄屏验收，交由用户验收。

2026-09-16 在当前分支完成编码后执行 `pnpm --dir new-design run typecheck`，服务与客户端通过；最终客户端微调后再次执行 `typecheck:client`。`node --test new-design/tests/type-editing.unit.test.cjs new-design/tests/presentation.unit.test.cjs` 共 9 项通过，覆盖先保存后发布、失败步骤、无自动重试、读取失败不撤销发布成功，以及回执核对保留追加编辑。

本切片没有修改数据库／HTTP 写入合同或迁移，没有重做 PostgreSQL／模型测试。单元用例不证明浏览器按钮实际交互、断网恢复或跨标签冲突可用，这些仍待用户验收。静态审查确认写入与后续读取分开，读取版本前不将空数组作为可编辑已发布字段。

用户随后追加字段定位与可点击恢复要求。对应追加修改包括类型校验错误路径、定位与阶段回执提示、API 无效响应／断连分类；上述历史 9 项验证不覆盖这些追加代码，追加验证在独立运行完整功能编码结束后集中执行，不能沿用历史通过结果宣称新代码通过。

追加代码最终通过服务／客户端类型检查，校验定位与精确发布回执单元覆盖；真实 HTTP 类型演进拒绝返回明确稳定字段路径且数据库未改动。完整集中证据及未执行边界见 [独立运行验证](../independent-runtime-review.md)。发布核对读取当前类型的不可变版本列表，只有发布指针变化、新版本号高于提交前且字段完全一致才确认为已发布；核对只更新身份／修订／发布元数据，保留当前人工编辑。
