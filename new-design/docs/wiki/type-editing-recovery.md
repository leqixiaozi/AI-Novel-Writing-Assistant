# 内容类型编辑失败与回执恢复

## 决策

失败必须说明当前内容类型、保存／发布／读取的具体步骤及可点击入口。只展示失败字符串不足以帮助作者恢复。

> 白话比喻：收银已付款但小票打印失败，不能让顾客再付一次。对应到系统：发布确认与随后版本列表读取分开处理；读取失败只重试读取，不重试发布。

> 速记方法：明确失败再修正，回执不明先核对；发布成功只重读。

## 当前规则

- 发布有未保存修改时，先保存当前编辑，再使用服务器返回修订号发布；保存失败则不执行发布。
- 网络／服务端故障视为结果待核对，禁止盲目重复写入。当前页面编辑仍保留，但未承诺刷新或跨设备后保留未保存编辑。
- “核对服务器结果”只读；新类型以固定类型键查找，已有类型按身份读取，避免网络丢回执后新建第二个类型。
- 核对保存成功时保留提交后追加的编辑，只更新服务器身份与修订元数据，不覆盖人工内容。
- 修订冲突先展示服务器名称、说明、字段及版本；作者显式选择保留当前编辑继续后，才允许以核对后的修订保存。该动作不自动写库，保存仍有乐观锁。
- 读取规格失败不伪装为空字段／空标签。已发布字段未读到时阻止字段编辑，显示原页面“重试读取规格”。
- “运行维护”在新标签打开，原编辑页保持不离开。来源页操作恢复，运行记录只负责查看与跳转。

## 范围与验证

覆盖内容类型目录读取及编辑器保存／发布和规格读取。其他专业流程仍按相同原则逐切片接入，不能宣称全部页面已统一恢复。当前页面未做浏览器／主题／窄屏验收，交由用户验收。
