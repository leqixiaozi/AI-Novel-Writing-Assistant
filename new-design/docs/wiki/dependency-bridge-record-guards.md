# 依赖桥接触发器的记录保护

026 的通用依赖桥接函数挂在九类表上。各表像不同部门提交的表格：发布表没有结算表的“状态”栏目，前台必须先确认表格种类再读对应栏目。技术上，触发器的 `NEW` 和 `OLD` 是实际表结构，不能依赖布尔表达式的求值顺序保护不存在的字段。

速记顺序是“先选表 → 再选操作 → 最后读字段”。对应实现为 `CASE TG_TABLE_NAME`，各分支先判断真实 `TG_OP`；仅结算 UPDATE 分支读取 `OLD.status`，仅质量报告 UPDATE 分支读取 `OLD.stale_at`。

057 以新增迁移 `CREATE OR REPLACE FUNCTION` 修复分支保护。正文采用、规划采用、事实、知识、时间、因果关系、结算、合同发布和质量失效的原资源登记与失效调用完整保留；没有停用或替换触发器，没有删除数据，也没有重写已应用的 026。函数保留新设计专用查找路径。

SQL 静态回归用例对比原失效调用，检查表/操作的嵌套分支以及迁移登记。静态用例不是数据库运行验收；实际发布和结算事务由主任务在整阶段编码结束后集中验证。

数据库纯事务命令若尚未发送 COMMIT，且物理连接已确认 ROLLBACK，可明确报告本次未写入，即使原错误来自 SQL 服务故障。这像柜台确认撤销整单后，作者能保留原表格、修复服务并明确重新准备。对应技术上，证明来自物理事务回滚 ACK，绝不来自“回执查不到”。已经开始提交或回滚未确认仍是结果未知，必须核对原请求；真实模型调用有外部副作用，不适用“事务回滚所以模型未调用”的推断。
