# 同源工作台运行与数据边界

5273 网关让旧外壳中的旧菜单与新设计菜单共存。页面和资源转发 5275；新 API 转发 5301，其余 API 转发 3000。旧外壳的启动门禁查询 /api/health，所以只启动 5301 或只获得首页 HTTP 200 都不足以让工作台可用。

网关分别监听 IPv4 127.0.0.1 与 IPv6 ::1；localhost 的解析顺序因浏览器而异，缺少 IPv6 监听会导致浏览器拒绝连接。两个监听共享代理与 WebSocket 行为，退出时均关闭。仅监听本机回环。

旧 API 的对比启动使用已存在 SQLite，跳过初始化、迁移、清理与后台恢复。新 API 的本次受控启动读取原数据库校验扩展与迁移数量，没有执行迁移或启动后台处理器；健康的 workers=disabled 应被如实说明。普通完整启动与此验证状态不同。

总控台与运行记录查询先在来源投影中计算状态，再关联书籍名称，避免书籍与任务同名 status 字段歧义。总控读取处于只读事务；不能通过恢复任务来修复读取故障。

故事工作区的数据、URL、草稿及 AI 能力边界见 [模块说明](../../src/client/storyWorkspace/README.md)。设定初始值和规划意图不等同正文事实；候选生成不等同采用或结算。

开发验证不应输出编译产物触发旧服务监听重启；使用 tsc --noEmit。界面验证须确认实际 DOM 菜单与内容出现，接口验证须包括真实功能读取，不能只看监听或首页响应码。

包的客户端入口会被旧路由再次用 React.lazy 导入。默认导出必须是普通组件函数，由该函数渲染内部延迟加载页面；不能直接默认导出另一个 lazy 对象，否则外层解析到对象而非组件函数，运行时会报错并卸载外壳和菜单。导航常量仍同步导出，读取菜单不加载业务页面。类型检查无法覆盖这个组合，需同时验证外层延迟导入的渲染及新旧菜单往返。

新版源码通过旧外壳的 Vite 服务加载时，包内 `@tiptap/react` 可能自带另一份 React，导致正文编辑器的 Hook 在不同渲染器下抛出 `Invalid hook call`，整页空白。跨包组件必须复用宿主 React；章节正文使用 Tiptap 核心实例、原生插件与宿主 Portal，并在卸载时销毁插件监听。章节页的回归需要实际查看正文编辑器、切换空章、检查控制台错误和隔离书的保存重开，不能只凭页面 HTTP 200 或 TypeScript 编译判定。

网页版旧菜单使用 React Router 的 reloadDocument，交由浏览器在同一来源打开目标路径，重建页面和路由状态；不会跳到内部 5275 或其他端口。新设计菜单保留站内路由。桌面版使用 HashRouter，不能用该方式打开根路径，因此仍通过原路由切换。离页草稿保护仍在捕获阶段生效，未保存填写需要先保存或明确放弃。HTTP 深链和模块响应只能证明资源可读取，不能替代用户的菜单交互验收。
