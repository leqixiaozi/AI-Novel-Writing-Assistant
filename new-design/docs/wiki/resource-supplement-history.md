# 稳定章节补充的历史依据

稳定正文已形成正式事实、读者／人物认知和状态变化，补充遗漏的资源变化不能把原稳定会话重开或重新采用相同正文。重新采用会触发原来源失效链；复制相同正文会产生另一个版本，仍不能代表原确认记录。独立补充应引用原检查点和确切采用正文，并最终把原确认来源与新增确认一起提供给下一章。

另一个风险是前值的时间范围。正常可编辑章使用当前正式投影；补充早期稳定章使用所选章结束时的正式状态，包含该章已经确认的变化。否则已有“0→1”的获取会再次被当作遗漏重复结算，或后续“1→2”泄漏成为早期章前值。

`database/resourceSupplements`的基础读取核对完整原检查点清单，逐类核对事实正文证据、认知提案版本和状态结算及提案。事实／认知／状态不互相替代。冻结正文对应的原计划版本，后来编辑计划不能替换它。清单、证据或正式来源失效时拒绝生成补充依据，原记录保留。

历史状态按实际书籍、对象、状态键和章末范围读取有效状态变化，校验结算、提案、当前采用正文和有效证据。明确的故事顺序优先，没有独立故事顺序时使用该变化实际所属正文的章节顺序。只有在原检查点形成之前已经存在的不可变初始版本才能作为回退；后来新建或修改的初始状态不能反向提供旧章前值。没有来源时保持未知，不返回0或false。

所有读取由调用方的同一个可重复读事务负责，仅SELECT，不生成候选、不写状态、不恢复任务。本基础合同不开放稳定补充按钮。完整链还需要独立补充会话／完整原请求、同事务保留原结算并合并确认清单、冻结实际下游来源和逐项复核。源页必须明确展示这些影响及恢复位置，不能用新的普通可编辑会话绕开它们。
