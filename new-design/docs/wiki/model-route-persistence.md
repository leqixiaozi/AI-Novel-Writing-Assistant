# 新设计模型路由版本与安全凭据引用

## 当前动作与必要闭环

用户在模型设置选择默认/任务模型、预算和技术回退，保存后必须被资料 AI 和研究/规划读取。仅保存环境配置不能表达任务覆盖、版本启用或重试幂等。只读参考旧系统的“默认模型＋任务覆盖＋技术故障回退”行为，新设计的最小实现复用自身既有路由配置、版本、发布回执、凭据引用和不可变快照表，不调用旧业务模块，不新增第二套路由事实。

验收闭环：编辑 → 输入校验 → 原子保存并启用 → 明确任务解析 → 固定本次快照 → 下游执行；失败定位到模型设置，来源页保留草稿并可重试。连接探测归属独立模型适配器，不表示已有作品或规划被采用。

## 保存与版本

配置、版本、备用模型和发布回执共用一个 PostgreSQL 事务。范围锁与配置修订号避免并发覆盖；请求标识锁避免两个重复请求追加版本。重复请求核对原版本 `content_hash` 中的完整已校验请求（包括预期身份/修订和替换确认），相同才返回原保存版本。迟到回执的 `active` 反映该版本是否仍启用，而非谎称再次启用。

> 🏠 白话比喻：模型设置像办公室电话转接表，保存版本像签字存档的旧转接表；重复点保存是拿同一张收据查询，不能偷偷再换一遍电话。对应到数据库：配置引用启用版本，发布回执记录原版本，重复请求不产生新版本。

> 🧠 速记方法：同键同请求只查回执，不同请求必须换键；同范围保存先核对修订再换版本。

系统默认必须完整配置并发布，六个明确任务可以覆盖。无已发布默认路由明确失败，不从环境模型配置或旧网关隐式回退。任务恢复继承只归档当前任务配置，保留所有版本和回执，不删除历史。任务分类来自受控任务键，不按输入关键词猜路由。

未知供应商、未知参数、能力需求和旧高级预算/重试设置不能被静默清除。目录准确标注需确认；显式 `replaceUnsupported` 后才建立新版本，旧版本正文不变。当前受控参数只使用 `baseUrl`、预算 `maxTokens`（总预算）/`maxOutputTokens`、重试 `maxRetries`/`retryDelayMs`。

保存和执行使用相同安全范围：输出 256～32768、总预算不低于输出且最多 2000000、等待 1000～600000 毫秒、重试 0～3 次、间隔 0～10000 毫秒、最多 4 个备用模型。远程地址仅允许 HTTPS，本地回环可用 HTTP。旧非法地址（可能夹带凭据）不回显到公开目录，其原始历史不改动，必须明确确认替换。

## 凭据与公开信息

仅保存 `env://NEW_DESIGN_AI_*` 定位引用，不保存密钥值。同名同供应商同定位重复返回已有记录；同名不同定位或供应商冲突，不覆盖旧引用。旧非专用定位仍保留，但不能作为新设计可用凭据。

> 🏠 白话比喻：引用像储物柜号码，不是柜子里的钥匙。对应到运行时：公开界面只看名称和是否可用，适配器通过专用环境变量取实际凭据，记录和导出不得携带值。

> 🧠 速记方法：界面只报“在哪找”和“有没有”，不报“是什么”。公开目录只提供凭据 id/中文名称/供应商/状态/可用标志和变量名称/可用布尔，不返回 locator 或环境变量值。

## 本次执行快照

迁移 052 将既有 `model_route_snapshots` 扩展为两种互斥合法范围：旧书籍＋任务合同版本两者都有，或开书前两者为空且明确六任务键。所有旧行、外键和不可变触发器保留。解析只读取已启用、已发布的默认和该任务版本，快照重建历史来源版本并核对内容，再写同一快照及备用模型子表。发布竞态不会把当前设置冒充旧任务来源。

旧按书籍合同读取的快照入口拒绝开书前快照，不产生字符串 `null` 假标识。公开预览不写快照。预算执行、错误类别判定和受控技术回退归属模型适配/执行模块，内容质量不自动切换供应商。

## 验证与隔离

`tests/model-routing.postgres.test.cjs` 创建唯一 `model_route_test_*` schema，仅复制表结构、约束及必要不可变触发器，在其内建立可归档的测试事实；生产 HTTP 不接受 schema/数据库上下文。不会临时替换、归档或更新用户默认路由；原默认身份/版本/修订前后只读比对。测试夹具保留并标明 schema，不执行删除或 drop。

内部注入已有客户端时，调用方拥有事务边界，必须先 BEGIN 并负责 COMMIT/ROLLBACK；生产默认由模块自行维护事务。单测/隔离 PG 不等于真实 HTTP、模型质量或用户界面验收，完整功能阶段需集中记录实际证据。
