# U4“关联资料与局部信息”静态审查

审查日期：2026-09-16

## 已完成

- 表单驱动：只读取当前书籍、当前主资料和当前已发布创作表单中的关联位置；显示客户可理解的名称、分区、关系规则和数量。
- 搜索边界：按标题／类型检索当前书有效资料，并过滤自身、已选中、已归档、类型或关系方向不符的资料；支持限量与继续加载。
- 原子新建：正式资料、初始不可变修订、挂载与挂载版本在同一事务产生，失败整体回滚。
- 单一写入：表单组合只写挂载；独立业务关系只写关系账本。旧组合保存入口不再同时创建／归档关系，也不物理删除挂载。
- 版本与来源：挂载、关系和动作回执只追加；挂载锁定来源资料版本，来源变化会显式提示，采用最新来源需单独确认。
- 局部信息：模板声明和用户新增的信息都固定为 `card_mount` 作用域，复用动态表单与 U3 字段构建器，不写回来源资料。
- 并发：实例和挂载修订不匹配时返回 `409`；主表单、搜索、新建、来源编辑和局部信息输入均保留在页面状态中。
- 安全移除：遵守最小数量，只结束关联，不删除来源；归档来源只读，反向引用数量可见。
- 依赖：挂载版本接入 026 统一依赖资源和边，不直接写 AGE 投影。
- 可访问性：输入均有可见标签，状态使用 `aria-live`，对话框有名称、关闭按钮和初始标题焦点，排序按钮带目标名称。
- 主题：样式仅使用现有 `--nd-*` 和主题变量，无固定明暗色值。

> 🏠 **白话比喻**：静态审查像在开店前核对收银规则、价签和消防通道图，能发现线路设计问题，但不能替代真正开门后的客流演练。对应到本批：类型检查和差异审查证明代码合同自洽，真实数据库与浏览器行为仍属于发布验收。

> 🧠 **速记方法**：**静态查线路，实测查运行；本批先开发，发布前补验收。**

## Release Gate

1. 在真实 PostgreSQL 顺序执行 001—035，验证旧挂载回填、不可变触发器、依赖登记、局部字段选项和外键。
2. 用真实书籍覆盖空关联、最小／最大数量、重复、自关联、错类型、错方向、归档来源、移除／恢复和来源换版。
3. 双窗口制造实例、挂载、来源资料并发修改，确认 `409` 后四类本地输入均保留。
4. 验证“新建并加入”任一步失败都不产生孤立资料，旧组合表单入口不再双写业务关系。
5. 四套主题和明暗模式人工检查桌面／窄屏、键盘焦点、长标题、长列表、空结果和错误状态。
6. 通过 PostgreSQL 逻辑备份与受管附件 manifest 在另一台机器恢复，核对来源版本、挂载历史、局部值、反向引用和依赖账本。
