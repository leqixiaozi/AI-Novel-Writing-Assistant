# 旧章换稿影响预览与选择性重算

## 目标与边界

稳定章节改用另一份正文时，系统必须先冻结影响预览，再由作者逐项选择处理方式并二次确认。执行只移动章节采用指针、撤销旧来源的有效性并登记选择性重算；旧正文、旧结算、旧检查点和人工修正记录都保留。后续章节正文不会被后台任务覆盖，只进入作者复核。

> 🏠 **白话比喻**：旧章换稿像改造已经通车的一段道路。不能直接推倒后面的街区，而要先画出受影响的公交线路、水电管线和路口，再逐项决定改线、复核或保留人工绕行。对应到系统：冻结预览是施工图，处理计划是逐项签字单，选择性重算只重建可再生派生物，后续正文始终由作者决定。

> 🧠 **速记方法**：**先冻范围，逐项选择，二次确认，从前一站重算，后文只复核。** “前一站”对应 `restart_checkpoint_id`，“只复核”对应 `chapter_revision_review_flags`。

## 作者流程

1. 在旧章采用确认中生成影响预览。此时正文采用指针不变化。
2. 对事实、角色所知、人物／关系／道具／事件／伏笔、依赖派生物、后续正文、关系图和语义索引选择处理方式。
3. 保存处理计划。高风险和核心影响不能选择“暂不处理”。
4. 核对正文差异、失效数量、保留数量、重算数量和人工复核数量，勾选二次确认后执行。
5. 新正文进入既有 F4 变化确认；依赖任务复用 030 Outbox／后台作业。
6. 后续章节在章节工作台显示来源原因，作者可“复核后保留正文”或“完成调整”。
7. 新正文产生稳定检查点且所有复核项关闭后，换稿执行才进入 `stable`。

## 数据合同

- `chapter_revision_previews`：冻结新旧正文、旧结算、旧检查点、重算起点、文档修订、依赖 generation、正文差异与摘要哈希。同一会话只允许一个 `ready` 预览；失效预览保留历史，可重新生成。
- `chapter_revision_impacts`：只追加的逐项影响事实，记录风险、原因链、可选动作、来源数量和人工保护状态。
- `chapter_revision_plans` / `chapter_revision_plan_items`：保存作者选择、理由、修订号和二次确认状态。
- `chapter_revision_executions` / `chapter_revision_recompute_steps`：记录采用切换、失效事件、从前一稳定检查点开始的顺序步骤，以及 030 后台作业 ID。
- `chapter_revision_review_flags`：把受影响的后续正文投影到其来源页面，正文内容本身不被修改。
- `chapter_revision_protection_marks`：对作者明确保留的人工纠正建立永久保护标记，后续预览继续识别。
- `chapter_revision_events`：只追加记录预览、计划、执行、复核和完成事件。

041 只编排既有正文、事实、知识、状态、依赖、图和语义正本，不建立第二套小说真相表。

## 处理动作语义

| 动作 | 语义 | 安全边界 |
| --- | --- | --- |
| `auto_recompute` | 撤销旧来源并复用依赖重算任务 | 只处理可再生派生物，不覆盖后续正文 |
| `review_manually` | 保留对象并建立作者复核 | 来源页面必须显示原因 |
| `mark_stale` | 标记旧来源或派生内容过期 | 不伪造重算成功 |
| `keep_manual_correction` | 保留人工纠正并写保护标记 | 必须留下执行、对象和理由 |
| `defer` | 暂不处理低／中风险派生项 | 高风险与核心影响禁止使用 |

共享事实先撤销旧证据；若仍有其他有效证据，事实正本保持可用。只有有效证据归零且作者没有明确保护时，事实才转为 `stale`。角色所知与状态变化同样依据精确旧正文／旧结算来源失效。

## 顺序与恢复

重算起点是被改章节之前最近的稳定检查点。执行先登记新正文采用与统一依赖失效事件，再按依赖路径产生步骤；图投影、语义派生和通用依赖任务仍由 030 运行器执行。失败、死信和取消继续显示在源页面，带后台作业 ID 的步骤可使用既有重试／取消入口。

正文、检查点或依赖 generation 在执行前发生变化时，预览转为 `expired`，执行失败关闭并要求重新生成。部分任务失败不会把章节伪装成稳定。后续修复完成后，F4 重新结算产生新稳定检查点；所有正文复核项关闭后，执行与计划才完成。

## F6 / F7 读取合同

`GET /books/:bookId/chapter-revision-state` 可按章节返回：

- 当前未关闭的后续正文影响及其来源路由；
- 当前未稳定的换稿执行及步骤进度；
- 最近可安全读取的稳定检查点。

后续规划和自动推进必须读取 `safeCheckpoint`，不能把 `awaiting_review`、失败执行或旧的 `superseded` 检查点当作当前真相。

## 跨机器同步

迁移 `041_chapter_revision_recompute.sql`、服务端／客户端合同、运行包规格和本文随 Git 同步。冻结预览、处理计划、执行、保护标记和复核结果属于 PostgreSQL 业务数据，必须通过项目逻辑备份／恢复与受管附件包同步；仅拉取代码不会携带作者的换稿处理进度。
