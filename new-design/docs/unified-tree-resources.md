# 统一树资源：字典树与多维标签树

## 用户看到什么

作者不需要理解“卡片”或数据库结构。在“创作资源”中，字典与标签都按紧凑目录使用：左侧选择资源，右侧编辑当前树；系统资源、开书模板和本书独立资源作为可收缩父节点，具体字典或标签维度作为子节点。树节点支持新增下级、调整同级顺序、改名、移动和停用影响预览。

字典树负责表单选项，例如人物类型、地点层级、道具类别和事件阶段。多维标签树负责独立分类问题，例如题材、情绪、叙事功能和完成状态。两者共用选择规则，但不会混成一张树。

> 白话理解：字典树像表单里的“省／市／区”选项，决定这一格允许填什么；标签树像档案袋上的多组贴纸，帮助筛选同一份资料。前者是字段值，后者是分类索引。

## 选择规则

每个字典字段或标签维度都可设置：

- 单选、多选、逐级单选或逐级多选；
- 整棵树、指定分支、直接下级、所有后代或向下若干层；
- 范围起点、最少／最多选择数；
- 是否只允许最末级、是否允许选择有下级的节点；
- 是否显示完整路径、允许原地新增、允许 AI 建议；
- 字典字段还可声明“章节采用后结算变化”；标签维度可分别决定是否参与筛选和 AI 参考资料。

服务端在保存内容类型、标签绑定和卡片值时重复验证这些规则。前端隐藏或禁用某个选项不能绕过服务端门禁。

## 稳定身份与历史显示

字段保存节点 UUID，不保存中文名称。节点改名或移动时会产生不可变版本；每个卡片版本同时保存当时的中文完整路径快照。因此旧章节、旧卡片版本和导出仍能显示当时看到的名称，不会被后来改名静默改写。

`dictionary_item_versions` 保存字典节点版本，`material_tag_dimension_versions`、`material_tag_versions` 保存标签维度与节点版本，`card_tree_value_snapshots` 保存卡片版本的字典路径快照。标签祖先改名或移动时，所有后代会追加新版本以刷新当前路径，旧版本仍保留。

## 模板安装与升级

模板版本冻结内容类型、字典树、标签维度和类型—标签绑定。开书时复制到书籍空间并重映射字典 ID、节点 ID、标签 ID和规则中的范围起点；模板种子卡片中的节点值也同步重映射。

模板升级只自动增加新树、新节点和新绑定。已存在节点的改名、移动、停用或规则变化进入冲突预览，不覆盖作者在本书中的修改。同步预览与应用结果记录在 `book_template_syncs.tree_additions`。

## 跨机器同步

迁移 `046_unified_dictionary_tag_trees.sql` 与 `047_tree_value_snapshot_paths.sql`、本说明和确定性模板定义进入 Git。作者创建的字典、标签、卡片值与版本属于 PostgreSQL 业务数据，必须通过项目的逻辑备份／恢复流程同步；不能只复制数据库数据目录，也不能只拉 Git 期待业务数据自动出现。

## 影响与安全边界

- 父节点必须属于同一棵树，数据库触发器阻止自引用和循环。
- 停用前提供后代数量、正式引用和受影响字段预览；停用不物理删除历史。
- 按祖先标签筛选会命中其后代标签，但不会复制标签成员关系。
- 系统只读资源不能直接修改；书内副本可独立调整。
- 树路径是数据库正本，AGE 和向量索引仍是可重建投影，不承担树的唯一事实来源。
