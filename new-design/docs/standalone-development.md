# 独立开发与运行

## 边界与闭环

目标动作是在不加载旧小说业务目录的情况下，启动页面、读取 PostgreSQL 并通过新设计自有模型生成资料。旧系统只供只读行为参考；本入口不导入旧 AppLayout、旧模型网关、旧提示词注册、旧 shared 或 SQLite 链。

> 白话比喻：独立店铺不仅要有自己的货架，也要有自己的门和收银台。对应到系统：页面入口、HTTP 服务、提示词执行和构建配置均归新设计所有，标准第三方依赖仍可使用。

> 速记方法：本包安装、本包配置、本包启动；数据库和模型服务是外部能力，不是旧业务代码。

本完整功能连续完成入口、界面主题、HTTP 接线和文档后，由集成负责人集中验证；本文不把静态实现或测试桩等同实际模型成功。

## 标准依赖与许可

独立 `package-lock.json` 使用 registry 下载项，不引用旧根 `node_modules/.pnpm` 路径。实际锁定 React／ReactDOM 19.3.0、Vite 7.3.6、tsx 4.23.13；锁内对应许可为 MIT。它们是基础 UI／构建工具，没有引入商业服务或 UI 组件库；原包 AGPL 许可保持。安装后依赖目录内应保留各自版权和 LICENSE，锁文件不是对全部供应链的安全背书。

## 安装、开发与构建

要求 Node.js 20.19+ 或 22.12+，Docker Desktop 已运行。所有命令在 `new-design/` 目录执行，不使用旧根启动命令。

```powershell
npm ci --workspaces=false
npm run dev
```

独立页面：`http://127.0.0.1:5174/new-design`。开发 API：`http://127.0.0.1:5301/api/new-design`。5174 的同源 API 代理指向 5301，不经过旧服务。已有 5173／3000 的过渡旧壳不受此入口修改；不能以它们代替独立验收。

也可分别执行 `npm run dev:server` 与 `npm run dev:client`。默认开发数据库模式只使用已锁定的 Docker PostgreSQL17／AGE／pgvector，不回退系统数据库或 SQLite。`AI_NOVEL_NEW_DESIGN_DEV_RUNTIME=0` 是受控私有运行包模式，需自有运行包 manifest，本阶段开发环境不要求打包。

```powershell
npm run build
npm start
```

构建后 5301 同时提供 `dist/client` 静态页面和自有 API；页面及所有 `/new-design/...` 深链接可直接打开。客户端构建与服务编译采用包内基础配置，`npm start` 不加载旧业务目录。

## 页面与主题

独立响应式导航直接复用新设计已有页面、表单和事实编辑器。创作首页、书籍、资源、研究及高级设置均可访问；提示词管理有独立入口，模型设置链接 `/new-design/structure/models`。移动设备可展开／收起导航；键盘可跳到编辑内容。

七项主题选择为跟随系统，以及清爽、纸张、夜读的浅色／深色。全部 HSL 语义变量在本包持有，不加载旧 CSS。主题偏好使用新设计独立存储键，浏览器禁用存储不影响即时切换。

## 失败定位和恢复

只读入口 `/api/new-design/independent-health` 返回启动阶段、失败步骤、数据库／后台状态和恢复位置，不输出凭据或 Docker 原始堆栈。数据库／后台启动失败时 HTTP 保持可访问，便于在运行维护核对；这不表示后台就绪，也不会自动恢复失败任务或清空数据。

| 失败位置 | 已保留内容 | 恢复动作 |
| --- | --- | --- |
| 依赖安装／开发进程启动 | PostgreSQL 数据未改动 | 在本包执行 `npm ci --workspaces=false`，再执行 `npm run dev` |
| HTTP 端口监听 | 数据库原有数据 | 检查 5301 是否被占用，设置 `NEW_DESIGN_HTTP_PORT` 后重新启动；开发代理相应调整仍仅限本包 |
| 数据库启动与迁移校验 | 原有数据，不做清空／重置 | 启动 Docker Desktop，点击高级设置 → 运行维护，核对后执行 `npm run dev:server` |
| 后台处理器启动 | 已保存数据库结果 | 点击运行维护核对，再重启独立服务；运行记录保持只读 |
| 页面渲染失败 | 已保存数据库结果；未保存页面内容不承诺跨重载恢复 | 先在新标签点击“打开运行维护／模型设置”，核对后才点击“确认重新打开页面”，重载会清除未保存页面状态 |
| 模型连接／生成 | 原有草稿及候选 | 点击模型设置修正配置，在原业务页面重试；不使用假生成掩盖失败 |

`independent-health` 不发起数据库写入、不恢复任务；真正工作流重试仍在有创作上下文的来源页面明确执行。

模型设置提供持久化默认／备用／任务路由，执行读取已生效 PostgreSQL 版本，不把环境变量中的模型名称当作生产路由。专用环境变量只用于凭据引用；页面不保存密钥正文。操作与失败恢复见 [模型执行和恢复](model-route-runtime-review.md)；底层事实复用见 [路由持久化](wiki/model-route-persistence.md)。没有明确配置并启用模型时，资料编辑服务仍可使用，但 AI 任务显示失败阶段与模型设置入口；连接检查和配置可读取不代表实际生成成功。

## 验收清单与证据边界

完整编码结束后集中执行：`npm run check:boundary`、`npm run typecheck`、`npm run build`，独立入口 HTTP／真实 PostgreSQL 测试，以及可行的实际模型调用。边界检查遍历生产源码、脚本和 Vite 静态／字面量模块加载，拒绝包外相对导入、未经声明的别名和计算式加载，并检查包内 tsconfig／自有主题；静态扫描仍不是任意外部第三方包的完整供应链证明。

模型、数据库和后台接线均需实际运行结果才算验收；测试桩只证明接口行为。中文输入、主题切换、窄屏和页面点击默认由用户验收，不反复截图。集中验证结果由集成负责人追加，此文建立时这些检查均未执行。
