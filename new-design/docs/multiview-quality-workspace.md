# 多维视图与质量闭环

F7 为每本书提供一个“多维视图”入口。标签页只改变筛选、排序和呈现方式，不复制人物、关系、事件、正文、事实或状态数据。

> 🏠 **白话比喻**：多维视图像同一座仓库的目录、货架图和盘点表。它们从不同角度帮助找货，但货物仍只有一份。对应到系统：PostgreSQL 业务表是正本，页面、AGE 和 pgvector 都只能读取或重建索引。

> 🧠 **速记方法**：**一份正本，多种看法；修改回表单，稳定改动先看影响。**

## 视图与正式来源

| 作者看到的视图 | 正式来源 | 编辑去向 |
| --- | --- | --- |
| 章节 | `chapter_documents`、正文版本、叙事位置、稳定检查点 | 章节工作台或资料表单 |
| 人物 | 人物资料 | 人物表单 |
| 人物关系 | `card_relations` 的人物关系正本 | 双向关系表单，保存前显示影响 |
| 剧情与事件 | `story_event_timings`、叙事位置、事件资料 | 事件表单和时间影响预览 |
| 线索／伏笔 | 线索资料、叙事位置、正文锚点 | 伏笔生命周期表单，保存前显示影响 |
| 道具流转 | `state_changes` 中道具正式变化 | 来源章节确认清单或道具资料表单 |
| 状态变化 | `state_changes` 与正文证据 | 来源章节确认清单或相关资料表单 |
| 世界规则 | 世界资料与 `canonical_facts` | 世界设定表单；事实走提案／确认链 |
| 整章对照 | `chapter_body_versions` 与采用指针 | 章节工作台的整章比较 |
| 质量检查 | 025 质量报告、问题、证据、修订候选和复检 | 问题处理、统一 AI 运行预览、章节候选采用链 |

043 扩展 `book_view_configs` 与 `smart_views.base_view_key` 可使用的视图键，并为既有书籍补默认配置。开书安装器会把旧模板缺少的视图配置按键补齐，因此旧模板和新模板创建的书都能得到完整入口。配置仅包含分组、排序、展示方式和展开状态，不保存业务结果。

## 质量问题生命周期

客观连续性问题与主观审美建议分栏展示。每个问题绑定书籍、报告、规则版本、任务与尝试快照；章节问题还绑定确切正文版本。证据继续使用 025 的正文锚点、事实、状态、时间、事件关系、规划版本、规则或显式未验证观察。

作者可确认、暂后处理、忽略、标记误报或添加备注。043 为“暂后处理”补充独立 `deferred` 状态，避免把延期决定伪装成确认或备注。AI 修订从统一运行预览发起，只能产生新的整章正文候选；候选必须回到章节工作台完成比较、采用、结算和复检。正文、规划或事实切版时，025/026 的失效规则会保留旧报告并标出原因。

> 🏠 **白话比喻**：质量报告像验房单，修订候选像施工报价单。验房单不能直接砸墙，业主选定施工方案、验收并复查后才算闭环。对应到系统：问题不会改正文，AI 结果不会自动采用，复检只针对当前采用版本。

> 🧠 **速记方法**：**发现—确认—候选—采用—复检；换稿旧单失效，历史仍保留。**

## F8 稳定读取合同

`GET /api/new-design/books/:id/multiview-workspace` 同时返回：未回收伏笔、仍有效的客观问题、待整理或陈旧章节、待确认事实、失败任务，以及从第一章开始连续通过稳定检查点的可导出范围。该合同只读正本，不依赖 AGE 或 pgvector 是否可用。

跨机器同步时，043 SQL、TypeScript 合同和本文随 Git 同步；作者的实际问题处置、正文、事实、状态和查看偏好属于 PostgreSQL 业务数据，必须通过逻辑备份与受管附件包迁移。
