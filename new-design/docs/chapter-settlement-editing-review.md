## 作者入口和恢复

在本书“章节创作”采用正文并打开“章节结果确认”：按中文对象、正式字段与类型化值填写；人工和 AI 共用待确认清单，逐项审阅后明确结算。知识持有者可选读者或本书人物；字典使用真实正式节点，不要求作者填写英文键或 JSON。

| 失败位置 | 保留内容 | 作者点击 |
| --- | --- | --- |
| 填写或正式规格校验 | 当前输入、原规格与前值 | 提示旁“定位…”；修正后保存 |
| 保存／结算回执未知 | 输入、原请求凭证和已确认结果 | “只读核对原请求结果”；确认前锁住写操作 |
| 服务器确认未写入、规格或前值改变 | 原草稿与新旧差异 | 核对最新清单或前值，明确重新准备 |
| AI 模型配置不可用 | 正文、人工草稿、已有清单；未发模型请求 | “打开模型设置”，返回本章“检查 AI 配置” |
| AI 输出保存成功、候选入库失败 | 原模型输出、上下文与实际用量 | “导入已保存结果（不重新生成）” |
| 候选已入库、运行终止回执失败 | 已保存候选和模型结果 | “完成运行回执（不重新生成）” |
| 旧结果因来源变化无法导入 | 旧结果与实际调用记录 | 明确“保留旧结果并结束本次提取” |
| 未知运行确实过期 | 原领取记录与未知用量 | 先只读核对；满足服务端条件后明确结束过期提取 |
| 关系缺少正式规格或实例版本 | 本书原资料、关系与输入 | 从提示打开本书关系配置，保存草稿并明确发布／勾选实例，返回原章核对 |
| 稳定结果保存后工作台读取失败 | 稳定回执、正式结果与检查点 | 只刷新工作台，不重复结算 |

> 白话比喻：付款回执丢失时先拿原订单查账；货物已送到但签收单没归档，只补归档，不再发一批货。对应到系统：未知写入先核对原请求；已保存模型输出或候选只恢复后续保存，不重复调用模型。

> 速记方法：未知先查，已存只续，换源重审。分别对应原请求核对、恢复后续阶段、明确确认最新规格与前值。

关系配置复用原正式关系类型、能力、维度和实例版本账本；草稿不生效，发布只影响本书。创建／明确重绑实例在同一事务追加真实关系版本及指针，缺版本不能用实例 ID 冒充不可变版本。运行记录页只读，恢复动作放在创作来源页。
