# 知识语义索引执行边界

本模块编排新设计专属嵌入执行，仅引用原知识解析版本、原 `embedding_*` 与 `semantic_retrieval_*` 事实。不是第二份正文、第二套模型设置或新 AI 提示词任务；不扩文字任务与六任务组合。

> 🏠 白话比喻：正文是图书馆原书，向量是按意思制作的目录卡。目录卡损坏可以核对原书，不能改写原书充当修好目录。对应到代码：原解析正文仍在资产版本，模型向量录入原嵌入结果和 pgvector 索引。
> 🧠 速记方法：选连接 → 定维度 → 冻来源 → 存回复 → 入原索引 → 按意思查；配置存在不等于真实执行成功。

## 真实入口和调用

`KnowledgeReferencePage` 挂载 `client/knowledgeIndex/KnowledgeIndexPanel`，位于知识与参考页。中文填写规格名称、明确模型维度、分块长度、重叠字符数，模型与端点引用原模型连接版本。`createKnowledgeProfile` 使用原规格版本的 key/hash/book 技术回执，不调用旧无键配置创建接口。

`prepareKnowledgeIndex` 同事务验证本书可读原件版本、精确解析版本和 SHA-256 校验，分块按 `knowledge.characters@v1` 的完整 UTF-16 字符范围保存。每次最多 20 份来源、64 块，不截断。逐块 `executeKnowledgeEmbedding` 一次发送，无默认模型、自动重试或回退。原结果保存以后才可显式 `buildKnowledgeIndex` 并启用完整分代。

`searchKnowledgeSemantic` 先记录原查询及冻结规格/连接/分代，再实际生成查询向量；检索仅向量权重 1，正文关键词和模糊匹配权重均为 0。显示命中精确解析版本，不自动加入书内引用或改正文。关键词入口仍明确标为原文查找。

## 失败与恢复

| 位置 | 保留内容 | 作者实际动作 |
| --- | --- | --- |
| 规格、分块准备、构建的纯数据库保存未知 | 原完整输入、key/hash 与原事实 | “核对原请求”；“核对并完成原数据库保存”先 GET 已有回执，若存在只展示，否则同一冻结输入/原键幂等完成，不调用模型 |
| 原模型发送未知 | 原请求/尝试、连接和规格版本、租约 | 仅 GET 核对；有超期原尝试才可显式结束，不重新发送原模型请求 |
| 原回复已收到但数据库录入未完成 | 数据库原回复或精确本地执行证据 | “用原向量完成录入”或“用原查询向量完成检索”，不再生成向量；不能绕过租约 |
| 正文或分代已失效 | 旧回复/旧来源/历史结果 | 核对原参考和当前规格；旧向量不补写当前索引 |
| 已保留回复且操作超期 | 原回复及已知用量 | “保留证据并结束原超期…”只结束原技术操作，未成功录入索引/检索，不伪称模型失败未发送 |

初始 claim 只有同锁内成功核对原领取不存在（分块还须完整身份一致、pending、原实际尝试和计数为零），显式记录 absence proof，再加实际 COMMIT 未开始、ROLLBACK 已 ACK，才产生 `KnowledgePreparationError.preparationNotWritten`。锁／原键查询失败、原键已存在冲突、COMMIT 未确认、回滚失败、配置读取后续事务、模型调用和回复保存都不能冒充这种证明。GET 空结果、GET 的事务回滚均不是原写入未发生的证明。

初始领取回滚证明响应丢失时，页面保留原键及冻结输入，不用 GET 阴性解锁。显式“核对并恢复原模型准备”复用原 execute/search POST：只有同锁下确无领取且输入／身份精确一致的首次 winner 可以调用；既有原尝试或查询只返回原回执。该按钮明确提示可能首次领取并调用，不称只读；失败不清原键。查询使用原 expectedGeneration，不能用当前新分代替代旧输入。旧凭证缺冻结身份的情况仍锁定并提供维护导航，不自动补值；这不构成全站恢复验收证明。
