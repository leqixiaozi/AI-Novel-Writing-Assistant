# 全书导演与手动章节生成

## 责任

本模块把已采用的总计划、卷计划、章计划与场景交给新设计自有受控正文任务。手动章节 AI 和全书范围使用同一执行函数、原 `chapter_writing_requests`、原 `ai_tasks` 与原正文候选库。导演只编排范围及执行边界，不拥有采用权，不生成另一份规划、关系、状态或结算事实。

> 白话比喻：导演像餐厅出单员，只按既有菜单逐单送厨房；端出的菜先让顾客确认，不能替顾客签收。对应到系统：范围负责执行顺序，正文候选、明确采用和后续结算分别由原领域保存。

> 速记方法：冻结→生成→保留原回复→保存候选→确认章边界；采用与结算回章节来源页。

## 执行与恢复合同

- 只有来源页明确接受的 `run/resume/retry_failed` 才派发工作。只读 GET、运行记录与轮询不派发、续跑或清除人工暂停。
- 每章原凭证在范围创建时固定；尚未派发的准备恢复继续使用它。已确认失败章的明确重试另建原请求，旧请求、成功候选和未知用量记录保留。
- 使用 `chapter_generation` 注册资产及真实作者路由来源版本。冻结新系统合同不会重发布作者合同，不借用旧网关、旧密钥或改作者默认配置。
- 模型回复必须保留后才导入原候选；选区输出按冻结正文的 UTF-16 起止位置拼回整章，前后原文精确保留。受控原结果接口拒绝未保存回复、另一尝试或任意替换文字。
- 已保存回复的入库／账本恢复不再调用模型。原档案修订变化拒绝迟到入库；来源页可只读查看和复制精确原回复，供作者对照现有稿件明确另存，不自动替换本地稿件。
- 未确认收到模型回复时停止该原请求的自动重试与回退，只读核对。明确结束真实过期原领取，保留原任务事件与未知用量，再允许明确准备新调用；旧尝试不能覆盖。
- 已保存候选的账本补记只完成原尝试，不启动新尝试。章边界确认标记与暂停／重规划状态同一事务提交，避免进程中断后跳过原结构化判断。
- 后台恢复先处理原候选的账本与章边界，然后才处理后续章。显式继续范围可能生成后续章，界面必须说明新用量，不能把整个范围继续描述成纯免模型操作。

## 质量与正式事实

完成优先下，`continue_with_warning` 和局部人工建议作为章级提醒继续。质量优先的 `pause_for_manual` 停在已保存章边界；只有作者明确继续才解除。`stop_for_replan` 保留本章候选并结束旧范围，不用后续未执行章存在为理由继续旧范围。

候选准备完成不等于完本。采用、内容切换影响、变化审阅、结算及稳定章由章节创作页的原链路完成。运行记录仅呈现原范围／请求／尝试的状态、候选进度、警告和来源，不提供工作流操作。

## 模块方向与静态阶段

HTTP 调本应用入口；应用通过数据库领域 facade、Prompt facade 与受控运行 facade 工作。正文领域负责原版本／操作证据；`chapterProduction` 负责同原请求的冻结回复与原账本原子收口；`productionDirector` 数据库域只存技术范围、原请求指针和边界确认。

本轮只完成编码与逐项静态审阅。迁移、类型、测试、构建、模型、启动和 UI 均等待全部授权队列编码完成后统一验证；用例存在不代表通过。
