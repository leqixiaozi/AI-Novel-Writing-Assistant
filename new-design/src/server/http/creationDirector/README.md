# 开书来源 HTTP 边界

统一审阅、逐资料 AI、共用阶段和确认开书的动作属于原开书来源页。运行记录只读查看和跳回来源，不操作阶段或重试。

创建会话、保存表单、正式关系／规划审阅和确认开书携带原请求键；服务端核对真实会话修订、冻结模板、资料身份与完整输入，生成本事务回执。未知写入只能先查询原请求，不从空查询推断未执行。模型输出已保存时只恢复后续保存，不重新调用模型。

> 白话比喻：拿原订单查是否付款，而不是丢了小票就再付款。对应到系统：原请求 GET 只核对，草稿不因失败消失，同一凭证不能换内容。

> 速记方法：凭证管核对，修订防覆盖，确认才正式。

输入不得传任意恢复地址、替代规格或执行快照；来源只允许原开书会话，以及模型设置／运行维护固定页面。错误说明具体步骤、保留结果和实际可点击动作。旧无请求键生成／选方向入口不执行写入；旧结果可在原会话读取，并明确转到共用准备方式继续。

普通资料审阅与生成允许空白标题和必填字段；类型和树范围仍校验。关系、四层规划和跨章事件精确引用由领域／持久化正本验证，不由 HTTP 猜测。正式确认才执行完整必填、采用决定和原子安装。
# 候选恢复入口

单项资料准备与共用阶段准备分别返回真实候选和原命令回执。导演命令回执包含各阶段候选，不能用单项准备请求键去冒充导演阶段请求。

| 原来源页操作 | HTTP 合同 | 后果 |
| --- | --- | --- |
| 核对起点保存 | `GET sessions/by-request/:key` | 只读原起点；空结果仍未知 |
| 核对表单、关系规划或开书保存 | `GET sessions/:id/write-receipts?requestKey=...` | 只读同事务成功回执 |
| 核对阶段切换或人工接管 | `GET sessions/:id/director/commands/by-key/:key` | 只读控制命令，不继续模型 |
| 核对共用阶段准备 | `GET sessions/:id/director/prepare/by-key/:key` | 返回阶段命令与已保存批次，不重发模型 |
| 核对单项准备 | `GET sessions/:id/review-ai/by-key/:key` | 只读候选状态 |
| 恢复刷新后的候选 | `GET sessions/:id/review-ai/batches` | 只读全部本会话批次 |
| 继续保存已有结果 | `POST creation-preparation-batches/:id/recover-saved-result {}` | 无模型调用；完成已有输出保存，或校验完整失败回复后恢复候选。核对原文哈希、冻结规格和会话修订，事务原子保存；不自动采用 |
| 采用勾选结果 | `POST creation-preparation-batches/:id/adopt` | 校验精确对象与字段，填入同一表单；不正式开书 |
| 核对采用回执 | `GET creation-preparation-batches/:id/adoptions/by-key/:key` | 只读原采用结果 |
| 保留旧候选并结束采用 | `POST creation-preparation-batches/:id/release-saved-result {}` | 保留结果，禁止旧批迟到覆盖 |
| 明确结束过期未知运行 | `POST creation-preparation-batches/:id/end-expired-unknown {}` | 不伪造成功或零用量，结束旧批写入资格 |

上表路径均以 `/api/new-design/book-creation/` 为前缀。恢复接口不接受客户端提供规格、数据库连接、来源路由或模型配置；来源由服务端实际会话与批次确定。

> 白话比喻：餐厅已经做好的菜只需要补送餐单，不能因为送餐单没打印又炒一次。对应到系统：保存结果恢复只处理已完成的模型输出，调用模型与后续保存分开。

> 速记方法：未知查原键，已存接后步，勾选填表单，确认建正本。
