# 章节结算工作页 HTTP 边界

本模块承接作者工作页的正式字段编辑与确认，不承接运行记录中的修改动作。路由在研究恢复中间件前挂载，输入校验失败不需要启动研究服务或创建运行记录。

## 合同与所有权

- DTO：`common/chapterSettlementEditing`，独立于大型通用合同。
- 输入校验：本目录 `validation.ts`，拒绝额外字段；正式规格、字典范围、对象归属与基线仍由数据库应用入口核对，HTTP 校验不能替代领域校验。
- 事务／回执：`database/chapterSettlement` facade；同一请求严格比较完整输入，事务内形成成功凭证。
- 展示与草稿：`client/chapterWriting/settlementEditing` 和采用确认面板。

> 白话比喻：门口检查包裹地址不等于仓库签收。对应到系统：HTTP 只核对请求形状，领域入口负责真实对象、规格与原子入账；读取回执才知道是否签收。

> 速记方法：入口验格式，领域验事实，回执验结果。

## 恢复与语义

未知保存只读查询原请求，不自动重新保存或生成；保存成功后的读取失败只重读，不覆盖成功回执。中文失败阶段、字段、保留内容与来源入口按 `docs/wiki/failure-recovery-gate.md`。

本轮“事件对象状态”与“资料关系状态”仅指原状态提案；故事时间、因果与并发仍归 `storyTimeline` 后续多维／P3，不包装成状态值。模型提取尚无专属完整执行能力时明确不可用，不通过任意已发布合同制造“已配置”状态。

旧人工清单写入、决策、结算以及通用直接章节结算 HTTP 入口不能绕过本模块正式规格和原请求核对。旧任意合同提取／结果写入同样禁止。现有读取、正文采用准备与后续专项修订合同不在这里重新实现。
