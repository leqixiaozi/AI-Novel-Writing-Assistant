# 原资源确认历史

本模块只读原确认与原引用，不创建转交状态。公开入口在repeatable-read只读事务核对明确发布关系与完整维度，包含当前已归档关系和资源关联的旧变化。当前持有单独使用原账本的正式来源；原确认、关系归档、数量0或false都不能作为当前持有或已转交的语义判断。

每个稳定检查点只读取一次完整原采用正文／计划／确认来源，历史变化必须逐字匹配确认清单。原关系取变化写入时点以前的确切不可变版本，资源引用使用其确切版本；缺失时保持待核对，不借最新档案补齐。正文证据按真实版本和UTF-16原文核验，已存在的完整性冲突保持待修正。失效记录保留在列表；SQL／读取异常不冒充空历史。最多200个变化关联，超界明确不完整，不能据此作整批判断。

源页明确只读入口已接通。6项真实隔离PG／完整HTTP检查覆盖两章true／false及确切UTF-16正文、原引用、完整稳定确认，重复读取／越书／错误完整规格零写入，资源归档和关系归档保留原确认、当前持有未知，以及正文失效保留记录并拒绝最新投影替代。实际隔离浏览器已展开原确认、逐章变化及确切正文来源，provider调用0，全部正式来源保持。

显示语义交由相邻focus模块的独立v2冻结合同和专属注册AI资产。历史证据按实际故事顺序与确认顺序读取，各字段只使用最新原来源；fieldAvailable须核对完整冻结编辑合同、实际字段、前后值和正文身份。隐藏或显示条件未满足的字段不进入模型；坏的最新来源不能回退较早值。模型不读取完整正文、原始冻结字段或无关认知。转交／淡出建议不能产生正式持有状态，本只读模块始终保留全部历史。

稳定依据的状态全文来自实际PG行，bigint／numeric以字符串保留，时间戳经同一驱动转为JSON；历史变化批量读取实际全文并采用相同表示后比较。直接to_jsonb产生的数字与微秒时间表示不同，不能拿它与驱动归一后的全文哈希比较，亦不能通过舍弃字段或只比ID隐藏差异。
