# 人物资源显示建议

旧版资源页按主角、长期角色、临时角色提供10／6／5条紧凑展示，临时角色关注跨章、冲突、伏笔和转移。角色文字正则不能作为新版业务分类的主实现；专属注册资产以真实已保存人物及资源档案作结构化AI判断。模型输出是作者核对的显示建议，不能产生正式资源状态或读者认知。来源不足保持unknown，不根据名称、0、false或未配置字段补猜。

`sources`在repeatable-read只读事务组合原人物资源账本和专业档案，档案仅冻结已安装、可见且满足显示条件的字段和值。完整账本保留在原记录和来源哈希中；专属资产向模型只发送范围与版本身份、可用性及可见档案字段，不发送原关系填写、状态、认知或条件未满足的账本策划展示值。隐含字段不进入模型上下文。证据使用确切资料版本及字段；文本保持原文，其他已保存JSON值转换为明确证据文本，0和false保留。每项输出必须覆盖完整真实资源／关系范围，证据UTF-16位置必须匹配相应人物或资源，不允许按重名合并或静默省略。

`index`拥有一次领取和执行，使用既有`ai_generation_batches`保存完整原输入、来源、注册提示词版本及模型结果；不新增用户库迁移。原键锁在repeatable-read事务之前取得，避免等待锁的并发请求持有较早数据库快照。原键完整输入一致只读原结果，来源或要求不同保持unknown。领取COMMIT确认丢失不调用模型，模型回复或保存未知不再次生成；原结果读取不重跑、不改角色或状态。真实模型仍通过既有form_assist管理链，保留配置、尝试、用量及未知回复停止规则。

`http/characterResources/focus`仅提供源页预览、明确准备、完整原结果读取和按原记录返回当前人物。后续显示必须重新核对实际来源哈希，再由作者明确采用建议；过期建议保留原结果并显示全部来源，不自动隐藏资料。运行记录只读，不放准备、继续或恢复动作。transfer_plan只是作者计划，不能当作确认转移。

页面明确采用、完整原结果恢复、来源变化退回全部及跨页面凭证保护已接通。双端编译、12项边界检查和真实隔离PG／完整HTTP的6项检查通过；独立临时服务的实际浏览器验证覆盖临时角色5／全部9、响应丢失后只读恢复、刷新保留明确采用及来源变化拒绝采用，provider桩仅调用一次，正式资源与时间来源保持。未作者库安装、现有服务加载、真实模型或用户验收；实际已转移资源的历史来源和长期角色过期范围仍需独立读合同，不能据显示建议宣布旧版资源页或C整体完成。
