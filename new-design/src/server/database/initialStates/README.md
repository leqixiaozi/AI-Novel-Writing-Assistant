# 初始值保存与原版本回执

stateStore 保留公共入口和原状态规则，本模块负责初始值版本写入与回执。新请求可携带 requestKey；它直接成为 entity_initial_state_versions.id，UUID 主键及请求／对象事务锁保证同一输入不追加第二版，不建立另一个初始值账本。没有凭证的旧调用继续使用服务器生成版本 UUID。

携带凭证时，新初始值的 expectedRevision 必须为 0；已有值必须匹配当前修订。保存前验证版本序号与状态修订单调一致：初版序号 1、结果修订 1，后续序号等于原修订加 1。违反此条件拒绝并回滚，不能根据相似值或当前状态猜测原输入。

只读回执按原 UUID 查不可变版本，并由原版本、对象身份、字段、来源事实、作者、备注以及验证过的前置修订还原规范输入及 SHA-256。客户端对保留的完整原输入独立计算哈希，全部匹配才解除重复提交限制。回执缺失不证明未执行；没有原 UUID 的历史未知请求不能用相似值补造成功证明。

保存仍调用原 requireStateKey 与 rebuildProjectionKey，后续变化和快照沿原规则保留；初始值版本不会覆盖已有章内变化来源。COMMIT 开始后发生错误保持 unknown；明确提交前回滚才能返回 not_written。集合逐项保存即时更新已成功项的基线，后续字段失败不重发此前已成功字段。
