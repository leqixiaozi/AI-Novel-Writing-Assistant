# 人物小传经历候选

## 来源与决定

作者明确选择已填写、已发布且允许 AI 读取的文本字段。模块冻结真实人物版本、修订、活跃历史表单、字段文本、事件版本和每人三个候选位置，不根据字段名称猜测小传，不按事件重名合并。注册 PromptAsset `new_design.character.experiences` 产生结构化候选，原文位置按 JavaScript UTF-16 字位核对；未知日期保持未知。

候选是计划安排，不能证明正文已发生、人物持有、角色所知或状态变化。作者明确选择本书事件后，候选只载入原时间编辑器。编辑、预览、保存与独立审核使用 bookComposition 和 storyTimeline 的正常命令。小传不是正文证据：保存为作者人工录入的时间提案，并在原模型批次及采用决定中保存完整 AI 候选出处，不能伪造 `ai + manual` 证据。

## 保存与恢复

既有 049 批次合同保存完整准备输入、冻结来源和输出；同完整原请求只领取一次。已发送但回复未知时保留原领取，来源页只读核对；明确结束未知占用须取得执行锁，保留未知调用及用量，不自动重发。读取、运行记录和来源导航均不能执行模型或恢复工作。

时间预览及保存重新核对原人物版本、文本、表单与引用事件。一个候选只创建一个提案；049 采用记录与 068 完整时间保存回执使用同一物理事务。书级会话锁先于串行化快照，同原键并发返回原回执。提交确认丢失后只能用完整原输入读取原回执，不根据当前最新提案推断原保存成功。

## 边界

对外使用本模块 index.ts；sources.ts 只拥有来源读取与冻结。HTTP 映射不包含业务推断。无需新增迁移，隔离验证只使用新空库、真实约束及模型请求桩，保留数据库。用户库、在线服务加载与真实模型验收单独管理。
