# 结构保存与发布回执

创作表单仍由 `card_group_forms/card_group_form_versions` 保存，开书模板仍由 `template_groups/template_group_versions` 保存。`structure_write_receipts` 只记录原请求、完整输入哈希和当次成功返回值，不建立另一套字段或模板正本。

> 白话比喻：回执像柜台给的取件单，包裹仍在原仓库；同一张单不能改成另一件包裹。对应实现是原请求锁、完整输入哈希与正本更新同一个事务。
> 速记：先核原单，再写正本，最后同事务留回执。

`executeStructureWrite` 保留原内部调用的可选请求键；作者页面每次明确准备时生成 UUID。保存或发布和回执在同一事务中完成，响应对象在 COMMIT 前映射，提交后不再另读目录来决定成功与否。同键同输入读取当次不可变回执，不追加版本；同键不同输入保留原凭证，结果按 unknown 处理，不能把本次回滚理解为原请求从未写入。

只有本命令尚未开始 COMMIT 且物理 ROLLBACK 已确认，才可报告 not_written。COMMIT 中断、ROLLBACK 未确认、取得连接失败均不能用目录为空证明没有写入。只读回执使用原 kind/key，空结果仍 unknown。

`strictFormInputSchema` 只把原表单槽位的简化字段解析替换为完整正式 `FieldDefinition`；保留原分组/槽位范围与引用规则，不修改作者发布合同。未知历史字段不会静默删除或补成正式字段：作者需在表单的“资料关系”中明确选择实际完整的正式关系规格，再保存。

071 仅已编码、已由主任务登记，未应用。用例仅编写，最终统一验证仍待进行；未宣称原版本/事务/触发器已经运行验证。
