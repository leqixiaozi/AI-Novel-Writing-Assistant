# 本书关系规格配置

此模块只管理章节结算所需的关系规格草稿和明确发布，正式类型仍是 `relation_types`，正式能力与维度仍是 `state_relation_capabilities` 和 `state_relation_dimensions`，没有第二套关系状态事实。

草稿像尚未盖章的表格：保存不会改变正式规格；发布是盖章步骤，规格、能力、维度、用户明确选择的实例迁移与回执必须一起成功或一起回滚。判断顺序是“保存草稿 → 核对范围 → 明确发布 → 核对回执”。

`policy.ts` 是共享 HTTP 输入规格与正式字段、字典校验；`catalog.ts` 读取真实本书对象和系统/本书逐维有效配置；`commands.ts` 负责原子事务、精确幂等与回执。对外仅使用 `index.ts` 导出，连接使用章节结算的私有事务基础设施。

系统类型只作为来源，本书发布使用真实本书类型 ID。已有同键本书类型不能暗覆盖，实例必须明确选择实际 ID 和读取时版本。旧字段、初始状态、流水与回执保留；退出结算的维度显式覆盖为派生策略，不删除历史维度。派生策略像把旧栏目留在档案里但不再让作者填写，对应技术上是保留同一维度记录并停用人工结算。

创建或明确迁移实例时，同事务追加已有 `card_relation_versions`，冻结真实两端资料版本、当前属性与状态，并更新实例的当前版本指针。它像档案室给每次办理留一张编号底单；对应到技术上，AI 上下文引用的是确切不可变关系版本，不是只有实例 ID 的可变记录。速记是“改实例 → 留版本 → 更新指针 → 一起提交”。

回执在提交前形成，提交后不重新读取来判定成功。已确认回滚可说明未写入；提交或回执不明只能说明结果待核对，按原请求只读查回执，不自动重复发布。
