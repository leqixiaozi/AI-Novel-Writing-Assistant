# 正式开书审阅与安装

模块只把作者明确确认的开书审阅安装到原正式链：资料仍在 `cards/card_versions`，关系仍在 `relation_types/card_relations/card_relation_versions`，规划仍在 `planning_objects/planning_versions/planning_adoptions/planning_version_references`。没有第二套可生产关系或规划事实。

审阅临时 ID 像搬家箱子的唯一编号：安装后登记每个编号对应哪件真实家具，不凭“椅子”这样的名字猜。对应技术上，审阅对象 ID 精确映射为安装资料 ID 和不可变版本 ID；关系两端、规划层级资料、事件等引用只能沿该映射解析。速记顺序为“审阅 ID → 安装 ID → 精确版本”。

`policy.ts` 是受控 DTO 校验、真实模板中文目录、字典范围和关系/规划领域校验；`repository.ts` 管理私有连接基础设施、统一请求锁、同会话回执和结果不明恢复；`commands.ts` 管理只读工作区、保存与创建事务；`install.ts` 调用原正式关系版本与规划 writer；`adoption.ts` 只采用已保存模型候选，不调用模型。

正式规划层级是故事总纲 → 卷 → 章节 → 场景。事件是资料，通过版本引用关联规划，可跨章节引用同一事件正本，不冒充新规划层。保留子草稿可以精确依据已保存父草稿；采用子规划必须依据父级明确采用版本。空白手工开书不被强迫建立未选择的完整规划；只校验作者实际保留、采用或排除的内容。

开书确认像一次柜台整单办理：安装模板、确认资料、建立关系及版本、保存/采用规划、完成开书会话、留下回执一起提交。对应技术上，所有步骤由同物理事务完成，回执在提交前形成；提交后不再读取来猜成功。原请求输入哈希完全相同才重复返回旧回执，不同输入 409；尚未提交且已确认回滚可明确重新准备，提交不明只能只读核对原请求。

普通资料修改会使原正式审阅来源过期；必须由作者重新核对并保存来源，不能后台默默重定基线。AI 输出保留为待审候选，明确选择的空白字段才可采用，已填人工值不覆盖；关系/规划进入待确认审阅，不自动生效。实际生成来源和回执保留，不把模型生成成功与正式安装成功混为一谈。

自动准备累计结果像把各科检查单装进一个文件夹：最后的文件夹不是每份检查单的出具者。对应技术上，采用会核对冻结 `sourceBatches` 的批次 ID、输入和输出哈希，再沿每个批次真实原始输出与冻结字段白名单解析；字段来源记录原生成批次，不冒充最后规划批次。速记为“累计展示，原单溯源”。明确采用方向时同时保存真实方向候选和选中 ID，不仅填写书名；自动命令仍持有会话期间拒绝普通修改和正式开书，作者先只读核对或明确接管。

最终开书安装不能把“已经采用到审阅表单”误当作来源失效：受控批次显式采用后是 `applied/review_adopted`，不再是 `review`。安装保留原 review 来源校验；已采用来源必须另有同会话不可变采用回执，精确匹配审阅对象 UUID、内容类型、字段键、字段值及其真实批次 ID。没有回执的 applied、跨会话来源或已改值的凭据均拒绝。白话像已签收的检查单仍有效，但必须核对签收单上的本人、项目和数值，不能随便拿“已签收”三个字替代证据；速记是“采用是状态，原票才证明”。

058 只在已有开书会话增加受控原请求、正式审阅和不可改写旧条目的回执列，既有会话与作者数据保留。测试代码由主任务在完整阶段编码完成后集中执行；本模块文档不是测试或真实模型验收声明。
