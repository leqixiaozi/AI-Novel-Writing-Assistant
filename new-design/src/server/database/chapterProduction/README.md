# 原章节请求与受控回复

本域在原章节请求上保存不可变执行输入与模型回复，在原正文域导入候选，并在原 AI 账本记录领取、结果、事件和用量。手动与导演范围调用同一准备和收口方法，不建立另一份正文或正式事实。

> 白话比喻：工单袋中放原订单、配料版本和厨房回单，出菜仍登记在原出餐簿。对应到系统：技术快照及回复是执行证据；正文版本、明确采用和结算仍归原领域。

> 速记方法：正本不搬家，工单带凭证；未知先核对，过期明确结束。

## 固定来源

生成前预览与实际准备共用 `readChapterGenerationSources`，预览事务只读取并回滚，不冻结任务或调用模型。返回完整原输入、资料清单和原来源哈希；作者可以排除本次真实存在的补充卡片，但采用计划精确引用和原作品约定必须保留。提交携带排除 IDs 和预览哈希，准备事务重新读取完整来源，来源变化或非法排除在冻结／模型调用前拒绝；局部值按确切原版本合并，连续性和知识选择保持原读取边界。

双端编译通过，现有章节合同／来源保护单元通过；本次新增资料排除和来源变化实际 PG／页面尚无完整证据，不据静态接线声明全链验收。

准备使用同一可重复读取事务，核对完整总计划／卷／章父链、真实采用版本、未失效场景、本章原采用合同及卷版本依据。精确规划引用读取原资料版本与动作，不以当前另一资料版代替；读取不完整或超过冻结上限明确报错，不静默截断。输入正文必须属于原书原章及精确版本，选区与原保存正文匹配。

每个新原请求冻结一个系统合同、配方和书级模型快照；只读取作者已生效路由，不改变配置、不借旧网关。重复原输入保留同原 key／hash／请求，不能把它当成新调用；手动操作的原输入 hash 与原 API 输入一致。

同一事务由 `continuitySources` 读取已确认事实、当前有效流水、人物认知、初始状态、正式关系及紧邻前章稳定采用正文。显示投影只用于找原来源，正式哈希取原依赖解析器；初始状态不冒充章节结算，后章来源不能当作此前状态，缺失前章明确说明且不改取较旧章。六类来源各有完整冻结上限，总量超限明确拒绝，不能静默裁剪。

`knowledgeSources` 只读取本次明确选择的原件／解析版本／完整哈希。准备时核对本书、真实成功解析、有效原依赖状态及完整正文；保存进相同 Prompt 输入、消息与上下文条目，不把 asset mount 当作实际模型引用，不复制知识正本。版本失效时返回知识参考明确重新选择，不自动换版。

## 租约与不可变结果

运行锁序统一为 task→step→attempt→request。回复首次入原请求必须是原当前 live attempt；已保存回复不可改写。受控正文候选必须精确等原回复还原的整章内容，来源、操作、原选区前后边界及原尝试均核对。选区使用 JavaScript UTF-16 位置，数据库不以 PostgreSQL 字符位置替代；冻结的前后边界支持数据库整章内容校验。

候选入库拒绝档案修订冲突；它不覆盖正式正文。账本补记依赖已保存候选、原尝试和精确结果证明，即使领取已经过期也只补原不可变结果，不创建尝试、模型调用或新的正文。

模型未知结果保留原尝试供只读核对；明确结束真实过期原领取才将其 discarded，并同一事务取消原步骤／任务／请求、保留原事件和未知用量。已保存原回复不能走“结束未知领取后重生成”。终态原尝试及结果不接受迟到覆盖。

尚未领取的 queued 原请求须核实任务／步骤 queued、无当前或历史尝试，才可明确结束未领取请求。已保存回复但人工修订冲突挡住入库时，可只读查看复制，或明确“保留原回复并结束导入”：原回复不删，真实用量和取消事件入原账本，不导入、采用或再次调用模型。已有候选不能用此动作跳过账本补记。

## 事务回执与失败说明

只有 COMMIT 之前的失败且收到 ROLLBACK 确认，才报告本次数据库 mutation 未写入。开始 COMMIT 后回执丢失属于 unknown。GET 未读到回执不是未写入证明，GET 不派发或解除暂停；读失败不能撤销已经确认的保存结果。

模型执行失败与回复保存失败分开处理。已收到回复但持久保存失败不能被描述成模型未调用，更不能再次生成以填补旧记录。用户可在章节来源页读取精确原回复；不能用其他候选或模型成功记录代替。

066／069 及当前编码尚未运行迁移、类型、测试、构建或模型验证。所有动态验证等待授权队列全部编码完成后统一执行。本地原回复凭证需与数据库逻辑备份一同保存 `data/ai-receipts`；本轮没有执行备份或写入实际凭证。
