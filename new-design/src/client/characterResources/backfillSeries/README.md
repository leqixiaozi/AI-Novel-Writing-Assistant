# 最近章节资源候选

作者明确最近三章／五章和完整资源范围，先只读预检全部所选确切采用正文，再按实际章序依次准备候选。稳定章使用普通独立补充创建合同，可编辑章沿原清单；既有冲突修正清单不混入普通批量。没有自动确认、正式保存、取消清单或清除冲突。

`preflight.ts`通过已有公开API读取实际来源，每章发送前重新核对正文、清单修订和完整冻结范围。预检最后一章失败时零创建／零模型调用；批次开始后的来源变化只阻止后续请求，原清单和候选保持。通用结算的resource_supplement关闭提示是普通正式结算保护，专属补充仍必须验证完整冻结普通来源，并通过原受管候选合同；不得移除正常会话门禁或把修正模式当普通资源回填。

`controller.ts`持久完整范围与每一步原输入。独立创建／候选生成前先保存pending状态，再发请求；结果保存失败保留原pending凭证并停止后续。未知结果恢复只读取完整原创建／AI合同，不能当作不存在授权重发。只读核对完成后停在ready，剩余章节需要作者明确继续；恢复页面不调用模型。结束ready范围保留全部原清单／已保存候选，不自动取消。

父资源页面始终创建恢复控制器，pending／ready／坏凭证重新打开页面后必须显示原范围恢复入口并锁定人物、范围和其他写入；不能把恢复表单藏在禁用按钮之后。进入新范围前保留旧完整结果的历史副本，不能覆盖原凭证。离页返回的旧回复不写入新人物范围。

所有章节的AI原键在完整范围第一次保存时预先冻结，不能在继续某章时重新生成。来源页以书籍／人物范围的浏览器独占锁串行执行创建、核对、继续和结束；写进度前比较原完整存储帧，旧页若发现同一原范围已更新只读取新进度并停止当前操作，不覆盖已经完成的后续原命令。原范围身份或冻结输入不同则停用旧页。浏览器锁不可用时零发送，不降级成无锁批量；正常后端同完整原键的受管幂等保护仍是模型调用的最终边界。
