# 作者知识语义入口

原知识与参考页实际挂载本模块，四步中文工作流：明确保存规格 → 选择原解析正文并准备分块 → 逐块生成/启用原分代 → 按意思检索。模型与维度必须明确选择，关键词查找不伪装语义检索。

> 🏠 白话比喻：失败提示像快递状态，分别告诉你“未发件”“运输回执未知”“包裹到达但尚未入柜”。对应到页面：failedStep 定位阶段，savedResult 说明保留内容，按钮只能核对原请求或完成同一已保留结果。
> 🧠 速记方法：先核原单，再用原件；未知不换单号，未保存不跨书覆盖。

`pending.ts` 保存原完整 payload 和 SHA-256；分块冻结原来源、分块、规格与连接版本的完整身份，查询冻结原问题与精确索引分代。存储不可读取、hash 不等、原回执与 scope 不等保持锁。profile/prepare/build 三个纯 DB 原操作允许作者显式核对并完成保存，先 GET，存在只展示，否则同键原完整 payload。回复本地证据明确不同于 DB 录入，完成恢复不生成新向量。

书籍代次阻止晚到回执跨书更新；onLockChange/onDirtyChange 接入原页切书和离开保护，命中原文按钮只选真实加载目录中相同 assetId+parsedVersionId。绑定/归档草稿尚未处理时不切另一参考。最近三份原准备批次可续看，不重造替代批次。

初始 claim 回滚证明响应也丢失时，阴性 GET 不解除锁。作者可明确点击“核对并恢复原模型准备”并确认后果：服务端在同锁内核对完整原身份／输入，只有确无领取且真实尝试为零的 winner 才能首次调用；已有尝试只返回原回执，绝不再调用。恢复失败仍保留原键和完整输入，不能改成新键。保存回复完成／超期结束也保留原调用元数据，不补成当前版本。

旧凭证缺完整身份或原存储损坏时仍阻写；运行维护导航不承诺读取知识浏览器凭证或自动修复，不清除、替换或自动解锁。可读原凭证仍在知识来源页按原请求GET核对。本批完整知识上传／分块／桩向量／索引／语义隔离PG通过；设置与索引页签共用保持挂载的原组件和请求控制，不丢输入／回执。编译通过，实际页面布局回看和真实模型／作者环境验收待验。
