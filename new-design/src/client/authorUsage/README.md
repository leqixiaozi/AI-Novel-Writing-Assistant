# 作者原运行用量

实际入口是运行记录 `AuthorTaskCenterPage` 右侧所选记录详情，直接挂载 `AuthorUsagePanel({record})`；调用原 `newDesignApi.summarizeAiUsage`，不增加页面路由、账本或计费接口。公共只读范围／呈现合同为 `common/authorUsage`，原 SQL 聚合位于 `database/aiTasks/usageProjection.ts`，原 `summarizeAiUsage` 仅消费该投影。

> 白话比喻：拿某一张购物小票查这次消费，或者拿会员号查这家店已有的小票，不能用一张小票冒充整月消费。对应系统：原 AI 任务详情用真实 `taskId`（有书时同时限 `bookId`）；其他书内领域记录明确读取本书全部原尝试，不冒充此条导演范围的单独用量。没有正式书／原任务引用时不请求全局摘要。

> 速记方法：原任务看原尝试，本书看全书账；没有范围不查全局。

## 用量与费用语义

只读原 `ai_tasks → ai_task_attempts → ai_attempt_usage`，原尝试与已有用量行精确关联。`attemptCount` 保持已有用量账本行数量；新增 `totalAttemptCount` 为真实原尝试数、`unrecordedAttemptCount` 为暂无账本的尝试、`unknownCostAttemptCount` 为暂无费用记录的尝试；`unknownUsageCount` 仅指已有账本但输入／输出数值不完整的尝试。没有把尚未写账本的在途调用计成已知零。

显示已知输入、输出、缓存输入及执行时长，未知保留 `null`。若存在未完整／未记账尝试，累计已知数只是已保存部分，不宣称总实际用量；空摘要不证明没有调用。预算、配置已生效也不代表真实模型执行已验收。

> 白话比喻：还有小票没拿回来时，手头小票合计只是已知部分，不能认定其他人没花钱。对应系统：SQL 的已知 Token 合计与未知／未记账原尝试数并排显示，未知不补零。

> 速记方法：已知计已知，缺票保未知；预算不是实际消费。

只显示原账本已有的同币种费用估算，不查询价格、换汇或推测收费，也不称实际账单。金额／币种缺失或多个币种不能合并时显示未确认，未知费用不以零元代替；真实账本记录零值则可显示零。无规范公开币种的内容不透出原任意字符串。

## 只读、失败与竞态

唯一操作是刷新原用量及打开当前准确来源链接；不恢复任务、不重发模型、不探测模型、不采用正文、不记账。读取错误固定中文显示阶段、保留原结果与实际按钮“刷新用量”，原来源链接仍可点击。请求代次／卸载状态／精确范围键避免迟到回复覆盖别书或别任务；同范围刷新失败保留此前已读数据，不能假称原写入失败。

原模型回复 spool 仅有本地证据而原用量行尚未入库时，SQL 此尝试显示未记账，不能把它当作零调用。此面板不读取本地正文凭证，也不完成未写账本。真正恢复仍去原来源页核对同一凭证和影响。

沿用现有主题变量、正常字重与平面明细，两列在窄屏变单列；文字状态、`aria-busy`、告警及键盘焦点不依赖颜色。
