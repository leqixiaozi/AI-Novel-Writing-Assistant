# 完本与原导出来源

`CompletionExportPage` 负责完本检查和新的导出预览／明确提交；`ExportHistory` 负责已有请求的只读选择、清单检视、刷新及已完成文件下载。两者不共享可提交的清单状态，历史记录不能填进新的提交预览。

新提交在发送前按本书保留确切清单、来源哈希、作者与幂等键。响应未知及刷新恢复仅通过原键读取回执，空查询不证明未执行；原结果未确认时不发送另一任务。服务端仅在确认事务未提交且回滚收到确认时返回未写入证明，提交边界或并发结果未知则保持锁定。来源改变不妨碍查询已提交原回执；重复凭证必须匹配原清单与作者。改选卷、章节或附带版本清单使可提交预览失效，原导出记录仍保留。

来源 `?export=<UUID>` 通过 `common/authorTasks` 严格查询合同解析，拒绝重复／空参数。只匹配当前加载 `workspace.exports` 中同书籍的实际请求，同时核对文件请求及清单身份；缺失／跨书／来源不一致必须明确未匹配，不能自动选第一条代替。

刷新仅读取工作区，不清空导出设置、完本说明、选章或预览。异步代次隔离旧书迟到响应；可提交预览须属于当前书籍。草稿离页由 `beforeunload` 提示。任务失败显示生成文件阶段、冻结清单与正文保留及核对原回执的入口；不显示技术错误文本，不重发原请求。

> 白话比喻：旧快递单放在“查询快递”窗口，不拿它填入“寄新件”的表单。对应到系统：原请求检视和新导出提交严格分离，不重复原任务。

> 速记方法：原回执只核对，新预览才提交；缺失不代替，草稿不覆盖。

研究页的对应规则：`ResearchRecordsPage` 用 `record/version` 定位同记录的运行历史；`ReferencePacksPage` 用 `book/adoption` 定位同书候选，未保存提案通过可选 `onDraftDirty` 通知父页，切书／切批须明确放弃或保持，刷新不得覆盖。保存说明和采用必须各在原来源页执行。
