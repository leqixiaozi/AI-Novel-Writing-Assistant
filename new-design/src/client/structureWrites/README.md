# 结构页草稿与原请求恢复

模板组/创作表单页使用原结构正本，列表刷新只更新目录，不替换当前填写。选择另一项或新建时，未保存草稿必须明确确认放弃；晚到目录、模板版本和升级预览响应按来源代次过滤。内部稳定标识由 UUID 生成，仅在高级只读信息中显示。

> 白话比喻：编辑像桌上的手稿，重新查目录不能把手稿换成别人的打印件；原请求凭证像挂号单，回执没找到也不代表挂号从没发生。
> 速记：换项先确认；响应先核来源；未知只读原单。

保存/发布发送前把原稿、原 UUID、操作和修订保存在本机 sessionStorage。发出后未知只调用 `getStructureWriteReceipt`，原稿和输入冻结，不生成新键。仅服务器明确本事务 not_written 才允许重新准备；GET null 保留锁。成功返回和原回执需核对种类、操作、ID、稳定标识、原定义及真实修订；JSON 对象键顺序不作为内容变化。存储失败同步锁定，原凭证清理失败保留已确认结果和实际恢复提示。

表单保存冻结前仅按正式字段 schema 的既定 defaults／trim 规范化，原raw另存；不补 order、字典必需规则或其他未知规格。重开原raw须与冻结稿同 ID／修订及完整规范化结构，坏记录保留并锁定。旧pending没有raw时不重写原输入／原key，回执匹配只规范化两个副本比较；发布仍用原输入与原修订。规范化不是内容放宽或正式规格升级，扩展属性不得静默丢弃。

原模板升级复用 `book_template_syncs`：发送前冻结原 syncId 和来源版本，只读 `getBookTemplateSync`。已应用/明确终止的原记录可确认；仍待应用或空结果都不证明未知请求已终止，不重新应用。目录读取不能充当升级回执。没有新增升级事实表。

ContextRun 同样核对原书、原合同/节点/来源、输入、checkpoint、预算；提交还核对完整原冻结身份、submitted 状态、真实 aiTaskId 和修订。不使用当前合同代替原冻结合同，旧凭证缺精确身份时保留阻断和维护入口。

这些保护已编码并静态审阅；用例未执行，071 未应用，浏览器/事务验证均留最终统一阶段。

专业维护页的来源重读同样不能替换 dirty/locked 的原编辑视图；当前对象从新清单消失时保留原视图并要求明确选择，不自动换成第一项。无效 selected 来源参数终止读取提示，不把正在读取的状态留住。
