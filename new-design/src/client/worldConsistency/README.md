# 世界检查来源页

`WorldConsistencyPanel` 已由 `WorldCharacterMaintenanceView` world 模式实际挂载，复用原主题变量与同一 BusinessFormWorkspace。作者选中文正式资料／关系，明确检查，审阅原质量问题，逐项采用到原草稿，正常保存后明确记录正式修复，再选原证据范围复查。

> 白话比喻：页面是会审桌和档案窗口之间的指路牌，不是自动改档案的机器。对应到界面：每个候选要作者明确采用，保存仍用下方原表单按钮，检查不会覆盖填写。

> 速记方法：选来源、看证据、填原表单、核原保存、再复查。

原 key/full payload/hash 在 sessionStorage 保留；坏凭证锁写，不补当前版本、不用同名资料替代。未知只 GET 原键；已存结果恢复不二次模型。历史精确回执可读，并经作者确认跟踪原请求，不自动调用。候选多字段可先逐项进同一卡草稿再一次保存；刷新后真实 normal-save receipt 可读后明确记录，不制造回执。

精确 `check` 查询只允许单个原请求 UUID。原请求 GET 独立于当前目录读取，即使当前规格或关系不可用仍可显示原执行证据；找不到则明确原来源不可读，不用首项替代。坏凭证维护链接只导航到运行维护，不承诺该页读取／修复 sessionStorage。原正常修复登记只有精确 candidate、登记 key、正常保存 key 和合法版本回执才解除未知锁。

BusinessFormWorkspace 修复采用核对正式原字段，而不是展示分组／排序后的字段；异步 hash 完成前后核对 scope/版本/当前值并忙锁，迟到结果不能覆盖切书、切卡或新填写。正常 save 仍重新验证正式规格、字典及原 revision。

正常保存与登记是两件事。作者修改建议后的真实正常保存值可读取；登记前明确确认追加 `source=user` 不可变原候选版本，原AI版保留，after 由服务端真实回执取值，不接受客户端传值。登记未知保留原key/完整payload/hash；恢复按钮先GET核对，既有精确回执只读接受，否则作者明确完成同一纯DB登记。登记明确回滚也不清原凭证，不撤销正常保存，不调用模型。

frontend-design 采用既有功能主义布局、原主题颜色、正常字重与44px按钮，不新增主题、图片或服务。当前未浏览器运行／视觉验证、未构建或测试；中央 typed API 尚由根统一接线。完整边界见数据库 README。
