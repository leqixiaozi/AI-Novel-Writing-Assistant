# 旧版功能价值迁移与新版重构设计

## 目标与完成口径

新版要逐项承接旧版面向作者提供的有效业务价值，并尽量保留已经成熟的业务判断、前置条件、状态流转、操作结果和恢复逻辑；页面组织、接口和数据承载则按新版产品目标、信息架构和技术底座适配。旧版负责说明“作者过去能解决什么问题，以及业务如何运转”，但不要求新版拥有相同页面、菜单、URL、接口或表结构。只有旧逻辑依赖旧底层、与新版正式合同冲突，或被证明确属缺陷时才调整，不能因为新版设计不同就随意重写业务含义，也不能在没有新版等价方案时静默删除旧能力。

新版继续作为独立系统运行。迁移对象是作者能够完成的任务、需要看到的状态、最终得到的结果、失败后的解释和恢复能力，不是旧版 React 组件、Service、SQLite 表或内部兼容代码。

一项旧版能力只有同时满足以下条件，才能记为新版已补全：

1. 作者能从新版清晰入口完成同等目标，并能通过新版深链回到准确对象；不要求保留旧 URL。
2. 页面读取新版真实正本，不用静态示例、测试桩或旧版接口伪装结果。
3. 创建、编辑、生成、采用、恢复、归档或导出等可见操作具有完整回执。
4. 刷新、中断、重复提交、来源变化和无效深链都有确定行为。
5. 候选、正式采用、来源版本及下游影响遵守新版数据合同。
6. 代码、隔离验证、作者环境启用、真实模型效果和用户页面验收分别记录，不互相替代。

## 新版优先的适配原则

1. **先定新版业务正本，再映射旧功能。** 资料、规划、正文、事实、状态、运行和衍生产物分别进入新版既有领域，不为旧页面另建平行正本。
2. **旧业务逻辑默认保留。** 旧版的校验条件、操作顺序、状态变化、失败语义和最终结果是移植基准；能直接映射到新版合同的部分不重新设计。
3. **功能等价不等于页面等形。** 保留作者目标、业务规则、必要信息和操作结果；菜单、页面数量和布局可以按新版主线重新组织，步骤变化必须有底层约束或体验证据，不能只因偏好而改变。
4. **减少分支。** 多个旧入口若解决同一任务，应合并为新版的一个主入口，通过上下文和模式承载差异，不把历史导航结构原样扩张到新版；合并入口不能合并掉原有业务状态或操作结果。
5. **候选与采用优先。** 旧版直接生成、覆盖或自动设为正式内容的行为，改为新版候选、明确采用、来源冻结和影响结算；安全边界优先于逐按钮复刻。
6. **恢复与可追溯优先。** 旧版只有“重试”的地方，按新版原请求键、冻结输入和原回执恢复；未知结果不得换键重发。
7. **只修明确问题。** 重复页面、失效兼容代码、无生产调用分支和依赖旧数据库的行为不迁移；无法理解的旧逻辑不能先判作缺陷，须先追踪它的调用方、状态和用户结果。
8. **每项差异可解释。** 对标矩阵同时记录旧版能力、新版方案、保留的旧逻辑、必要调整及验收结果；“底层不同”不能成为删功能的理由，也不能成为机械照搬的理由。

### 四层迁移口径

| 层次 | 默认处理 |
| --- | --- |
| 用户目标与功能范围 | 完整保留；旧版能完成的有效任务，新版必须有可发现的对应入口 |
| 业务规则与状态流转 | 尽量沿用；逐项映射前置条件、状态、错误、恢复和最终结果 |
| 页面流程与交互布局 | 按新版信息架构适配；只在不损失业务语义时合并入口或缩短步骤 |
| 数据、API、模型与任务运行 | 使用新版独立底座重建；不得调用旧版运行系统作为捷径 |

## 范围定义

### 纳入范围

| 业务域 | 需保留的用户价值 | 新版承载方式 |
| --- | --- | --- |
| 首页与创作向导 | 首次模型配置、创作里程碑、唯一下一步、失败恢复、从灵感／市场／拆书开书 | 新版首页、开书会话、任务模型路由和来源版本 |
| 小说与书架 | 搜索、筛选、排序、分页、继续创作、阅读、封面、任务状态、回收站、简易／专业／短篇入口 | 新版书籍、采用正文、视觉资产、导演投影和原任务回执 |
| 书内创作 | 方向、故事、世界、人物、卷章规划、正文、质量、历史、多维视图、完本导出 | 现有八步主线和折叠辅助工具；不增加第二套书内流程 |
| 创作中枢 | 持续会话、书籍绑定、状态查询、失败诊断、改文影响分析、正式入口导航 | 新版只读诊断 Agent；写入动作回到对应业务工作台 |
| 研究与知识 | 市场雷达、拆书、研究记录、参考包、文档上传解析、索引、引用和归档 | 新版研究版本、知识来源版本、明确入书和精确段落引用 |
| 公共创作资产 | 题材基底、推进模式、标题、写法、反 AI 规则、人物、世界、视觉资源和提示词 | 新版公共资料、策略、提示词资产及不可变版本 |
| 世界样本 | 独立创建、AI 生成、世界手册、势力／地点／规则／关系、导入本书和双向同步 | 公共世界根档案、世界包、安装映射和同步命令 |
| 漫画工作台 | 来源提取、分集大纲、整话分镜、角色／场景设定与图片、分格成图、采用和导出 | 独立漫画项目、不可变候选、采用事件、图片版本和导出 manifest |
| 短剧工作台 | 来源、改编策略、分集、台本、质量检查／修复、分镜、视频提示词、任务和导出 | 新版独立短剧项目及版本账本，不借用旧版短剧表 |
| 运行与设置 | 运行记录、导演跟进、模型厂商与任务路由、知识连接、问题策略、维护和界面偏好 | 新版模型连接、任务路由、只读运行投影及专业命令 |

旧版短剧入口虽然曾在菜单中禁用，但仓库中已有可使用的工作区和业务合同。基于“旧版有的都要”的决定，新版承接其有效业务能力；页面、流程和数据按新版衍生创作合同重构，不继续保留灰色占位，也不照搬旧工作区结构。

### 不原样复制的内容

- `/chat-legacy`、重定向地址、废弃兼容分支和无生产调用的旧代码不逐条移植；其中仍有效的持续会话价值统一进入新版创作中枢。
- 不导入旧版业务 Service，不从新版调用旧版 API、SQLite、Prisma、模型配置或运行任务。
- 不把旧版直接写入行为带入新版。AI 输出仍先形成候选，作者明确采用后才进入正式来源。
- 不以旧版表结构决定新版表结构。页面和结果兼容，正本、版本、采用与回执按新版领域设计。
- 不为追求菜单数量或页面外形一致而恢复重复入口；新版只有在完整保留旧业务逻辑和操作结果时才能减少步骤，并在对标矩阵记录差异。
- 本轮目标是本地源码功能完整；桌面安装、打包、跨机器迁移、推送和部署仍是独立交付任务。

## 信息架构

顶层导航不复制旧版侧栏，而是按作者目标收敛为四组，避免把每项能力都变成并列主入口：

1. **开始与创作**：创作首页、我的书籍、创作向导、创作中枢。
2. **衍生工作台**：漫画工作台、短剧工作台。
3. **资源与研究**：创作资源、标题、研究与分析、知识与参考。
4. **运行与设置**：运行记录、导演总控、模型与高级设置。

书内继续使用现有八步工作流作为唯一主线。世界、人物、人物试聊、视觉资产、资料、知识、历史和专业图形属于当前步骤的辅助工具，默认折叠，不再创建平行创作主线。页面切换优先复用持续存在的应用壳和书内侧栏，只替换内容工作区；无效深链明确报错，未保存内容继续受离开保护。

## 业务与技术边界

### 页面和接口

- 新版页面只通过 `/api/new-design` 调用 `new-design/src/server/http/`。
- 每个旧版可见操作在新版应落到一个明确的查询或专业命令，页面不得直接拼接数据库写入。
- 运行记录和创作中枢保持只读；重试、恢复、采用、生成和导出回到原业务来源页。
- 长任务必须提供原请求键、冻结输入、当前状态、最终回执和原键恢复；未知结果不得换键重发。

### 数据语义

- 公共资源与本书资料分别拥有稳定身份；导入时冻结来源版本，不共享可变正文。
- 故事、卷、章、场景、漫画分集、漫画分镜、短剧分集和台本都使用不可变版本与明确采用事件。
- 正文、图片、视频提示词和导出产物分别有自己的版本账本；生成回复不能直接充当正式资产。
- 人工编辑与 AI 结果走同一候选／采用边界，来源变化触发失效或待复核，不静默覆盖作者内容。
- 新增结构只编写增量迁移和运行包清单。迁移文件准备完成不代表获准安装到作者数据库。

### AI 与提示词

- 新增 AI 能力必须定义新版 `PromptAsset`、任务类型、结构化输出、上下文策略和模型路由。
- 创作中枢的模型只能调用只读诊断工具，不得绕过工作台生成或保存正文。
- 漫画与短剧的提取、规划、分镜和提示词任务分别冻结其小说／项目来源，不能使用当前页面临时文本冒充正式来源。
- 图片或视频供应商未配置、响应中断或结果未知时保留原输入与原请求，只提供核对或在原键上恢复。

## 实施顺序

所有工作继续留在当前功能分支，按完整业务模块形成提交，不为每个页面再开分支。

### 第一阶段：完整功能矩阵与共用合同

- 从旧版菜单、路由、页面操作和服务合同生成唯一对标矩阵；每项同时写明旧业务逻辑、新版承载位置、直接沿用部分和必要调整理由。
- 将现有“已编码／部分／待验证／缺失”重新按可见操作归类，删除仅靠页面存在得出的完成结论。
- 补齐跨模块共用的请求恢复、版本采用、附件、导出和任务投影合同。

### 第二阶段：全局入口与创作中枢

- 补齐创作向导、首页下一步、模型未配置门禁和跨来源开书入口。
- 实现新版创作中枢的会话、书籍绑定、只读工具、诊断结果、影响分析和来源导航。
- 完成世界样本的独立创建与生成工作区。

### 第三阶段：小说与公共资产差项

- 逐项闭合书架、封面、简易／专业创作、短篇、正文编辑、任务恢复和导出差异。
- 对齐题材、推进模式、标题、写法、反 AI 规则、人物、世界、视觉资源、提示词及设置页操作。
- 保持八步工作台唯一主线，不因补功能增加并行菜单分支。

### 第四阶段：漫画完整产线

- 接入 AI 来源提取、分集大纲和整话分镜候选。
- 接入角色／场景视觉生成、分格图片、批次状态与历史版本。
- 完成项目级预览、问题定位、重新生成、明确采用和导出。

### 第五阶段：短剧完整产线

- 建立独立项目、来源冻结、改编策略、分集和台本版本。
- 接入质量门禁、修复候选、分镜、视频提示词及供应商任务。
- 完成可追溯导出和从小说稳定版本继续改编的入口。

### 第六阶段：统一调试与测试

- 开发期间为新增合同编写针对性单元和隔离数据库测试，但在各模块接线完成后统一执行构建、边界检查和回归。
- 覆盖空状态、已有数据、运行中、失败、未知回执、来源变化、无效深链、刷新恢复、未保存保护和重复提交。
- 在 1280、1440、1920px 检查 PC 首屏、持续导航、正文工作区和衍生工作台；移动端按已有响应式合同回归。
- 浏览器逐项验证全部主菜单、书内八步、辅助入口、漫画、短剧和创作中枢。真实模型质量、作者数据库安装和用户最终验收分别执行。

## 验收与交付

最终交付应能从一条矩阵追溯每项旧版用户价值的新版入口、数据正本、操作命令、恢复方式、适配理由和验证证据。旧版页面被合并或流程被优化不算缺失，前提是作者能在新版完整实现相同目标，并且调整有明确依据。以下情况不能称为已完成：

- 只有菜单、路由或空页面。
- 只有迁移、API 或测试桩，没有页面操作闭环。
- 只能创建候选，不能查看版本、采用、恢复或处理来源变化。
- 通过旧版服务、共享数据库或代理接口获得结果。
- 只追求界面或按钮一一对应，却绕开新版正本、版本、采用和恢复合同。
- 编译通过但关键用户操作未验证。

功能源码补全后再统一调试和测试。实际作者数据库迁移、真实模型调用、推送、合并、桌面打包和发布均须获得对应的单独授权。

## 2026-09-21 实施状态

漫画完整视觉产线和独立短剧产线已按新版底座完成源码接线，对应手动迁移为 `117`—`122`。漫画覆盖视觉候选、分格成图、采用、气泡与导出；短剧覆盖来源、策略、人物、分集、台本、质量、修复候选、分镜、媒体提示词与四种导出。未配置或未安装的媒体供应商端口会返回明确不可运行状态，不用模拟结果占位。

本状态只说明实现文件已经齐备。遵循“全部功能做完再统一测试”的要求，构建、类型检查、隔离数据库、回归和浏览器操作将在最后阶段一次执行；`117`—`122` 目前不安装作者数据库，也未调用真实模型或外部媒体供应商。

首页与创作中枢的剩余用户价值已按新版底座补齐源码：首页在唯一推荐之外显示需要作者处理的提醒和最近作品；创作中枢可从本书、章节和运行记录带精确绑定进入，复用相同范围会话，并提供归档恢复、正式阻塞、原来源、唯一下一步和每轮冻结证据。它不复刻旧版的业务写入、审批和自由分支，这些操作继续回到新版正式工作台及不可变回执链处理。
