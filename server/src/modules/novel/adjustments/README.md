# 可选人工调整边界

本模块将明确启用的作者要求、候选和交接接入原小说流程。未携带调整合同的请求保持旧业务含义。

候选与编辑版本不写 Chapter.content；正式采纳才调用原事实提交与同步。DirectorArtifact 记录来源依赖，NovelSideEffectJob 承担持久同步，没有第二个任务引擎或事实库。

人工接管在短事务中提升章写入许可 epoch。运行在开始时捕获 epoch，完成回调必须恢复同一上下文并在业务事务内校验；完成交接不能重新授权旧运行。模型调用不得包含在事务内。

> 白话比喻：旧送货单可留档，但地址变更后不能继续用旧单派送。速记：候选留档，采纳入账，旧单失效。

卷段人工调整由 `BookArrangementVolumeService` 编排，`ArrangementVolumeAdapter` 接入原卷文档与 `persistActiveVolumeWorkspace`。草稿字段 `volumeEdits` 可选，卷预览与后续写作要求候选分开；旧保存／生成合同不增加必填参数。预览只读取原资料并保存候选，不调用会自动激活或补全规划的入口。

正式应用在同一事务内完成版本核对、交接与同步校验、原卷版本保存、授权卷归属更新、旧写入许可失效、所选草稿消费和回执持久化。底座持久化函数的可选 `affectedVolumeIds` 仅供明确范围的新合同使用，默认调用仍处理完整原文档；未授权卷及其 Arc 兼容记录不得被局部调整重写。跨卷移动保留原章节规划 ID 与任务资料；移出且没有归入其他卷的链接保存在调整前卷版本，正文和实际章序不变。

影响预览列出原人物职责、关系、场景、事件和导演资料；结构检查不能代替剧情审核。修改卷的节拍表和关联重平衡建议需重新核对，不用全书人物重建或新增模型调用代替作者的范围授权。

> 白话比喻：换一间教室的课表，只改授权课程的安排，历史课表留档，教材不改。速记：限定卷、留原单、核冲突、一次生效。

对象编排由 `BookArrangementObjectService` 接入原事件、场景、关系阶段和线索表。详情返回原对象与来源，候选保存修改前后内容及真实引用；只有应用才写原表。事件删除记为取消、线索删除记为放弃、关系安排删除记为停用；这些操作保留历史引用。章节提取关系、历史场景计划及 `ForeshadowState` 快照只读，预期回收日期不能转为已回收事实。

场景跨章调整保持场景 ID，仅重排涉及的两个章计划，并同步相关章 `sceneCards` 规划字段。原场景卡预算和细化约束保留；对应字段发生明确修改时才同步该字段，候选保留旧章场景卡与旧计划。随后记录底座原有的 `executionContractHash`，让 `PlannerService.ensureChapterPlan` 复用作者场景；其余原始计划 JSON 保留为来源记录。章节执行要求随后变化仍触发原重规划规则。删除或移走本章最后一个场景会被拒绝，已有完整预算的章须满足原 3–8 场景约束。没有完整预算的旧计划仍保留明确场景资料，不伪造字数预算。

应用核对对象与引用版本、相关章节锁定、运行、接管、同步待办和写入许可。时间线约束的事件／线索引用也进入依赖和范围保护，无章归属的全书约束覆盖全部章节。受影响的非用户保护章节任务单、保留合同和审核资料标记失效，同时更新小说版本与批次缓存；正文、事实快照、非场景执行材料及其他规划不会自动改写或自动重新审核。事件和线索修改后的关联剧情仍须通过原核对／修复入口处理，影响预览仅列出实际引用与待核对范围。新线索以 `planned` 保存，新关系以 `arrangement_plan` 保存并限定章／卷范围，不顶替现有当前关系事实。

> 白话比喻：改行程表可以挪动景点，但不会改掉已经拍摄的照片。对应到系统，计划和资料可采纳，正文及历史快照保留。速记：先看原件、预览差异、限定应用、另行核对正文。

`TimelineHookPlanService` 为原章规划和写作上下文提供独立的 `plannedHookGuidance`：只包含本章设置或本章预计回收的 `planned` 线索，明确标识尚未实现。它不进入 `listOpenHooks`、事实账本或人物知情，也不增加模型调用；无匹配计划时字段和提示片段均省略，保留旧提示词内容。已停用／已回收线索不走此计划通道。
